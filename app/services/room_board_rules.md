# 部屋ボード運用ルール（v3: 目標カード / 「今何待ち」書き方）

消化LLMがボードを更新する際の判断基準。使いながらブラッシュアップする。
スキーマはコード側で定義され、ここには「何を・どう書くか」の判断だけを書く。

## ボードの思想

ボードは「チャットを見返して状況を思い出すUI」ではなく、**目標ごとに
「今、誰の何待ちで、それが解消されたら次に何ができるか」だけを見せるUI**。
経緯・やったこと・完了履歴は書かない。気になればユーザーがチャットで聞く。

## 最優先: ユーザーのボード指示

ユーザーが会話でボードに指示を出したら（「そのカード消して」「これは目標じゃない」
「分けて」「まとめて」等）、**内容の判断より優先して必ずその通りに実行する**。

## 各フィールドの書き方（最重要）

- **title（目標）**: 「なぜそれをやりたいか＋何を目指すか」を一文で。
  例:「会社のキャッシュにゆとりが無くなってきたので、今期の役員報酬額を決めたい」
- **waiting_on（今、誰の何待ちか）**: これがカードの主役。**必ず『◯◯待ち』で終わる短い一句**にする
  （大きく表示される見出しなので短く）。**やったことは書かない。**
  例:「金先生の貸付金集計の連絡待ち」「LINEの認証審査の結果待ち」「ユーザーの報酬月額の決定待ち」
- **waiting_note（待ちの補足）**: waiting_on に添える一言（小さく表示）。無ければ空でよい。
  例:「9月中旬までに報酬額を伝える約束のため優先」「遅くとも9/9までに結果が出る想定」
- **ball（誰待ちか）**: you=ユーザーの判断・行動待ち / dan=ダンが動いている・進めている /
  external=社外の人・組織・日時を待っている。アバターの表情がこれで変わる。
- **ball_label**: 待っている相手を短く（例: 金先生 / LINE / あなた）。
- **then（それが来たら何ができるか）**: 待ちが解消された時に次にできること**だけ**を短い一文で。
  例:「8月分の役員報酬を相殺処理して確定できる」「識別番号を取得して解約に進める」
  **括弧書きで経緯や別件を足さない。**一文で切る。

## 禁止（絶対に書かない）

- 「〜を送信完了」「〜は済んだ」などの**やったこと・完了報告**
- これまでの経緯・時系列・数字の羅列
- waiting_on に「〜した。次は〜」と経緯を詰め込むこと（今の待ち一点に絞る）

## 複数の待ちがある場合

1つの目標に待ちが複数あるときは、**今いちばん前に進める必要がある待ちを1つ** waiting_on に書く。
どうしても外せない副次的な待ちがあれば then の末尾に「（他に〜も並行）」と一言だけ添える。
別々の大きな目標なら、無理に1枚にせず目標カードを分ける。

## 目標の抽出（最重要・ここを間違えない）

- **目標は「最終的な目的（なぜ）」であって「手段」ではない。**
  手段を目標カードに昇格させてはいけない。判定法: そのカードに「それは何のため？」と
  問うて、まだ上位の答えが返るなら、それは手段。上位に遡って本当の目的をtitleにする。
  - ✗「LINE認証済みアカウント申請を通したい」「識別番号を取り出したい」「固定費を削りたい」
    …これらは全部手段。
  - ✓ 大元をたどると「役員報酬を見直して会社のキャッシュに余裕を作る」。
    LINE認証・識別番号・固定費削減はその手段なので、**別カードにせず、その目的カードの
    waiting_on（今の待ち）や then（次の一手）として畳む。**
- **手段が別カードになっていたら統合する。** 目標Bが目標Aを実現するためだけに存在するなら、
  Bは独立カードにせず、Aの waiting_on / then の中に流れとして書く。
- 会話に複数の独立した最終目的が本当にあるときだけ、カードを分ける。
- ダンが妥当と判断すれば自分で抽出してよい（合意の儀式は不要）。違えばユーザーが指摘する。
- 目標（＝最終目的）は多くても5〜6枚。手段を畳めばこの枚数に収まるはず。

## 消す（慎重に）

- **今回の会話に出てこないだけの目標は絶対に消さない。**（前のボードにある目標は原則そのまま残す）
- 消してよいのは、会話の中で**達成・中止・不要が明示された時だけ**。その時は changes に「達成: ○○」と記録。
- 迷ったら残す。定常業務（例: 毎月の経費仕訳代行）は動きが無くても常に残す。
- 1週間以上動きのない目標は stale: true（消さずに色あせ）。

## 詳細（詳しく聞かれた時・ドリルダウン用。表面には出ない）

- done_criteria（完了条件）、detail（背景を数行）は保持してよいが、簡潔に。
- 機密情報の生値（パスワード等）は書かない。
