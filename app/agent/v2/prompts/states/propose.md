# PROPOSE状態

## 目的
ユーザーに提案し、承認を得る。これが唯一の承認ポイント。

## やること
1. 候補からおすすめを1つ選ぶ
2. 選んだ理由を説明
3. 予約詳細を明確に提示
4. 承認を求める

## 重要：承認後の遷移
- 承認されたら → 直接 [STATE: EXECUTE] へ（CONFIRMを経由しない）
- 質問がある場合 → 回答してPROPOSEに留まる
- 変更要望がある場合 → [STATE: PLAN] で再検索

## 出力例

```
[STATE: PROPOSE]
[STEP] 19:00発ののぞみ45号がおすすめです
[STEP] 希望時間に最も近く、所要時間も短い

予約内容:
- 列車: のぞみ45号
- 日時: 2026年1月30日 19:00発 → 21:30着
- 区間: 東京 → 新大阪
- 座席: 普通車指定席
- 人数: 1名
- 価格: ¥15,820

代替案:
- のぞみ47号 19:15発（15分後の便）
- のぞみ49号 19:30発（少し遅め）

この内容で予約を確定しますか？
```

### 承認された場合
```
[STATE: EXECUTE]
[STEP] 承認されました。予約を実行します

予約処理を開始します...
```

## ルール
- 価格、時間、所要時間は正確に
- 推測で値を作らない
- おすすめ理由を明確に
- 承認=即実行（二度聞きしない）

## 禁止事項
以下の表現は絶対に使用しない:
- ❌「確定する前にもう一度確認させていただきます」
- ❌「後で改めて確認します」
- ❌「実行前に再度お伺いします」

理由: この提案が唯一の確認ポイント。ユーザーが「はい」「うん」「OK」「この内容で確定して」等の承認を返したら、追加確認なしで即座に実行する。

## 承認判定
| ユーザー返答 | 判定 |
|------------|------|
| はい、うん、OK、お願い、確定して、進めて | → 承認。即 `[STATE: EXECUTE]` |
| やめる、キャンセル | → 拒否。`[STATE: REPORT]` |
| 〇〇にして、変更して | → 修正要望。`[STATE: PLAN]` |
