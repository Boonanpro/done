# LIVE 会話の受け渡し・取消・小規模編集の改善

## 確認した故障と変更

- 9月11日の縮小依頼は逐次文字起こしに全文があるのに、GPT6入力では「左上を起」で途切れていた。画面履歴を含む16,000文字超のイベントを黙って破棄していたため、会話イベントは破棄しない仕様に変更。さらに、実行入力にクライアントの会話本文を直接載せ、診断ログの送信完了を前提にしない。
- 各時刻の画面情報が直近のマウス軌跡全体を繰り返し含んでいたため、各時刻の位置を残して重複する軌跡配列を除去。
- 過去の欠けた会話は、同一セッション・話者・開始時刻の逐次ログが既存本文の厳密な続きである場合だけ復元。ユーザーの「左上を固定し、黒背景込みで80％」を実際の旧ログで復元確認。
- 実行中の会話担当CLIへ原文と画面情報を `turn/steer` で届ける。道具のロック待ちをせず、受け渡した原文は別ファイルにも保存して制作委譲へ引き継ぐ。
- 新たな委譲は古い会話側の応答を中断し、最新の全文で再判断する。制作ジョブ自体を発話ごとに取り消す仕組みではない。旧応答の終了・失敗を新依頼へ重ねない。
- 12ツール呼び出しを12回の思考と誤って数えていた打ち切りを撤去。
- `transform_visuals` で静止配置の字幕・背景・位置指定付き画像等を共通起点で拡大縮小。一つの変更として検証・保存・Undo可能。既存の保護・編集範囲・競合検出を通す。動きのあるキーはこの道具で勝手に消さず、既存の編集操作を使う。
- タイムライン情報に抜粋の範囲と全クリップ数を明示。実際のモデルテストで最初の3クリップだけ変更する失敗を再現した後、全36クリップを取得して編集するまで確認。
- UIにCLI起動・情報取得などの実行イベント、制作担当の直近の報告を表示。「進行中の制作なし」をLIVEに明示し、空の作業一覧に「停止していません」という説明を付けない。

## 実測

実作品を変更しない隔離したテスト作品。36個の背景・字幕、12の表示区間。

| 条件 | 保存まで | 最終応答まで | 使用した操作 |
| --- | ---: | ---: | --- |
| 対象を事前選択 | 6.52秒 | 10.84秒 | transform_visuals |
| 未選択、自然文で全区間指定 | 15.88秒 | 21.19秒 | timeline_state、read_skill、transform_visuals |
| 稼働アプリのHTTP経由・未選択 | 12.45秒 | 15.92秒 | timeline_state、transform_visuals |

最後のHTTP試験は41,000文字の画面情報と会話本文を同時送信し、全文が保持されることも確認。LIVE APIの音声会話を含む時間ではない。前回の実作品での3分13秒との厳密な同条件比較ではない。

実CLIの処理中に取消原文を追加して「取り消しました」と応答することを確認。ただし追加前に出始めた旧依頼への着手発言までは取り消せない。

Python 48件、Node 8件、実HTML/CSS/JSのPlaywright検証が成功。新しい委譲で旧応答を中断し、次の依頼を開始する試験、道具のロック中でも訂正を渡す試験を含む。

## 限界と次の実地確認

LIVEが制作側の状態と一致した自然な報告をするか、音声からの取消と追加が実地でどう働くかは次の音声会話で照合する。今回の改善ですべての生成・調査が数秒になるわけではない。前回の長い制作担当の初動約2分については、初期化と推論の内訳がまだ分離できていない。
