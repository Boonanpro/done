# 部品を独自作品へ使う検証

## 目標と対象

ユーザーが全70部品を採点する前に、元の実装を使った独自作品と、比較・部分修正が成立するかを検証する。
検証用の題材は「Dan：頭の中の映像を会話で形にする10秒の紹介」。ユーザーが発注した本編ではない。

- 同じ目的に、構成・見た目の違う3案。色替えだけにしない。
- 既存候補表示5秒以内、制作済み見本の表示2秒以内。
- 軽い部分修正は判断から表示15秒以内を目標。
- 指定していない部分を維持し、再生位置を戻しても同じ絵を描く。
- 音声の自然さや長編制作全体の合格とは区別する。

## 制作と品質

Aはフローチャートの線・ノードを会話から映像への変化へ転用。
Bは傾いた画面とガラスのカードを、朝の部屋が会話に応じて動く演出へ改変。部屋とカーテンは新規SVG。
Cは字幕の文字サイズの対比と太さの変化を「書けない」という気持ちが軽くなる演出へ転用。
参考MP4や画面録画を作品へ流用していない。取得したHTMLソースをAstraに渡し、改変したHTML/CSS/SVG/GSAPで描画した。
元実装の全機能をそのまま保存したわけではなく、Bのガラスは元の外部WebGL依存を使わずCSSで実装している。
出典・読んだ元ソースのハッシュは各 `*-provenance.json` に保存。

初案Bは円と文字でAと近く、比較の幅が弱かったため不合格にして作り直した。
最終3案は図解・立体的な画面・文字中心という違いが見て分かる。
私の評価では比較・相談に使える短い作品になったが、実写や高品質3Dの表現力、普遍的な商用品質まで証明したものではない。
部品を増やしても、モデルが簡単な表現に寄せれば品質の幅は増えないことが今回も分かった。

## 実装した改善

`scene.html` に単一GSAPタイムラインを持つHTMLを渡すと、Danのビジュアル履歴内で直接再生できる。
従来のThree.js用コードへの書き直しや動画書き出しを挟まない。
GSAPをローカルに固定して配信。iframeは不透明な別オリジン、外部スクリプト等は読み込まず、親画面・認証情報へアクセスできない。
同期登録・document.fonts.ready後の登録を確認した。他の外部ライブラリや画像を必要とする全70部品の無変更実行を保証する機能ではない。
作品側の調整値は `window.danParams` で読み、既存 `revise_presentation` から値だけを変更できる。
制作指示も「まず簡単な演出6種を使う」ように読める順序を改め、参考元の実装や自由な表現をそのまま使えることを明記した。

## 測定

本番port8000、隔離したテスト部屋、実Edgeで確認。ユーザーの部屋やタイムラインは変更していない。

| 測定 | 結果 |
|---|---:|
| 3案の構成を考える | 37.921秒 |
| AのHTML生成 | 65.274秒 |
| 初案BのHTML生成 | 76.388秒 |
| CのHTML生成 | 63.325秒 |
| Bの方針修正 | 18.774秒 |
| 改訂BのHTML生成 | 141.645秒 |
| 制作済みA/B/CのAPI保存から表示 | 0.232 / 0.570 / 0.143秒 |
| Jevが説明と要望から適した案を順位付け | 0.997 / 0.554 / 0.531秒、3/3一致 |
| Astraの比較についての返答 | 9.999秒 |
| Astraが一文だけの変更を解釈 | 4.788秒 |
| その変更を本番API経由で表示 | 0.178秒 |

判断と描画の計測は別の呼び出しであり、音声を含む実通話の一続きのレイテンシではない。
Jevの選択は人間が画面確認した後の説明を使う。Jevが直接映像を視覚検品したという意味ではない。
利用モデルは既存のJev APIとGPT-6 Astraの定額CLI Fast。動画生成APIは使っていない。
初回のコード生成はまだ遅い。候補表示だけの速度と混同しない。

## 修正・会話テスト

「図解より作れないかもという気持ちが軽くなる感じ。文字が大きく出るやつ」という発言でCを選択。
続けて最後の一文を変える指示を出し、Astraが返した `/scene/params/closing` の変更を本番APIで実行。
ソース本体は同一、途中6.8秒の画面は同一ピクセル、エディター内の計算済みスタイルも一致した。
迷っている発言に対する追加の小テストでは、AとBの具体的な見た目を比較する質問が出て、勝手な採用はしなかった。
この追加テストには比較を促す指示を与えているため、本番の会話で毎回適切に質問を選べることの証明ではない。
LIVE1のマイク入力や実音声のテストは今回実施していない。

全案でJSエラーなし。各6時点を目視。シークを往復して描画を比較した。
Bの勾配描画で、1回の測定にRGBの1/255の差が2画素出た。DOMと動きは同じで、ブラウザの描画丸めに限定された。
検査は最大1/255かつ平均0.001未満の差のみ許容。再測定では全案で同一ピクセル。
MP4は同じHTMLを30fpsでフレーム描画してエンコード。ffmpegで別の動画を組み立てていない。
Python回帰64件、JavaScript回帰20件通過。元のcode形式の見本も維持。
