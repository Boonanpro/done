# 参考知識庫とJevの比較実験（2026-09-17）

## 目的と実装範囲

毎回のWeb検索を、実物と確認済み情報を持つ参考知識庫で置き換える効果と、候補評価をJevに任せる効果を分けて測る。

`scripts/benchmark_reference_library.py` に再実行可能な隔離実験を追加。既存エディターへの新しい検索経路の組み込み、既存タイムラインの変更、サーバー再起動は行わない。Jevのユーザー提供キーは既存credential serviceの `typesafe_jev` に暗号化保存し、読み戻しと実API接続を確認。キーは実験ファイル・結果には含めない。

## 方法

- 実際の会話で提示済みの公開イラスト12件を収集し、11件取得成功。1件は取得失敗として保持。
- 画像を目視して、画風、構図、表情、文字、媒体を記述。タイトルだけで未確認の特徴を付けない。以前「心配する表情」とされた笑顔の画像も、実物に従って記述。
- 同じ11件、同じ依頼、同じ質問、同じ候補選択ロジックでAstra CLIとJev APIを比較。
- 4条件を2回ずつ。別画風の比較、深刻な場面、同画風の別人物、知識庫にない実写動画。
- 期待候補はモデル入力に含めない。ただし採点基準は今回作ったもので、ユーザーの満足率や独立した盲検評価ではない。
- 0〜3の適合度で2以上を候補にする。「別画風」条件では同じ画風の重複を除外。これは実験側の既定条件であり、Jevが比較軸を自動発見した証拠ではない。
- 追加検証では、会話内の呼び名と候補の対応を入力に追加し、最初の記録を上書きせず別に保存。
- 現行 `search_web` も4条件で実測。ただし測定終点は検索結果の取得まで。実物取得・視聴・選別まで揃えた完全な三者比較ではない。

## 現時点で判断できること

整理済み情報を参照する方式は、会話中の外部取得・再調査を省ける。Jevは限定した条件判断を速く返す。一方、曖昧な画風の近さではスコアが閾値に達せず候補を出さなかった。同じ入力のAstraは候補を選べた。単純に閾値を下げて合格にする調整は行っていない。

このため、Jevですべての選択を確定する方式より、関連候補の評価・並べ替えに利用し、不確かな比較はAstraへ渡す構成が次の検証候補。ただし、その混合構成の速度と品質は今回未測定。

## 限界

- 小さな既知の画像集。動画、字幕、カメラワーク、未知ジャンルへの一般化は未検証。
- オフラインで人手によるラベル付けを実施。自動ラベルの品質、蓄積費用、更新費用を測っていない。
- モデルは同じ文字情報を見る。Jevの画像理解性能を試したものではない。
- 参考が選べることは、独創的な演出や高品質な完成動画を作れることの証明ではない。
- 既存候補を選ぶ検証であり、好みの変化を伴う連続会話や「どちらでもない」からの探索は未検証。
- 推論時間と、ブラウザーで実物が見えるまでの時間は別。ローカルレポートの画像読み込み確認は、音声エディター内の速度保証ではない。
- 現行Astraは契約CLIのFast/medium設定を利用。APIへの置き換えなし。

## 次の実装判断

まず出典・実物・確認済み記述を一体で保存する小規模な知識庫を編集UIの提示経路へ接続する。知識庫に適切な候補がない場合は外部検索へ進む。Jevの確信をユーザーの好みの確率と呼ばず、弱い根拠で候補を確定しない。広い公開サイトの建設や全SNSの取り込みを先行させない。
