## 設計上の結論（提案、未実装）

1. **8項目のヒアリングは残す。** 目的と条件を忘れないための合意メモとして適切。入力欄を埋めること自体を目的にしない。既知の情報を質問せず、相談済み未定を許容する現方針も残す。
2. **シートと演出設計を分ける。** シートに長文の台本を詰め込まない。シートと選んだ参考から、伝える内容、場面順、演技、カメラ、音、見た目の基準を作る。参考IDだけでなく、採用する特徴・変える特徴を制作担当に渡す。
3. **全編を通して見て直す体験は残す。** ただし全カットを同じ手法で作らない。必要ならその前に完成見た目の静止画や短い動きの試作を見せる。これは現行の「最初は必ず全編Vコンテ」からの変更提案で、まだ適用しない。
4. **3Dは任意の編集手段として残す。** 複数人の配置、移動、回り込むカメラ、同じ場所の別角度、物体との接触などで使う。インタビュー編集、文字中心の説明、平面モーション等で必須にしない。見た目の作り込みより、構図・動作を明確に伝える幾何とリグを優先。顔の微細な演技まで粗いモデルで決められるとは言わない。
5. **Jevライブラリは拡張する価値がある。** まず既存動画の観察とジャンル横断の不足を埋める。見た目の参考と制作手順は別の種類の情報として管理し、相互リンクする。既存作品だけでなく、その手法を別内容へ応用した実証例も残す。
6. **検索は候補を先に少数へ絞ってJevで判断する形へ。** 幅広い目的・映像形式・視覚特徴による複数経路の索引と、必要なら意味検索を併用。単一ジャンルで切り捨てず、異分野からの有用な候補を残す。Jevの全件分割方式をそのまま巨大化しない。GPU増設がこの83組問題の直接の解決ではない。
7. **演出と生成結果の選別は残る仕事。** Jevの参考選択だけで、物語設計・表情・間・編集品質が自動的に解決するとは証明されていない。GPTが毎回Webを探索する必要は減らせるが、独自作品の設計・判断まで不要になるという結論にはならない。
