# Dan UI改善：初回実装と検証

2026-09-23。設計方針は [調査結果](dan-ui-improvement-research-20260923.md)。全面リデザインの完了ではなく、主要操作の入口・到達性・パネル重なりを改善した最初の実装。

## 変更

### PCブラウザ / Webモバイル

`frontend/src/components/layout/main-layout.tsx`

- プレビュー中のメニューを左端ホバーだけに依存させず、常に見える48pxのボタンから開く。
- Radix Dialogでメニューの名前、フォーカス管理、Escape、閉じた後のボタンへの復帰を実装。閉じる操作にも文字を付けた。
- プロジェクト変更とリンク移動でメニューを閉じる。会話を直接開いたモバイル画面では初回メニューが会話を隠さない。
- サイドバー幅を左右キー、Shift＋左右、Home/End、マウス／Pointerで変更可能にした。ダブルクリックで標準幅に戻す。
- 狭いPC画面では本文領域を確保する上限に制限。Pointerの終了・キャンセルでドラッグ状態を解除し、グローバルなbodyスタイルは変更しない。

### Android APK

`mobile/App.tsx`

- アプリバーと添付操作の領域を48単位へ拡大。入力欄の最小幅とボタン間隔を調整。
- 戻る、検索、添付、制作物追加、送信、作業停止に操作名・ボタン役割を付けた。
- 送信不可の状態をアクセシビリティにも通知し、添付を外す操作には対象名を付けた。
- 会話送受信、音声、認証、ネイティブモジュールの処理は今回の変更対象外。

### 制作エディターの相談画面

`app/static/editor-assistant.html` / `editor-assistant.js`

- 会話ツールバーに「素材」「文字で伝える」「話す／ミュート／再開」「終了」の可視ラベルを追加。
- マイク表示は音声処理が持つ既存ラベルへ追従し、接続状態を二重管理しない。
- 文字入力パネルをEscapeで閉じ、起点へフォーカスを返す。閉じて開き直しても未送信の下書きを保持。
- 実画面で、相談メモが文字入力と閉じるボタンに重なる問題を確認。パネルを切り替えて両方を同じ場所に重ねないようにした。相談メモがDOMContentLoaded後に追加されるケースも検証。
- 320 / 390 / 700px幅で会話ツールバーが画面内に収まり、各ボタンが48px以上で重ならないことを確認。
- Rust製タイムライン自体の変更はまだ行っていない。

## 検証環境で解消した問題

最初の独立Next出力フォルダーがTailwindの自動探索へ入って生成CSSを壊したため、この作業の開発プロセスだけを確認して停止し、出力を退避、生成物を探索対象外にして再起動した。本番プロセスは停止していない。

メニューのEscape検証では、先に表示された既存ツールチップを閉じる段階を区別した。エディターの重なりはテスト手順で回避せず、実装を修正して再確認した。
