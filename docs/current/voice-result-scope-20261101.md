# 音声の完了結果と追加条件を分離する

## 失敗と原因
前回voice-grammatical-endingでは、短縮だけが完了した結果を追加の「参加費は無料にして」へ混ぜて完了と誤報告した。job_feedは依頼を80文字で切り、ファイルの住所で目的が切れる場合があった。結果到着と新しい発話が競合していた。

この枝はorigin/main cb971002から作り、未採用の語尾判定8e87ec65を含めない。

## 実装
- resultイベントに、その結果が生成された時点で担当が受け取っていたrevisionと追加指示を固定保存。受取は完了の証明とは呼ばない。古いイベントへ現在のjob状態を後付けしない。
- 音声に、元の依頼・そのイベントの追加指示・結果本文を区別した記録を渡す。完了の事実は結果本文だけ。元の依頼は4000文字まで、結果本文は保存イベントそのまま（従来1500文字で再切詰め）。
- 自発的な完了報告のみ、到着後1.5秒は入力認識の後着を待ち、発話が静かになり、その発話の判断が済んでから届ける。結果は未読のまま保持して、次の周期で一度届ける。失敗・本人への確認・終了時の会話への保存は待たせない。

文字起こしより前の生のマイク活動はサーバーから見えていない。1.5秒は入力後着の緩衝で、あらゆる話し始めを検出する保証ではない。発話を許可に使う処理と停止の許可条件は変更していない。
