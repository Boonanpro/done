# Work continuity

Work survives individual turns in `~/.dan/work.sqlite`. Events from one-shot watches (including the existing official LINE webhook delivery), matched inbound messages, and collab batches enter the same ledger. No new message polling or channel-specific action planner was added. Room context carries outstanding commitments in ordinary conversations, including personal tasks. The agent can register commitments through `scripts/work_checkpoint.py`, using JSON on stdin.

The ledger records purpose, authorization basis, completion criteria, the last verified result, remaining work, and status. A returned chat answer is not completion: a checkpoint is required. `done` requires evidence, `waiting` requires a resumption condition, and optional `wake_at` schedules an existing obligation. A new relevant message exposes waiting obligations in room context; the agent reconciles them rather than blindly resuming all work. `ready` continues via the existing follow-up scheduler. The scheduler only checks persisted pending work; it does not poll outside chats.

SQLite transactions claim one job per room across processes. Process-local sessions and DB-backed active runs both prevent starting over a live conversation. A lease survives a checkpoint until its turn exits. After a dead process, reconcile actual effects before proceeding. Cancellation wins over late checkpoints. Failures are blocked rather than replayed; three turns without a progress checkpoint also block. An actual progress checkpoint resets that counter. Blocked work produces one idempotent room notice. No sending or purchasing authority is added by the ledger; current approval tools and the owner's prior authorization still apply.

The agent still judges what to do, whether evidence is sufficient, and how to incorporate feedback. Evidence text is not an independent quality assessment. Tests exercise transitions and adapters with a deterministic agent double; they do not establish that real client work meets the owner's quality standard. A client reply that does not arrive through a connected channel remains undetected. Personal LINE notifications, migration of clients to Dan chat, and reorganization of the customer UI are outside this change.
