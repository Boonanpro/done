# チャットの時系列・送信・キャンセルの定義（2026-10-02）

本人の要望: どんな送り方・キャンセルをしても、起きたこと・割り込んだメッセージ・考え中が妥当な順番で並ぶ。
実行中の表示は1行の「Working」ではなく、入力中アニメーション（3つの点）にする。

## 1. 並び順はひとつの決まりだけ

**部屋の中のものは、サーバーがそれを受け取った／それが起きた時刻の順に並ぶ。** 端末の時計は並び順にも判断にも使わない。

| もの | 並ぶ時刻 |
|---|---|
| 本人のメッセージ | サーバーが受け取った時刻 |
| ダンの作業の一歩（考えた・道具を使った） | その一歩が起きた時刻 |
| ダンの返事 | 返事を書き終えた時刻（書き始めではない） |
| 追い連絡で割り込まれたターンの作業の記録（返事があればそれも） | 追い連絡の直前（元のメッセージの下、追い連絡の上） |
| 通話の記録・作業の報告・受け口の知らせ | それが書かれた時刻 |
| 「停止しました」 | キャンセルを受け付けた時刻 |

同じ時刻なら、保存された順。

- ダンの返事を「書き始めの時刻」で置いていたため、途中で送った本人のメッセージより上に返事が来ることがあった。返事は書き終えた時刻に置く。
  本人が見ていた流れ（送った → その後にダンが答えた）と同じになる。
- 追い連絡で割り込まれたターン（2026-10-13）: 作業の一歩は追い連絡の前に起きているのに、書き終えた時刻で置くと
  追い連絡の下に落ち、本人が2通続けて送ったように見えた。割り込まれたターンの記録は追い連絡の直前に置く。
  追い連絡の後の作業と返事は、追い連絡の下に（新しいターンとして）並ぶ。

## 2. 「考え中・作業中」は出来事ではなく状態

- 3つの点のアニメーションは、ダンがこの部屋のチャットとして動いている間だけ、**いつも一番下**に出す。並び順の中には入れない。
  送った直後の、まだサーバーの時刻が付いていないメッセージよりも下（2026-10-13: 送った瞬間だけ上に出ていたのを直した）。
- 送った直後に始まった作業の一歩も同じ。サーバーの時刻が付くまでの約1秒、一歩はサーバーの時刻を持ちメッセージは持たないので、
  何もしないと一歩が上に出る。画面は「送る前に見えていた一歩のいちばん新しい時刻」を覚えておき、それより新しい一歩は
  メッセージの下に置く（時刻が付けば §1 の決まりで同じ順になる）。追い連絡で割り込まれたターンの一歩は、送る前から
  見えているので上に残る。
- 裏で動く作業（通話や司令塔から頼んだ作業担当）はチャット自身のターンではないので、3つの点も出さず、送信も妨げない。
- 部屋一覧でも、チャットとして動いている部屋は1行の「Working」ではなく3つの点。

## 3. 送信はいつでもすぐ

- 送ったメッセージは押した瞬間に一番下に出て、サーバーが受け取った時刻が分かったらその位置に収まる（ほぼ同じ場所）。
- ダンが作業中でも、送信は待たせない。メッセージは普通のメッセージとして並ぶ（半透明の「仮送信」は使わない）。
- ダンがそれを読むのは作業の次の区切り（道具の結果が戻った時）。読んだ後のダンの動きは、そのメッセージより下に並ぶ。

## 4. キャンセル

- キャンセルは「この部屋でダンが今していることを止める」。
- **ダンがまだ読んでいない本人のメッセージは、取り消して入力欄に戻す**（複数あれば順につなげて戻す）。読んだかどうかは
  サーバーが自分の記録で決める: そのメッセージより後にダンの作業の一歩や返事が1つでもあれば「読んだ」。
- 読んだ後なら、メッセージもそこまでの作業も残し、作業を止めて「停止しました」をその時刻に置く。
- 画面は、サーバーの答え（取り消したメッセージ）に従って消す・戻す。端末だけの推測では消さない。
- 何も動いていない時のキャンセルは、何もしない（次の送信を壊さない）。

## 5. 画面が2つ以上あっても同じ

スマホとWebで同じ決まり。どちらも、並び順・取り消し・状態はサーバーの記録から作る。

## 6. 部屋のモデルが違っても同じ（2026-10-14）

部屋は Claude でも GPT でも動く。§1〜§5 はどちらの部屋でも同じに成り立つ。

違うのは1点だけ。作業中に届いたメッセージを、ダンがどうやって読むか。

| 部屋のモデル | 作業中に届いたメッセージ |
|---|---|
| Claude | 作業を続けたまま、次の区切りで読む（§3） |
| GPT | 作業の途中では受け取れないので、作業を止めて、そのメッセージで始め直す |

どちらでも、本人から見えるものは同じ: メッセージは必ずダンに読まれる。それまでの作業の記録は、そのメッセージの直前に残る（§1）。

- 決まりを書く場所は `app/agent/turn_flow.py` の1か所。「待たせるか・止めて始め直すか」と「作業の記録に付ける時刻」をここで決め、
  どのモデルの経路もここを呼ぶ。モデルごとの違いは同じファイルの表 `ENGINES` だけに書く。
- `tests/test_turn_flow_engines.py` は、決まりの1つずつを `ENGINES` にある全部のモデルの経路で確かめる。経路を足したら表に足す。
  表に足すと、テストがその経路でも走る。
- 実際の部屋で確かめる時は `python scripts/verify_chat_engines.py`（テスト用の部屋で、モデルごとに1通目と追い連絡を送り、
  読まれたか・記録の並びを見る）。
- 経緯: 決まりが Claude の経路の中にだけ書かれていた。GPT の部屋では、追い連絡で止められたターンの記録が保存した時刻
  （追い連絡の0.7秒後）に置かれ、本人が2通続けて送ったように見えた。送ってから2分以内の追い連絡は、誰も読まない置き場に入り、
  ダンに届かなかった。
