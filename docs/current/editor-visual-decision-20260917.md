# 会話から参考を選び、実物で絞る経路（2026-09-17）

## 今回の合格条件

- 用意済みの参考について、発言終了から表示まで中央値1秒以内、p90 2秒以内。
- 字幕だけでなく、モーションと人物映像でも、曖昧な希望から約3回の比較で狙った方向へ近づける。
- 感想・仮定・表示方法への批評を制作許可に変えない。
- 実際に表示できた候補を音声側へ渡し、同じ発言の途中更新で履歴を乱立させない。
- 本番と同じHTTP・WebRTC経路で検証する。テキスト注入テストだけで音声体験の合格としない。

## 構成

`LIVE1の原文 → Jevの行動・表示先・候補選択 → 参考表示専用API → 描画確認 → LIVE1へ事実を通知`

用意済み候補の比較にはAstraを起動しない。制作、編集、ライブラリ外の調査は従来のAstra CLIへ渡す。JevはWeb全体を検索する機能ではなく、渡した候補と会話を比較する役割。

以前の約100候補への個別採点を、候補群からの一括選択に変更。今回の温まった接続ではJev部分が約0.24〜0.36秒。接続プールを再利用する。発話の文字起こし中に参考候補を準備し、音声の小休止で表示する。これは比較表示のみで、部分発話から制作を始めない。

同じ発言に対する候補の更新は同じ表示グループを差し替える。新しい発言には新しいグループを残す。世代番号で遅れた履歴取得による巻き戻りを防ぐ。参考動画は画面内で無音再生し、手動停止を尊重する。拡大表示中も再生・停止できる。

参考表示は編集用の `/begin` を通さない。ここでタイムラインのスナップショットや制作コンテキストを組み立てていたため、本番では余分な待ちと、文字起こしの追加による完了通知の欠落があった。参考の保存先と表示機能は共通のまま、処理経路だけを独立させた。

画面は途中の参考も出せるが、音声案内は入力音声と文字起こしの時刻を照合してから、その時点の最新の比較を一度案内する。表示情報は大きなJSONを途中で切るのではなく、比較全体・各候補・提示完了の完結した情報として渡す。継続して適切な既存見本は再生成せず、表示済みの実物と実際の描画時刻を参照する。

表示先もJevが判断する。見た目の比較は比較欄、単体の確認は拡大表示、尺・カット順・通し作品はタイムライン。今回の速度目標は既存参考の比較表示についてであり、タイムライン上の新規作品制作時間ではない。

## ライブラリ

現在102件（参考32件＋コンポーネント70件）。今回、Blender公開作品の実写・3Dから8抜粋、Pexelsの住宅・車内作業・都市から3抜粋を追加。出典・権利情報を保存し、フレームとブラウザ再生を確認した。実在の大阪やCybercabであるとは扱わない。

これはあらゆる動画を網羅する量ではない。候補数だけでなく、実物に対応した説明、望む比較に有用かという選び方、即時再生できるローカル素材が必要。Jevの確率値は「ユーザーが満足する確率」とはみなさない。

## 検証記録

- `scratch/visual-acceptance-final/`: 旧採点方式の本番経路。狙った候補は選べたが速度目標未達。失敗証拠として保持。
- `scratch/visual-choice-audio-caption/`, `visual-choice-audio-motion/`, `visual-choice-audio-film/`: 一括選択方式の実音声・実描画。3種類9提示、最後の更新まで中央値955ms、p90 1488ms。各3段階で予定した方向へ到達、制作側起動0、ブラウザエラー0。
- `scratch/visual-acceptance-choice/`, `visual-acceptance-direct/`, `visual-acceptance-settled/`: 本番経路の途中検証。表示通知欠落、暫定案の説明、逆に案内しなくなるケースを検出した。最終合格の証拠には使わない。
- `scratch/visual-acceptance-confirmed/`: 最終の本番経路検証。字幕・動き・人物映像・暮らしの実写、4ケース各3比較。12比較すべてに音声案内があり、4ケースとも意図した候補へ到達。制作側起動0、ブラウザエラー0。`summary.json`、`review.html`、各ケースの `conversation.mp4` を参照。
- `scratch/visual-decision/holdouts.json`: 話題変更、世界地図、グラフ、カメラ転換、車内実写、批評、沈黙、仮定、制作依頼の追加検証。
- `scratch/visual-decision/presentation-ui.json`: 幅統一、自動再生、停止、拡大、途中更新、旧世代無視。

音声入力は自然なTTSを用いた固定テスト。期待する候補IDは評価側だけに保持しDanに渡していない。ただし反復開発に使った会話なので、未知のユーザー全般への成功率とは扱わない。数値は録音終了時刻から計測し、発言中に表示済みなら待ち時間0。最初の表示と最後の更新の両方を記録する。何も表示されない失敗を速度集計から除いて合格とすることはしない。

最終12比較の表示待ちは中央値0ms、p90 1559ms。0msは発言中に表示済み、または既存候補の継続利用。最後の候補更新までは中央値720ms、p90 2057ms、最長2108ms。合格条件の「表示まで」と「文末まで解釈した最後の更新」は区別する。特に途中検証では音声APIから文末の文字が数秒遅れて届く場合があった。既存候補の再利用は、同じ候補の過去の実描画イベントに結び付け、発言開始時点に架空の描画時刻を置かない。

追加の判断テストは9ケース合格。AI側の提案がユーザーの好みを上書きしないことも含む。関連のPythonテスト62件、JavaScriptテスト29件が合格。同じ部屋の別タイムラインの提示を現在の提示として参照しないことも確認した。

## 今回だけでは証明しないもの

ユーザー本人の美的満足、膨大な候補数での速度、完全新規作品の高品質な演出、参考から独創的な完成動画への変換、全会話での自然さ。既存参考を出しただけなのに加工したように話す例も出たため、表示側は選択・作成数・変更数の実績を音声側へ返す。

最終録画にも説明の長さや相槌の多さは残る。暮らしのケースでは台本にない短い英語の認識も1件あり、原音との照合による原因特定はしていない。制作の誤発火は起きていないが、音声認識や自然さが完全に解決したとは評価しない。
