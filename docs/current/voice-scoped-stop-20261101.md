# 別室の作業への停止

10/31本人通話で停止要求が別室への伝言になり、7操作・8判断往復で約22秒だった件の続き。

`job_status(query=部屋名)`で観測したproject_id/run.idを`stop_run`へ渡す。停止は認証した実行プロセスへ一度だけ送る。部屋名による一括killはしない。実行ハンドルに保持したrunと照合し、遅れた停止・古い後片付けが新しい仕事へ作用しない。準備中・CLI再試行・常駐CLIの追い連絡にも同じrunの停止を適用する。停止記録は同時更新で失わない。

検証: tests/test_run_stop.pyの音声関数→内部HTTP経路、実子プロセスによる文章書込停止、同じ部屋の後続処理の継続。実子プロセス試験はモデル・本人の部屋・外部サービスを使わない。関連114件合格。既存の名前による状態読取・通話内の停止を保持。新しい関数は組立済みsession_configにも含まれる。

限界: 受付を実行終了と表現しない。親CLIの終了だけでは派生ツールや外部操作の終了は証明できないためstopped=falseを維持。チャット返信DB挿入をロックする別枝のRPC移行、広範なブラウザ後片付け変更は取り込まない。既存の古い実行プロセスには新しい停止エンドポイントがない場合があり、その場合は未受付を返し伝言や部屋単位停止へ迂回しない。

この試験は実音声からの停止選択・発声遅延の改善を証明しない。次は初期条件にない追加条件を含む実編集と、受信音声の発声開始を計測する。過去の20人保持の試験は初期条件にも20人保持を入れていたため、新条件反映の証拠には使わない。
