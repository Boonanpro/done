# Dan × Jev：実装・実測・残る合格条件

2026-09-17。ユーザーが合計3米ドルを承認。実Jev評価・隔離ブラウザ試験・Astra込み比較を実施。本番MCP公開とCore経由の実ブラウザ試験も実施。速度の表はそれぞれ測定範囲が異なる。

## 結論

高速化できる。ただし、Jevを全操作に挟むと逆に遅くなる。既知の操作はコードで一括実行し、画面の意味に応じた小さな選択だけJevへ渡し、計画・文章・難しい判断・目視検品をAstraに残す構成を実装した。各画面で条件を読み直す6段階の合成仕事では、最終版のAstra込みの完了試行中央値59.664秒→24.180秒（約2.47倍）を確認。通常側2/3完了、新経路3/3完了であり、失敗までの時間を完了時間の中央値へ混ぜていない。全サイト・全タスクへの保証ではない。

## Jevの特性と参考実装との差

JevはChoice・Score・Noulの構造化判断に特化する。自由文・コード・画像を扱う汎用の代替モデルではない。独立質問は1リクエストにまとめられるが、次画面の情報が必要な操作は直列になる。Choiceは最大255候補。confidenceは分布の集中度であり、正答率ではない。[公式Primitives](https://docs.typesafe.ai/primitives)、[Choice](https://docs.typesafe.ai/primitives/choice)、[confidence](https://docs.typesafe.ai/confidence)

公式の70〜500msや最大193.6倍という数字はDanの仕事全体の保証ではない。価格は公式掲載の入力100万tokenあたり$0.042、出力無料を試験予算の基準に使用した。[公式紹介](https://typesafe.ai/blog/introducing-system-one-models-and-jev)、[公式評価](https://evals.typesafe.ai)

参考にした[awlevin/typesafe-computer-use](https://github.com/awlevin/typesafe-computer-use/tree/7d120f1944d0156773d5089b81f8e46d108a6c8d)はmacOSのOCR/Accessibility候補からJevが行動種別・対象・サイトを選び、文章は別モデルが担当する。READMEの判断0.13〜0.38秒、OCR込み約1.5秒対5.5秒は参考値で、Danとの同一条件比較ではない。

DanではDOM参照を使うためOCRを毎回走らせない。候補の同一性と変更を確認し、値や結果条件をコードで照合する。Jevの「完了」という判断を成功証拠に使わない。参考実装より厳しい実行境界を用意したが、総合性能が同等以上という実証はまだない。

## 実装した経路

1. `browser.fill_form`：対象が既知なら従来の一括入力を優先。モデル呼び出しを増やさない。
2. `browser_plan`：AstraがURL・入力文字列・手順・各結果条件を指定。曖昧な欄の意味照合だけJevの1回にまとめる。候補が1つならJev不要。最大12段階。
3. `browser_flow`：Astraが小さな目標・許可候補・最終DOM条件を指定。Jevが現在の画面から次の通常クリックを選び、毎回コードで完了を確認。段階ごとの条件が特定箇所に出る場合は`instruction_selector`で照合範囲を指定し、無関係なページ本文をJevへ送らない。入力・認証・支払い・送信・削除・新規タブ等はAstraへ戻す。最大12段階。承認済み予算と公開設定が有効な時だけ公開。
4. `browser.open_target(ready=...)`：具体的な表示条件で準備完了を確認できる時だけ固定待ちを省く。ログイン済みとは推定しない。readyがなければ従来の遅延認証遷移待ちを維持。
5. DOMだけで値・文言を検証できる場面は明示的にDOM観測を選択。画像依存操作と目視検品には画像を維持する。最終観測の初期値は画像あり。
6. CLIの指示組み立てとMCP設定の準備をスレッドへ移して並列化。毎回の最新指示を保持し、古い指示のキャッシュは導入しない。

Jev接続は手順内で再利用。鍵は既存資格情報サービスから取得し、ユーザー別に短期間だけプロセスメモリに保持する。入力値・画像・鍵・APIエラー本文を計測ログへ記録しない。応答分布の型、候補集合、確率和、最大候補を検証する。confidence≥.9かつ選択肢確率≥.95は暫定運用閾値であり、品質保証ではない。

## ブラウザ以外の余地

| 部分 | 実装の現状・判断 | 何がどれだけ短くなるか |
|---|---|---|
| 指示/MCP準備 | 今回、非同期化・並列化 | 実際の読み込みでは所要時間約0.24秒のまま、他の処理を止める時間0.236→0.019秒。実ログcli_setup中央値0.997秒の全量が消えるわけではない |
| CLI起動・モデル接続 | 通常Codexチャットはターンごとのexec。音声・編集は既にapp-serverを使用 | 通常チャットの永続化余地はあるが、まだ分離実測なし。接続時間の数字を捏造しない。中断・指示更新・MCP権限・会話分離を含む別検証が必要 |
| 独立した取得・メディア処理 | 並列化・キャッシュ・文字起こし再利用が既にある | 新規効果0として扱う。未並列区間が見つかれば理論上「合計時間−最長時間」だけ短縮可能 |
| メール/通知のポーリング | メール180秒などの周期処理あり。command jobには既に即時起床経路あり | 到着が一様という仮定で180秒周期の平均検知待ちは90秒。イベント通知化はその待ちを減らす可能性。外部サービス接続・権限・運用条件が未確認なので未実装 |
| 文章・設計・難しい判断 | Astraを維持 | Jevへ置換して品質維持とする根拠なし。現段階の確実な短縮量は提示不可 |

現在のブラウザログはspanが重なり、仕事ごとのモデル/通信/検品を完全に分離できない。42件のresult到着中央値158.218秒を、すべてLLM待ちとみなして割り算するのは誤り。仮に全体の60%が対象でその部分が10倍になっても、全体は1/(0.4+0.6/10)=2.17倍。対象部分が20%なら1.22倍に留まる。これは推計の例で実測ではない。

## 検証と配備

- 既存ブラウザ・job・指示関連88テスト合格。その後の変更について、plan/flow/準備34テスト合格。重複するので122ケースと合算しない。
- 追加のflow公開制御・指示変更・無効時の通信禁止を含むflow関連11テストも合格。MCPのツール列挙で必須引数付きbrowser_planの公開とbrowser_flowの非公開を確認。最終fixture画像のStep 6も目視確認。
- Jevクライアントの異常応答、タイムアウト、低確信、画面変更、候補重複、キャンセル、途中指示変更、敏感な操作、クリック不確定時の再送防止を確認。
- 実APIの最初の40例は採用11/30と低かった。対象照合と権限判断を質問内で混同しないよう修正し、別の未使用40例で24/30採用・採用誤り0を確認。閾値はconfidence≥.9、選択確率≥.95のまま。以後この40例に合わせた閾値調整はしていない。
- 最終機能を含む92テスト合格。その後の本文範囲の絞り込み・診断情報について関連20テスト合格。既存の88件等と重複するため合算しない。
- Astra込みの比較では、全ページの曖昧な目標をそのまま渡す初期設計は棄却が多く、76〜83秒かかって通常経路より遅かった。画面の現在条件を特定して渡す設計へ変更。本番でも境界値で2回棄却したため、指定がある場合は無関係な本文を送らないよう修正した。失敗時も誤クリック0で停止した証拠を保存している。
- 承認は合計$3。実験は別台帳で最大200回、24,000bytesの送信上限に基づき最大費用より大きい$0.25を本番予算から先に確保。本番呼び出しは共有ファイルをロックし、送信前に費用を予約する。失敗・タイムアウトも払い戻さず、合計予約額が$3を超える呼び出しを拒否する。設定・鍵・予算・APIのいずれかが使えなければAstraへ戻す。無制限に有料実行する設定ではない。
- 設定は`~/.dan/jev-browser-budget.json`。鍵は従来の資格情報サービスのまま。診断・予算ファイルに入力値・ページ本文・APIキーは保存しない。
- 完了時点の試験台帳181予約、保守的費用見積もり$0.043062。本番側の52予約は試験との重複を含み、追加予約額$0.011674。二重計上しても合計$0.054736で、請求額の確定値ではない。本番予算は試験枠$0.25を含め$0.261674予約済み、残り$2.738326。失敗を含む別台帳の試験最大費用は$0.25より小さく、二重予約により上限を緩めることはない。
- 78室、CLI、command job、Core/sandbox配下のCodex実行が無活動であることを確認してCoreを再起動。PID44116→46676、Core9000とsandbox8000のhealthは200。新規MCPでツール公開を確認し、Core所有の専用ブラウザで実Jevの6段階と最終表示を検証。検証ブラウザだけ閉じた。最終状態の画像も目視確認。

合成課題・有限標本での合格は、全サイトでの品質不変を数学的に保証しない。外部サイトの遅さ、ログイン、CAPTCHA、文章作成、Astraの難しい判断はこの高速化の対象外。条件が不明なら通常経路を維持する。コミット・pushはしていない。
