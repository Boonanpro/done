## 実装

- 先回りの対象に `job_status`、`get_calendar`、`search_records`、`room_files` を追加。予定は「今日・明日・今日から7日間」と確実に分かった範囲だけ。それ以外は通常の裏側のモデルが読む。
- `work` は `list_operations` を読むだけ。作業開始、送信、予約、決済、ブラウザ操作は先回りでは実行しない。
- 同じ通話オブジェクト・本人・部屋・発言・実効引数だけを再利用する。読み取りは5秒で失効し、1依頼で1回だけ消費。途中の別の道具、言い直し、中止、遅れて届いた結果は再利用しない。バックエンドのキャンセルを飲み込まない。読み取りの待ちは最大1秒。
- 過去の会話の検索語が裏側で書き換わり、検索に使う語が一致しない場合は通常の検索へ戻る。部分一致だけで別の検索の結果を渡さない。
- 声と裏側の両方に、一点ずつ相談を詰める指示、曖昧な名前・数字・日付を一点だけ確認する指示を追加。組み立てたセッション設定でも確認した。開始済みの通話の設定は差し替えず、次の通話から適用される。
- 終話後に読む既存の1回の処理で、最大3件の決定を取り出す。本人の発言の引用と数字を検証し、提案や未決定事項は残さない。相談の仕様・予算を決めただけで新しい仕事を始めない。
- 通話の行の直下に1件のAIメッセージを置く。画面係の図があった場合は同じメッセージに含める。以前の通話の行・図の形式は保持。終話処理が失敗しても通話の行は先に保存され、図は最大30秒の待ちの後に残る。
- 決定の参照用に通話中の発言を最大60,000文字保持。直近24発言から消えた早い段階の決定も読める。上限を越えた通話からは、不完全な決定要約を作らない。
- `DAN_VOICE_PREFETCH_READ=0` で追加した読み取りだけ止められる。全先回りの停止は既存の `DAN_VOICE_PREFETCH=0`。

## 判定モデルと通話後の記録

固定した日本語30件でJevの分類は27/30→29/30。「今の作業の状況」と「過去の相談」の取り違えを解消した。「昨日送ったメールの返事」はtalkとなり先読みされなかった。先読みの種類を選ぶ5問は、作業状況・明日・今日・会話・部屋の資料の5/5が予定どおり。これは開発用の例題で、未知の発話の精度保証ではない。

LayaはMacのMPSで実行した。最終の同じ質問定義では **13/30正解、温まった後の中央値 24.79ms、初回 5.53秒**。最初の古い定義では9/30だった。速さは十分だが日本語の分類精度が足りないため採用せず、Jev停止時のdeepseek-flashを維持した。公式の33msはT4での値であり、Macの実測ではない。[公式README](https://github.com/NandhaKishorM/laya)

環境は作業場所の `.venv` のみ。`laya 0.4.15 / torch 2.14.1 / transformers 4.57.3 / scipy 1.14.1`。SciPy 1.15.xのwheelはMacで読み込めなかったため作業用環境だけ1.14.1へ変更した。本番の依存パッケージは変更していない。
