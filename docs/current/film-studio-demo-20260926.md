# 会話で映画を詰める独立デモ

## 目的と起動

ユーザーがダンと相談して2分の映画を詰める道具。エージェントが作品を代作して承認まで済ませるものではない。本番エディターのプロセス・既存作品は変更しない。

起動: `python -m scripts.film_studio_server`。URL: http://127.0.0.1:3020/
ユーザー用データ: uploads/production-assets/film-studio-demo-v1/contents.json。
ログ: scratch/film-studio/film-studio-demo-v1/events.jsonl。

既存の8項目を引き継ぎ、尺だけ今回の指示どおり2分。参考はHidden Figuresが近いという未採用の状態。以前エージェントが作った30秒案は引き継がず、物語・場面・会話は空から開始。

## 実装

- LIVE1 WebRTCとテキスト入力。GPT-6 Astra Responsesが同じ状態・道具を使う。
- 物語・場面・台詞・音・カメラを差分保存し、画像とsceneを場面IDに関連付ける。
- GPT Imageで完成見た目を作成・修正。画像モデルはJevで対応済み3モデルから選択。失敗・低確信時はGPT Image 2を使用しログに区別する。これは全モデル・全工程のルーティング完成ではない。
- 既存Jev参考検索を利用。Three.js/2D compositionの提示と差分修正、履歴を保持。
- 現在の処理を1行表示。サーバー側の道具実行中は作業名と経過秒数を表示。
- ページ再読込後も会話・案・見本を引き継ぐ。開始ボタンで自動発話しない。
- 場面ごとの生成指示・参照ID・音・未決事項をsave_recipeで保存可能。JSON保存ボタンは制作状態をダウンロードするだけ。本番動画生成は公開していない。

## 検証

別作品・別ポートで実GPT-6とブラウザを接続。物語案19.8秒、初回3D42.75秒、人物だけの配置変更19.61秒。コード同一、人物のstart/end座標だけ変更され、カメラ・車・工員のparams保持。再読込後の会話と見本を確認。

実画像ツール: JevがGPT Image 2を選択(confidence .99)、画像生成からブラウザ表示まで88.46秒。スクリーンショットを目視確認。音声の接続・終了成功。

実音声の追加試験はscratch/film-studio/check/result.jsonのvoice_editを参照。初回は実際の修正に成功したが、時間表示ラベルの正当なコード変更をテストが禁止して誤失敗。再試験は履歴を共有したため同じ指示の再適用として扱われた。その後の隔離用fixtureにはproposalのIDが欠けていた。これらを修正した独立条件で、音声指示から歩行2秒→1秒、見本全体4秒→2秒の変更に成功。他の配置・カメラは保持。接続ボタンクリックから検証完了29.76秒（接続準備と12秒の先頭無音を含むため応答速度ではない）。最終音声報告まで待つ検証を追加。成功のみを抜き出して最初から全件通過とは扱わない。

## 反映待ちと限界

追試完了: 独立作品で実LIVE1音声「今の動きを全体で半分の時間にして。他の配置はそのままで」→歩行1秒・全体2秒へ変更、他のparams保持、バックエンド処理終了と音声応答開始まで確認。接続クリックから検証終了50.78秒（先頭無音と最後の待ち時間を含む）。音声応答全文終了や自然さの合格までは主張しない。関連13単体テスト通過。ユーザー用3020の条件が2分で、テスト会話・採用済み物語が混入していないことを実ブラウザで確認。

2026-09-26、初回デモ起動後の追加修正を反映するための再起動が自動承認レビューでblocked by policyとなった。プロセス停止を迂回しない。起動中のデモには最後の「変更時に既存生成仕様をneeds_reviewにする」処理と、音声ログの順序逆転時に短い旧文で上書きしない処理が未反映。静的UIファイルは更新済み。

未検証: 2分全体の採用・制作仕様完成、複数場面の画像一貫性、実機マイクでの長時間会話、すべての参考URLの再生。作品全体の本番品質を証明していない。生成用仕様は保存できるが、対応プロバイダーでの実行可能性・費用・全場面の準備完了を自動保証しない。

現在の3Dはモデルが生成したsceneを隔離iframeで描画し、自然言語で差分修正する。汎用の3Dモデル・リグ編集ソフトが完成したわけではない。画像生成の遅さは測定値の通りで、瞬時表示とは報告しない。
