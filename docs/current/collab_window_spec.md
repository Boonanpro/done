# 外部窓口（コラボチャット）システム 動作定義書

作成: 2026-09-01（レビュー用ドラフト v1）
状態: **ユーザーレビュー待ち。承認された項目のみが正式仕様になる。**

これまで場当たりに実装してきた外部窓口まわりの挙動を、1枚に固定するための文書。
「誰に何が見えるか / 通知はどこに出るか / 成果物の正はどこか / 公開はいつ起きるか」を全て明文化する。

---

## 0. コンセプト

**外部の相手（クライアント）とのやりとりは、ユーザーが共有しなくてもダンに自動で届き、
ダンが作業と返信案まで済ませ、ユーザーはコミュニケーションタブだけ見れば完結する。**

- クライアント体験: 招待URLを開く→名前だけで参加→スマホならホーム画面追加でアプリ同様（Push通知つき）
- ユーザー体験: コミュニケーションタブの通知を見る→窓口画面で返信案を直して送信ボタン→終わり
- ダン: 窓口ごとに紐付いた本体ルームの文脈・記憶で動く。作業（成果物修正等）は実際に実行する

## 1. 登場する場所と役割

| 場所 | 役割 | クライアントから見える? |
|---|---|---|
| **コラボ窓口**（コミュニケーションタブ内の1ルーム） | 対応の主戦場。会話・返信案カード・送信結果が全部ここ | ✅（カードと owner_only 発言は見えない） |
| **プロジェクトルーム**（本体チャット） | ダンの文脈・記憶の置き場。窓口はここに紐付く | ❌ |
| **成果物タブ** | クライアント納品物（HP等）の現物 | ❌（公開URL経由でサイトだけ見える） |
| **通知タブ（ベル）** | フォールバック専用（ダンを起こせなかった時だけ） | ❌ |

## 2. 受信フロー（クライアント発言時）

```
クライアント発言（窓口）
  → 窓口に未読バッジ + オーナーへPush（既存）      ← ユーザーへの通知はここ**だけ**
  → core /internal/collab-inbound → 窓口ごとのアグリゲータ（collab_wakeup）
      ├ **60秒静かになるまで待つ**（連投を1回の起動に畳む。デバウンス）
      ├ 起動時は**未処理メッセージ全部**をまとめて読む（処理済み位置はDBに永続化）
      └ ターン実行中に届いた分は同じウェイターが次のバッチとして続けて処理
  → 紐付きプロジェクトルームでダンを自動起動（wake）
      ├ まず**3分岐の判断**をする:
      │   (a) 軽微で明確な依頼 → 実行して返信案カード（窓口画面にインライン表示）
      │   (b) ユーザーの判断が要る → 作業せず consult（相手に見えない相談を窓口画面へ・通知つき）
      │   (c) 返信不要（お礼・相槌） → 何も出さない（方針が許せば👍等の短い一言のみ可）
      ├ 連投にはカード**1枚**でまとめて応じる
      └ 本体ルームには「窓口ログ: …」1〜3行だけ残す
           └ 折り畳み表示・未読を増やさない・部屋一覧も動かさない（静かな記録）
  → wake不能（コア停止・15分ビジー）時のみ通知タブへフォールバック（連投は1通にまとめる）
```

- ダンの記憶 = プロジェクトルームの履歴（窓口ログ含む）+ 送信案ダイジェスト。
  後からその部屋で「◯◯さんの件どうなってる?」と聞けば全部答えられる。
- 紐付きの無い手動作成ルームは従来どおり（隔離collab DANの軽いサポートのみ）。

## 3. 送信フロー（ユーザー承認 / ダン送信）

- カードの「送信」ボタン（窓口画面）＝ ダンの `compose_message(action="send")` ＝ 同一経路。
  DBの現在本文（ユーザー編集反映済み）が送られる。
- 送信結果はクライアントに「ダン」名義でリアルタイム到着（WS配信＋Push）。
- 送信・破棄の事実は本体ルームには出さない（窓口の会話に残る + ダンには次ターン冒頭ダイジェストで伝わる）。

## 4. 表示・通知マトリクス

| イベント | 窓口画面 | プロジェクトルーム | 未読/通知 |
|---|---|---|---|
| クライアント発言 | ✅ 本文 | —（ダンが起きるだけ） | 窓口の未読＋Pushのみ |
| ダンの作業ログ | — | ✅ 折り畳み1行（窓口ログ:） | **付けない** |
| 返信案カード | ✅ インライン（未送信のみ） | ❌ 出さない | 付けない |
| 送信/破棄 | ✅ 会話に残る | ❌ 出さない | 付けない |
| wake失敗 | — | — | 通知タブ（ベル） |

> 検討中: 折り畳みログすら出さない「完全非表示」モード。しばらく折衷案で運用して判断（2026-08-31 ユーザー決定）。

## 5. 運用方針（自動/承認バランス）

- **既定 = 全件承認**。ダンは送信案カードまで。勝手に送らない。
- **作業に着手するかも判断対象**（§2 の3分岐）。費用・納期・デザイン方針・仕様の大幅変更・過去指示との矛盾などは、作業前に consult でユーザーに相談する。
- 返信の文体はチャット準拠（宛名・定型挨拶・署名なし、相手のトーンに合わせ簡潔に）。絵文字1〜2個だけの発言はスタンプとして大きく表示される。
- 窓口ごとに `collab_thread(action="set_policy", autonomy="auto", guidance="許可範囲")` で
  **guidance の範囲内だけ承認なし送信可**（例: 受領確認・お礼のみ）。範囲外・金額・納期・新しい約束は常に承認待ち。迷ったら承認待ちに倒す。
- ユーザーが部屋でダンに口頭で指示すれば、ダンが set_policy を呼んで切り替える。

## 6. 成果物と公開

- **編集の正 = ローカルの成果物ファイル**（`frontend/src/app/artifacts/<slug>/`）。ダンはここを直接編集する。
- **クライアントが見る場所 = 公開URL**（成果物専用の Vercel プロジェクト。1成果物=1プロジェクト）。
- **公開は自動**: ダンが成果物を編集したターンの終了時に専用デプロイが自動実行され、2〜4分で公開URLに反映される（編集ツールの書き込み追跡→ `schedule_dedicated_deploy`）。
- 成果物タブは配信URL（delivery_url）優先で表示するため、自動デプロイが回っている限りタブ＝公開＝ローカルが一致する。
- 既存クライアント案件（kittoku 等の writeback→push 経路）はこの仕様の対象外。従来どおり。

## 7. 自動起動ターンの出力規律

- collab wake の本体ルーム出力は「窓口ログ:」で始まる1〜3行のみ。長い報告・本文引用・前置き禁止。
- 公開反映は自動なので、反映確認の見張りを乱発しない（確認するなら1件だけ）。
- 承認なし送信の可否は §5 の方針に従う（wakeプロンプトに方針が注入される）。

## 8. 窓口の作成

- ダンのツール `collab_thread(action="create", title=...)` → その部屋に紐付いた窓口＋招待URLを発行。
- 招待URLは初回参加の期限つき（既定7日）だが、**一度参加した相手は無期限アクセス**（意図した仕様。2026-08-31 ユーザー決定）。
  リンク流出対策として「招待の無効化」ボタンを将来追加（未実装・優先度低）。
