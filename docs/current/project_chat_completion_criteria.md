# Project Chat 完成条件

## 目的
プロジェクトチャットで、ユーザーが依頼してから「提案」「承認」「実行」「完了」までを、ぶれずに動かせる状態を完成とする。

## 対象範囲
- 対象: チャットでの運用（テキスト）
- 対象外: 音声連携、旧 `create_project` ツール経由の自動起動

## 完成条件（Done）
以下をすべて満たしたら完成。

1. ユーザーがプロジェクトチャットに依頼を書くと、計画提案が1件作られる
- 提案は `project_proposals` に保存される
- プロジェクト状態は `planning` から `proposed` になる

2. 提案を承認すると、実行が開始される
- プロジェクト状態は `approved` を経由して `in_progress` になる
- 実行イベントが `execution_events` に記録される

3. ステップ実行中の結果が保存される
- 各ステップの状態（成功/失敗）が proposal の steps に反映される
- チャットに進捗メッセージが出る

4. 危険ステップは停止して確認待ちになる
- 確認待ち時は `awaiting_confirmation` になる
- ユーザーが再開したら次に進む
- ユーザーが中止したら `paused` になる

5. 最終状態が正しく終わる
- 全ステップ完了なら `completed`
- 中断・失敗で停止なら `paused`

6. 旧経路に依存しない
- チャット起点の提案・実行フローで `app/agent/v2/runner.py` と `app/agent/sdk_runner.py` を呼ばない

## 受け入れテスト（最低）
1. 正常系
- 依頼送信 -> 提案作成 -> 承認 -> 実行完了 -> `completed`

2. 確認停止系
- 危険ステップで停止 -> 再開 -> 完了

3. 中止系
- 確認停止 -> 中止 -> `paused`

4. 失敗系
- ステップ失敗 -> 結果記録 -> `paused`

## 非機能条件
- 同じ入力で大きく動作がぶれない
- 失敗時に原因を追えるログが残る
- 途中で切断しても再開手段（`/resume`）がある

## メモ
- このファイルは「実装前の約束」と「実装後のチェック」の両方に使う。
- 実装中に仕様を変える場合は、このファイルを先に更新してからコードを変更する。

## 追加要件（差分）
1. 調査・計画段階と実装段階の両方で、プロセスモニターを必須にする
- 「今なぜその作業をしているか」と「今何をしているか」が追えるログを継続表示する

2. 作業中のキャンセルは即時に反映する
- 停止ボタンまたは `Esc` によるキャンセルで、その時点の作業を中断する
- 中断はイベントと状態に反映され、再開可能な形で残る

3. 方向転換時は軌道修正と再調査を許可する
- 提案出力後・実装中を含む任意のタイミングで、ユーザー方針が変わったら再計画できる
- 必要なら再調査を行い、旧案を引きずらずに更新した方針で続行する

4. 全行動で自律実行・自己修復・自己拡張を許可する
- 人間が事前にツールを作る、コードを直す、手順を準備する前提にしない
- 利用可能な基本ツールで、必要な修正・拡張・実行を自律的に進める
- ただし Green / Yellow / Red の提案・報告・停止基準は常に守る
