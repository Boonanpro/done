# 音声の会話確認に重なる補完返答

本人の音声の使い勝手改善依頼の続き。外部電話発信なし、スピーカー出力なし。実音声試験は専用部屋と専用メモだけを使用。

## 原因と変更

前回の voice-backchannel-final では、質問への音声回答25.24〜28.65秒に重なって26.15秒に補完の response.create が発生し、32.10秒に別の回答本文が届いた。受付済みの仕事が一つでもあれば、会話の確認にも毎回補完を要求していた。

補完が必要な未処理発話で、既に仕事を受け付けた時だけ、聞き終えた言葉と会話の文脈を既存の判断接続へ渡す。会話だけで答えられると判断できた場合は自動補完を省く。音声そのものと通常の delegation は待たせず、実行許可・完了判定も変更しない。先の仕事が未開始なら省略しない。

判定は最大1.2秒。失敗・曖昧・新発話なら通常の補完を維持し、同じ発話の判定は繰り返さない。既知の呼びかけだけなら追加判定なし。新しい言葉が来たら省略結果は無効。通常の delegation が先に届いたら二重に要求しない。

## 証拠（作業場所 voice-conversation-dispatch）

- `.tmp/voice-conversation-after`: 発話途中の先読みだけを使う試作。質問の認識が短く、判定できず補完が残った。この方式は不採用。
- `.tmp/voice-conversation-settled`: 聞き終えた後の判定へ変更。質問は「何何か覚えてる」と認識。補完は残った。
- `.tmp/voice-conversation-clear`: 質問前の間隔を5秒から12秒へ変更し、全文を認識。ただし conversation 0.89 を閾値0.9が拒否した。速度の前後比較には使わない。
- 限定した意味判定で、進捗・完了確認・送信承認・無料への変更・過去の決定・会話確認に続く停止を backend と判断。会話確認は0.89〜0.97だったため閾値0.8を使用。これは一般的な誤分類率を保証しない。お礼は0.75で補完を省かなかったため、全種類の重複が解消したとは扱わない。
- `.tmp/voice-stop-selection`: 音声で専用の別室停止を依頼。job_status → stop_run → job_status を選択し、発話終了から5.164秒で停止操作。専用実プロセスは終了し、35秒後の書き換えは発生せず、メモはstartedのまま。外部メッセージ0。対象情報・認証境界は試験用の固定値、停止処理とプロセスハンドルは実装そのもの。実際の本人の部屋を停止した証拠ではない。

新しい実通話での主観的な自然さ・端末を含む速度は未評価。発話が重なった時の文字認識欠落と、お礼・相づちの余分な返答は残る確認対象。
