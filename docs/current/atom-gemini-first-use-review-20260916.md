# Atom Gemini 初回利用レビュー

2026-09-16。対象は09:55〜09:59 JSTのGemini 3.8 Live Extended Thinking、thinking=lowの通話。
チャット保存内容、headlessイベント、音声送信統計、実行ジョブ記録を突き合わせた。
その後のmedium通話についてはユーザーから「会話改善された」と報告あり。以下の問題をmediumの評価に流用しない。

## 観測と評価

- 使用モデルを尋ねられても「私はダン」と繰り返し、質問の意図に答えられていない。現行プロンプトにはダンとしての役割がある一方、実際の音声モデル名の明示がなく、統合側にも改善余地がある。
- 前日の予約の確認では保存された質問から具体的回答まで約39秒かかり、その間に確認中の応答を繰り返した。これは文字起こし保存時刻の差であり、音響的な応答遅延の厳密な測定ではない。
- キャンセルを進める・停止したと発言したが、この通話には対応するdelegate_to_dan/control_dan_task、新規作業ジョブの記録を確認できなかった。発話と実行の一致を確認する必要がある。実際の予約状態はこの調査では確認していない。
- イベント日程という通常の検索依頼に回答を拒否した後、外国語の文字起こしと外国語応答が入った。ユーザーから日本語で話すよう訂正があった。録音がないため誤認識の原因は断定できない。
- 最終的には検索ツールが成功していた。一方、09:59:22の「システムエラー」という応答は、こちらがmedium設定を反映したfrontend更新時刻と重なる。更新でリクエストが中断した可能性があり、モデルだけの不具合とは評価できない。
- 通話終了依頼の保存後にも前の検索結果の発話記録があり、約5秒後にstandby要求、約6秒後に閉じた。終了依頼の優先順位には改善余地がある。

## 限界

音声送信統計266件ではsend timeoutは0、最大gapは78ms、100ms超は0だった。
この範囲で大きな送信断は見られないが、マイク・スピーカー・AEC・認識精度が良好だった証明ではない。
生音声と詳細な全ツール入出力を保存しておらず、音声モデルとAstraのどちらで判断が崩れたかは断定できない。
事前比較試験の合格範囲は接続、音声出力、割り込み応答、通話終了であり、予約業務や会話全般の品質を保証するものではない。

## Medium / Highと費用

Mediumで改善したというユーザー評価を受け、Highのソース・ビルドと設定送信を検証済み。
当初の本番更新は自動承認レビューで拒否され、詳細理由は返されなかった。
再依頼後、本番がHighビルドで稼働していること、ヘルス正常、本番ブラウザのsession要求がthinking=highであることを確認した。
実機は確認時点でオフラインのため、Highでの実機会話の品質はまだ未評価。
公式料金は推論レベル別の単価ではなくトークン従量。テキスト出力（推論を含む）は100万トークンあたり$4.50。
仮にHighで推論が1万トークン増えればその分は$0.045、10万増えれば$0.45。
これは増分の計算例であり、この利用での予測ではない。推論使用量の実測がないため倍率は未算定。
音声入力$0.005/分、音声出力$0.018/分。履歴処理、文字起こし、裏側のAstra費用は別途考慮が必要。
