# 通話の調べものの判断を DeepSeek V4 Pro へ（2026-11-12）

本人の 11/12「進めて」（やることの1番目）。通話の裏の調べもの（app/services/voice_lookup.py）で、検索結果を読んで判断し答える係を
gpt-6-luna（考える深さ low）から deepseek-v4-pro（high）に替えた。検索（web_search.py の DeepSeek 検索＋flash）とページ読み（read_page）は同じ。

## なぜ

11/11 11:09〜11:15 の通話。本人が「なかえまさし」先生（北九州・鍼灸）を頼み、文字起こしは「中江雅史」。検索は「仲江政史・仲江鍼灸院（田川郡香春町）」を
返していたのに、luna は字が違うことを理由に3回とも「特定できなかった」と答えた。15〜30秒で切り上げていた。

## 何を変えたか

- MODEL=deepseek-v4-pro、REASONING=high。DeepSeek は Responses API を受けるが応答を保存しないので（previous_response_id は「No tool call found for tool output」で断られる）、毎回それまでの全履歴を input で送る（stateless()）。
- 指示: 本人の言葉は文字起こしで、人名・店名・地名の字は音に当てた推測。字の違いは理由にせず手がかり全体で判断し、決めきれなければ「どこの誰か」を入れた問いで確かめる。急がず中心の事実はページを読んで確かめる。中心が1つ分かったら先に share_progress。
  「読みが同じなら同じ人」「何秒で決まらなければチャットのダンへ」は入れていない（本人が場当たり的と却下）。指示の例は試しの件と別の名前にした。
- 持ち時間 120→150 秒。次の1回分の検索で 110 秒（SECONDS-40）を越えそうになったら、道具なし・考える深さ low の最後の1回で、確かめた事実から答えさせる（WRAP_UP）。直す前は2つの頼みの後半を調べ続けて3回中3回とも時間切れ・無言だった。
- 道具なしで呼ぶのは、tool_choice=none だと DeepSeek が道具の呼び出しを文字で答えに書いた（<｜｜DSML｜｜tool_calls>…）ため。without_markup() でも消す。
- 戻すには DAN_VOICE_LOOKUP_MODEL=gpt-6-luna（DAN_VOICE_LOOKUP_REASONING=low）。

## 試し方と結果

`python scripts/voice_lookup_compare.py <tree> tests/voice_lookups/<件>.json <out.json>`。<tree> に /Users/mikihonda/done（前）と作業場所（後）を渡し、同じ入力で比べる。
本物の調べもの係（モデル・指示・ダンの検索とページ読み）が動く。画面の道具は通話の無い部屋に向くので何も出ない（前後とも同じ）。答えを正規表現で採点する。
