# インスペクタ（ライブペイント）再設計

作成日: 2026-04-26
ステータス: 提案中（実装前）

## なぜこれを書くか

吉川特装の HP を編集中、以下の不具合が出ている：

- 「特装車 全機種、キットク（吉川特装）にお任せください。」が編集できない
- 「キットク」だけが独立した部品として選べてしまう
- クリックすると「（吉川特装）」が増殖する

最近のコミット 5 本はすべてこの種の不具合に対する応急処置で、直しても次が出る。**設計が原因**なので、応急処置をやめて作り直す。

## 何が根本原因か

現在のエディタは「**画面に映っているHTMLそのもの**」を編集して保存している。

文字の一部だけ色を変える操作（`setLiveStyle` の部分テキスト分岐）が、装飾用の小さな部品（`<span>`）を**文章の中に差し込み**、その差し込み済みのHTMLを `inspector_overrides.attrs.html` として保存する。

問題は、

1. **要素の識別方法**が「HTML上の位置」ベース（例：`div[0]>section[2]>p[1]`）。
2. しかし装飾を入れるたびに**HTML構造そのものが変わる**（部品が増える）。

この 2 つは両立しない。次にクリックしたとき、本来は文全体を選びたいのに、差し込まれた部品の方が選ばれる。`setLiveText` がその部品にテキストを書き込む → 増殖して見える。

`fix(inspector-runtime): 編集中の要素への text override 再適用を停止` `fix(inspector): html/text 衝突 + nested span 防止` などの最近のコミットは、この衝突を後追いで埋めているだけで、構造的に終わらない。

## 何を変えるか（一文で）

**「画面のHTML」を保存するのをやめ、「文章」と「装飾の指示」を別々に保存する。画面はその 2 つから毎回組み立てる。**

これは Slate / Lexical 等のリッチエディタが採用している標準的な分離。

## 新しいデータの形

### 編集対象 1 つにつき保存するもの

```json
{
  "element_id": "ykw-hero-headline",
  "text": "特装車 全機種、キットク（吉川特装）にお任せください。",
  "block_style": { "font-size": "32px", "color": "#222" },
  "spans": [
    { "start": 8, "end": 11, "style": { "color": "#c00" } },
    { "start": 12, "end": 17, "style": { "font-size": "40px" } }
  ]
}
```

- `text`: 一本のプレーンテキスト。span などのHTMLは入らない。
- `block_style`: 要素全体の装飾。
- `spans`: 部分装飾の指示。文字位置（start/end）で範囲を指定する。**HTMLを含まない**ので構造変化が起きない。

### 既存データとの違い

| 現状（`attrs`） | 新形式 |
|---|---|
| `text: "..."` または `html: "<span>...</span>..."` のどちらか（衝突あり） | `text` と `spans` が常に分離 |
| 装飾を増やすと html が膨らみ構造が変わる | text は固定、spans 配列が増えるだけ |

## 要素の識別方法を変える

### 現状の識別子（壊れる）

```
div[0]>section[2]>p[1]>span[0]
```

DOMの位置を使うので、span が差し込まれただけで identifier が指す先がズレる。

### 新しい識別子（壊れない）

```
ykw-hero-headline
```

ページのソース（JSX）が**初期化時に各編集可能要素に固定IDを振る**。
このIDは構造変化に影響されない。クリックは常に「論理的なまとまり」（見出し1つ、段落1つ）を選ぶ。

実装：吉川特装の各 JSX 要素に `data-edit-id="ykw-hero-headline"` を付ける。新規ページは生成時に自動付与する。

## 編集→保存→画面反映の流れ

```
[ユーザー操作]
   │
   ▼
[エディタ UI]
   │  「ykw-hero-headline の 8-11 文字目を赤に」
   ▼
[データを更新]
   │  spans に { start:8, end:11, color:"#c00" } を追加 or マージ
   ▼
[画面を再レンダ]
   │  text + spans から HTML を組み立てて innerHTML に書き戻す
   ▼
[保存]
      element_id, text, block_style, spans を inspector_overrides に upsert
```

ポイント：
- **DOMは出力先**。データを変えてから DOM を作る。逆方向（DOM を編集してから保存）はやらない。
- 連続スライダー操作も spans を更新するだけ。span がネストする問題は構造的に発生しない。
- `setLiveText` は `text` フィールドだけ更新。spans の文字位置はテキスト編集時に自動補正する（追加位置以前は不変、以後はズラす）。

## 既存データの移行

現在の `inspector_overrides` の `attrs.html` には差し込まれた span 入りのHTMLが保存されている。

### 移行ルール

1. `attrs.html` をパースする（HTMLパーサ）。
2. `<span data-dan-edit="1" style="...">` を検出。
3. その span の前後のテキストから `start` / `end` 文字位置を計算。
4. style 内容を `spans[].style` に変換。
5. span を取り除いた純粋なテキストを `text` に格納。
6. `attrs.text` のみがあるレコードはそのまま `text` に移す。

### 失敗時

パースに失敗したレコードはログに出して保留（古い形式のまま残し、UIで「再編集が必要」と表示）。新規編集すれば新形式で上書きされる。

### 段階移行

DBスキーマは増やさず、`attrs` の中身を新形式に切り替える方式にする：

```json
{
  "v": 2,
  "text": "...",
  "spans": [...],
  "block_style": {...}
}
```

`v` フィールドの有無で新旧を区別。InspectorRuntime は両方読めるようにし、書き込みは常に v2。

## 非ゴール（やらないこと）

- リッチエディタ機能の追加（リスト、見出しレベル変更、リンク挿入の改善）。今回は**現状維持で構造だけ直す**。
- JSX 自動書き戻し。引き続き JSX には触らず DB の overrides に保存。
- 複数要素の同時編集。1要素ずつのまま。

## リスクとロールバック

### リスク

- **既存の overrides の移行失敗**：吉川特装に既に多数の編集が入っている可能性。プロトタイプ段階（ステップ 6）でこのページの実データで移行関数を試す。
- **`data-edit-id` の付け忘れ**：新規生成ページで漏れると識別不能。生成スキル（`build` skill）にチェックを追加する。
- **連続編集中のID衝突**：同じセクションを2人が同時編集する想定はないので不要。

### ロールバック

`v` フィールドで新旧を区別するので、新形式の保存を無効化すれば旧形式に戻る。フロント側のレンダだけ旧コードに戻せば即時復旧可能。スキーマを破壊しない設計にしているのでDB側のロールバックは不要。
