# SEO・集客 自動エンジン 計画書（専門用語なし版）

最終更新: 2026-06-22

## これは何の計画か

「ダンが作ったサイトを、サイトの中身に合わせて“よしなに”自動で伸ばす」仕組みを作る計画。
今のダンは「Googleに登録する」ところまでは自動でできているが、その先（人が来る・ビューが伸びる）が空白。
ここを、サイトの種類を見分けて自動で最適な伸ばし方を実行するエンジンとして埋める。

### ★最重要：成果物は「個別サイト」ではなく「汎用エンジン」
電管ナレッジや paina.info を1回手作業で伸ばして終わり、ではない。
作るのは「**どんなサイトでもダンが中身を見て、自分でパターンを選び、自動で伸ばし続ける土台**」。
2つの題材は、その土台が本当に効くかを実物で確かめる**テスト台**であって、最終目的ではない。
（関連: project_reusable_primitives_direction = 毎回ゼロから作らず共通の仕組みから選ぶ方針）

参考にした実例: 補助金エージェント（hojokin-agent.jp）。
かっこいいデザインではなく「11万件の補助金データを自動でページ化している」ことが強さの正体だった（実地調査済み）。


## 今あるもの / 無いもの（2026-06-22 時点・実コード確認済み）

### ある（土台）
- 独自ドメイン取得 → 公開 → Google所有権確認 → サイトマップ申請 までは**全自動**
  （`app/tools/publish_site/search_console.py`、公開フローに結線済み）
- 独自ドメイン時だけ検索に出す/プレビューは隠す、の出し分け（`robots.ts` / `sitemap.ts`）
- 構造化データ（WebSite/Organization）の自動埋め込み（`_seo/structured-data.tsx`）

### 無い / 使われていない（ここを作る）
- 検索データの引き戻し（どの言葉で人が来てるか／来てないか）← Googleに申請するだけで結果を見ていない
- アクセス計測（何人見たか）← 公開サイトに計測タグが一切入っていない
- サイトの中身に合わせた自動改善・ページ量産 ← まるごと未実装
- 店舗向けのGoogleマップ連携 ← 未実装
- `LocalBusiness` 構造化データ生成関数（`seo_generator.py` にあるが呼ばれていない死にコード）


## 伸ばし方は4パターン（ダンが自動で選ぶ）

| # | パターン | こういうサイトの時 | 伸ばし方 | ビューの伸び |
|---|---|---|---|---|
| ① | データ量産型 | 補助金・記事・店舗など**元データが大量にある** | 1件1ページを自動で数千〜数万ページ生成 | 爆発的 |
| ② | 記事型 | 専門知識はあるがデータは無い | 「○○ 費用」等、人が検索する悩みに答える記事を量産 | 中〜大 |
| ③ | 地域・店舗型 | 飲食・美容室・地元企業 | Googleマップ／地域検索に強くする、地図に店情報 | 中（地元に強い） |
| ④ | ブランド/成約型 | 1サービス・コーポレート | 社名/サービス名で確実に出す＋問い合わせ成約。広告と併用 | 小（質重視） |

### 「よしなに」の中身
1. ダンがサイトの中身を読んで「これは①／②／③／④だ」と判定する
2. 判定したパターンの伸ばし方を実行する
3. 公開後、Googleの検索データを毎週見て「来てる言葉／来てない言葉」を読み、自動で手直しする（改善ループ）


## 最初の題材2つ（実物でテストする）

### 題材A: 電管ナレッジ → パターン①（データ量産型）★最優先
- 正体: 電気主任技術者向けに、同業ブログ19ソース＋YouTubeの記事を横断検索する知識サイト
- **すでに3,499記事を収集済み**（`frontend/public/denki-knowledge-index.json`、6.8MB、日次自動更新あり）
- 今の弱点: データはあるのに「1ページの検索アプリ」止まりで、Googleに拾われるページ群になっていない
- ⚠️ **著作権の絶対ルール**: ブログ主には「リンクのみ・完全引用しない」と約束済み。
  各ブログ記事の本文を自サイトにコピーするのは**禁止**（約束違反＋Googleが重複コンテンツとして評価を下げる二重の悪手）。
- やること（約束を守った上で）: 集めた3,499記事は“コピー元”ではなく“どのテーマが重要か／どこへリンクすべきかの材料”として使い、
  - **専門用語・テーマごとのオリジナルまとめページ**（VCB・絶縁抵抗・接地・PAS・継電器試験 等／数百〜）
    = ダンが書いた短い解説（オリジナル）＋「詳しくはこの方のこの記事」と外部リンク集
  - 必要なら各テーマの**オリジナル解説記事**（パターン②寄り）
  を自動生成し、サイトマップに載せてGoogleに出す。記事本文は載せず、リンクで送る（ブログ主にアクセスを送る側になる＝利害一致）
- **補助金エージェントの小型版。** ただしページの中身はコピーでなく自前のまとめ。一番すぐ結果が見えて、面白い
- ⚠️ ドメイン未取得 → ただしダンのドメイン自動取得が使えるので**ブロッカーではない**。安いドメインを1つ取れば即着手可能

### 題材B: paina.info → パターン④（ブランド/成約型）
- 正体: 株式会社パイナのコーポレートサイト（日英、waitlist/contact 付き）
- ビュー爆発を狙う種類ではない。狙いは「パイナ」「AIエージェント ダン」等で確実に出す＋問い合わせ成約
- やること: 社名/サービスの構造化データ整備、OGP/タイトルの最適化、検索データで指名検索を確認、必要なら会社紹介系の記事を数本
- ①の対極（質・成約）として、エンジンが両端をカバーできるか確認する良いテスト


## 作る順番（一気にやらない・1つずつ動かす）

各段階で「実際に動くもの」を出してから次へ進む。

- **第0段（土台の穴埋め・小）**: 公開サイトにアクセス計測タグを自動で入れる＋検索データを引き戻して見えるようにする。
  → 以降すべての「改善ループ」がこの数字で回るので最初にやる。
- **第1段（題材A・本命）**: 電管ナレッジでパターン①を実装。ドメイン取得 → 3,499記事＋用語ページを自動生成 → Google登録 → 数字を観測。
- **第2段（題材B）**: paina.info でパターン④を実装。ブランド整備＋成約導線＋指名検索の確認。
- **第3段（横展開）**: ①④で固まった仕組みを「サイトを見て自動でパターン判定」する入口に繋ぎ、②記事型・③店舗型を足す。
- **第4段（重い）**: Googleビジネスプロフィール連携（マップの店情報編集）。API審査が要るので最後。


## 「完成」の定義（何ができたらOKか）

- 電管ナレッジ: 独自ドメインで公開され、記事・用語ページが数千件Googleに登録され、検索からの訪問が計測できている
- paina.info: 「パイナ」等の指名検索で1位付近、問い合わせ/waitlist のアクセス計測ができている
- 共通: 毎週ダンが検索データを見て「この言葉が弱い→このページを直す」を自動で回せている


## 未確定・ユーザー判断が要る点
- 電管ナレッジ用のドメインを取るか（取るなら候補TLDと予算。例: `.jp` / `.com` / `.info`）
- 計測は運営者（パイナ）の共通アカウントで全テナント分まとめて持つ方針でよいか（既存のSearch Console方針と同じ＝おそらくYES）
