# 編集可能な成果物: 初回検証（2026-09-07）

> この初回は編集機能の検証に偏り、ユーザーの求める画像LPとの品質比較になって
> いなかった。その後の同内容比較は [floor-lp-comparison.md](floor-lp-comparison.md)。

目的は「高品質な成果物を編集可能な形で作る」。画像貼り合わせ・画像からの再構成・
コード制作のいずれかを維持すること自体は目的ではない。

## 今回の実装

- buildのLP画像方式への固定を解除。新しい制作入口は
  `.claude/skills/build/recipes/editable-lp.md`。画像素材とネイティブ要素を組み合わせ、
  編集・レスポンシブ・保存と見た目を確認する。
- `EditableElement`を追加。画像とセクションのスタイル・属性を公開リビジョンから
  描画する。単なる`data-edit-id`付与ではできなかった初回HTMLへの反映を行う。
- `toEditableOverrides`が画像コントロールの直接保存形式（attrs.src/alt等）を読む。
  以前はmodel_v2内の属性しか読まず、画像がプレビューだけ変更される問題があった。
- 手動編集の画像URL差し替えを追加。行間はcomputedStyleのpx値をフォントサイズで
  割って倍率として扱うよう修正（以前はpxをそのまま倍率入力に表示）。
- 既存moonbox素材でネイティブな3セクションLPを作成。写真は既存ファイルを
  未加工でコピー。写真内部の画素を編集可能にするものではなく、写真自体の差し替え、
  文字、主要レイアウトの編集を対象とする。顧客の既存LPは変更していない。

## 確認方法・結果

ローカルプレビュー: http://localhost:3001/preview/editable-lp-lab

`python scripts/test_editable_lp.py --origin http://localhost:3001`

- 1440pxで表示し、写真の読込・編集IDの一意性を確認。
- 390/700/1024pxで横はみ出しなし。
- 実際のPreviewPaneの手動編集で改行を含む見出しを変更、行間1.4→1.8を確認。
- 画像URL欄で画像を差し替え。セクション余白はstoreの既存操作で変更。
- 新しいブラウザーコンテキストで保存された文字・画像・余白を復元。
- 一時的なrelease.gen.jsonを実際のNextページに読み込ませ、JavaScript無効でも
  文字・画像・余白が初回HTMLへ反映されることを確認。終了時にファイルを復元。
- 長い見出しへ変更後のモバイル表示でも次のセクションと重ならないことを確認。
- `npm run typecheck`成功。新しい編集プリミティブ・サンプル等のESLint成功。
  inspector-panelには変更前から存在するset-state-in-effect / memoizationのlint違反が残る。

スクリーンショットと機械検証結果は `scratch/editable-lp-verification/`。
再実行で生成できるため、このディレクトリは配布する実装には含めない。

## 未確認の範囲

- 保存APIは検証専用のメモリー内ストレージ。本番DB、認証済みチャットからの生成、
  公開デプロイは未検証。未認証のローカルAPIは401を返すことを確認した。
- 見た目はPC/スマホ画像で目視確認済みだが、既存Image 2 LPとの同一内容・同一素材の
  比較は未実施。この試作で画像方式以上の品質や、全LPの品質再現性を証明したとは扱わない。
- 既存画像LPの一括変換、ピクセルからの文字・背景の分離、レイヤー並べ替えUI、
  手動編集全操作のUndo/Redoを今回実装したわけではない。

次の品質検証は同じ実案件の短い区間を画像方式と編集可能方式で並べ、見出し、
写真・図解、密度、余白、モバイルでの読みやすさを比較する。方式を決め打ちせず、
見た目の差を特定して制作手順に反映する。
