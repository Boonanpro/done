# 作業表示と最新ログの調査

ユーザーの指定によりスキルは使用していない。制作中のジョブや音声接続を停止せず、静的 UI と次回の処理に使う計測情報を修正した。

## 変更

- オーブ周囲の回転リング・虫眼鏡を撤去。カードの登場時の移動と拡縮、オーブ全体の上下動を撤去。
- 現在の依頼と実行中の道具を表示。追加指示の受領待ちと状態更新の途絶を区別する。
- マイク OFF と制作の実行状態は独立して表示する。
- LIVE への状態通知は現在進行中のジョブだけ。過去の完了・失敗の一覧を現在の進捗として渡さない。個別の終了通知は継続。
- 作業イベントの日時が数値で ISO 日時を上書きする不具合を修正。
- 制作ツールが description を持つ場合は作業表示へ渡す。コマンドそのものは表示しない。この Python 側の変更はサービスの次回読み込みから有効。

## ログで確認した問題

音声イベント a9236a93-bfee-4a81-b15e-2447fa1f4f94、制作ジョブ 73b3b9cc-a27f-4942-840f-615f40b47994。時刻は UTC。

- 10:57:11〜10:57:42 の画像確認は約31秒。個々の資料・素材取得は26〜115ms。空の参考一覧を取得し、素材一覧を経由して同じ画像を2回取得した。モデルの各判断の間隔は数秒。画像検索の query に一致しない場合、サービスは候補全件へのフォールバックを明記して返している。query が無視されていると断定しない。
- 10:54:39以降に wait_for_user で終わる約8秒の判断が複数ある一方、音声側は確認中と発話していた。モデルの能力不足と断定できない。
- 11:03頃の「二つ完了、一つ失敗」という報告は直後に訂正された。実装は履歴ジョブも同じ状態通知で送信していた。今回この混在を修正したが、音声の再試験で誤報解消を検証する必要がある。
- 制作側は11:10:28に音声・映像素材種別の不一致、11:10:46には編集対象範囲外のクリップで失敗している。操作自体は0〜0.2秒で失敗し、その間に再判断が発生している。GPU待ちだけでは説明できない。
- 11:10頃の検品 watch_render は約40.6秒。判断や検品の時間をすべて無駄と扱わない。

## 検証

- Node 音声・画面・切断ライフサイクル6件成功。
- 実際の HTML/JS/CSS を使う Playwright テスト成功。発話対象Aのまま参考Bへ移動、マイクOFF時の作業表示、過去ジョブの除外、表示位置の安定、390px幅で操作ボタンとの非重複を確認。
- editor_activity の既存テスト2件成功。
- テスト画像は架空の状態を注入した表示検証。実際の銘板修正の成功を証明する画像ではない。

## 残る範囲

制作の対象指定エラー、モデル往復回数、実際の動画の品質はこの UI 変更だけでは改善しない。今回それらを解決済み・高速化済みとはしない。
音声ミュート後は発話の静まりを約3秒待ち、返答処理中は待機する実装。音声終了直後に必ず接続が切れるとは限らない。
