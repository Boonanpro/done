# 提案書作成で学んだ改善パターン

新しいパターンは該当セクションに追記する。古いパターンが矛盾する場合は新しい方を優先。

---

## 確立済みパターン（3回以上の実績で有効性を確認済み）

初版生成時に**必ず全て適用する**。

（まだ確立済みパターンなし）

## 仮説パターン（1-2回有効だったもの。適用を試みるが必須ではない）

確認回数が3回になったら「確立済み」に昇格する。

### H{番号}: パターン名

- **解決策**: 具体的に何をしたら改善したか
- **対象基準**: Q1〜Q5のどれに効くか
- **確認回数**: {N}/3

### H1: ソース鮮度の正確な記載
- **問題**: 「2025年版は8月頃公開予定」と書いたが、実際には2025年6月に公開済みだった。古いデータを使う場合の理由説明も曖昧だった
- **解決策**: ①使用するデータのソースを実際にWeb検索して最新版の有無を確認する ②古い年のデータを使う場合は「最新版には同設問が含まれていないため」等の具体的理由を明記する ③「○月頃公開予定」のような推測は書かない
- **対象基準**: Q5（情報の正確性）
- **確認回数**: 1/3
- **日付**: 2026-03-05

### H2: UIモックアップは実際のUI環境を再現する
- **問題**: ワイヤーフレーム風の抽象的なモックアップでは「何を作るのか」が伝わらなかった
- **解決策**: 実際のアプリケーション環境（Outlook風のリボン・Chrome・ウィンドウ装飾）を再現し、ステップ番号と説明文でユーザーフローを明示する
- **対象基準**: Q3（情報伝達力）
- **確認回数**: 1/3
- **日付**: 2026-03-05

### H3: 実行計画はAI活用・協業前提で書く
- **問題**: 人間が1人で全部やる前提の計画になっていた（旧MVP 3ヶ月）
- **解決策**: 「誰が何をやるか」を明示し、AI（ダン）が担当するタスクにタグを付ける。開発期間もAI活用前提で見積もる
- **対象基準**: Q3（情報伝達力）, Q4（実現可能性）
- **確認回数**: 1/3
- **日付**: 2026-03-05

### H4: MVP期間は1ヶ月以内を基準にする
- **問題**: MVP 3ヶ月の見積もりが「長すぎる」とフィードバックされた
- **解決策**: AI活用前提で1ヶ月（4週間）以内に収める計画を立てる。それでも足りない場合のみ理由を明記して延長
- **対象基準**: Q4（実現可能性）
- **確認回数**: 1/3
- **日付**: 2026-03-05

### H5: サービス名を大きく目立たせる
- **問題**: タイトル「返信を確実にもらう。」が先に来て、サービス名「ReplyGuard」が埋もれていた
- **解決策**: ヒーローセクションでサービス名を最も大きいフォント（48px+）で表示し、キャッチコピーはその下に配置する
- **対象基準**: Q2（ビジュアルデザイン）
- **確認回数**: 1/3
- **日付**: 2026-03-06

### H6: 導入フロー（オンボーディング）を明示する
- **問題**: プロダクトのモックアップはあったが「どうやって使い始めるのか」が不明だった。前提知識のない人に伝わらない
- **解決策**: インストール→認証→設定→使用開始のステップを図解で示す。各ステップの所要時間・難易度も明記
- **対象基準**: Q3（情報伝達力）
- **確認回数**: 1/3
- **日付**: 2026-03-06

### H7: ダンの担当範囲は最大化する
- **問題**: OAuth認証設定やGraph API設計を「みきさん担当」にしていたが、ダンが実行可能なタスクだった
- **解決策**: 「物理的に人間が必要」（本人確認・生体認証等）以外は全てダン担当にする。みきさんは最終判断・承認のみ
- **対象基準**: Q4（実現可能性）
- **確認回数**: 1/3
- **日付**: 2026-03-06

### H8: オンボーディングフローは実際の画面モックアップで示す
- **問題**: 導入フローをテキスト+アイコンのカードで構成したが、「サボり」と指摘された。何を操作するか具体的に伝わらない
- **解決策**: AppSource検索画面、OAuth認証画面、設定画面、Ready状態のOutlook画面の4つを、CSSモックアップで実際の画面として再現する。テキストとアイコンだけの説明カードは禁止
- **対象基準**: Q3（情報伝達力）
- **確認回数**: 1/3
- **日付**: 2026-03-06

### H9: 導入後の体験（運用時の挙動）を可視化する
- **問題**: 「使い始めるまで」のフローだけで、「使った後に何が起こるか」が欠落していた
- **解決策**: メール送信→待機中→AI自動リマインド送信の時系列フローを、3画面のモックアップで可視化する。ユーザーが操作しなくても自動で動く挙動を具体的に見せる
- **対象基準**: Q3（情報伝達力）
- **確認回数**: 1/3
- **日付**: 2026-03-06
