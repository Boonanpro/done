# 提案書作成（自己評価ループ内蔵）

このアクションは「生成→評価→改善」のループをスキル内で閉じる。
人間は「作って」と言うだけ。品質が基準を満たすまでダンが自律的に改善する。

---

## 手順

### Step 1: 学習パターンの読み込み

1. `learned.md` を読む
2. **確立済みパターン**を全てリストアップする（これらは初版生成時に必ず適用する）
3. **仮説パターン**も参照し、該当しそうなものは適用を試みる

### Step 2: 要件の整理

1. ユーザーの要件を以下の観点で整理する:
   - **誰に向けた提案か**（業界・役職・関心事）
   - **何を提案するか**（1文で核心を定義）
   - **相手に何をしてほしいか**（承認・検討・予算確保等）
2. 不明点があればユーザーに確認する（ここだけ人間の介入が入る）

### Step 3: HTML生成（初版）

1. SKILL.md のデザイン原則に従う
2. Step 1 で読み込んだ確立済みパターンを全て反映する
3. criteria.md の Q1-Q5 を意識して、初版から高スコアを狙う
4. `D:/dan-workspace/proposals/{project-name}-proposal.html` に保存

### Step 4: 自己評価ループ（最大3回）

以下を最大3回繰り返す。1回目は必ず実行する。

#### 4a. 視覚確認

- browser ツールで生成したHTMLファイルを開く
- スクリーンショットを取得する（テキストだけの自己評価より視覚評価の方が正確）

#### 4b. 必須基準チェック（criteria.md M1-M5）

- M1-M5を1つずつ確認する
- **1つでもFailなら即修正**して4aに戻る（品質スコアの前に必須を通す）

#### 4c. 品質スコアリング（criteria.md Q1-Q5）

以下のルールで採点する（criteria.md の評価ルールに従う）:

1. **根拠→スコアの順**で書く。先にスコアを決めない
2. スクリーンショットを見ながら「HTMLのどの部分がどうなっているか」を具体的に述べる
3. 迷ったら低い方のスコアをつける
4. 「この評価で見落としている点はないか？」を最後に自問する（メタ認知チェック）

#### 4d. 合否判定

- **合格条件**: M1-M5全Pass + Q1-Q5平均3.5以上 + スコア2以下が0個
- **合格** → Step 5 へ
- **不合格** → 4e へ

#### 4e. 改善

1. 最もスコアが低い項目を特定する
2. その項目のcriteria.mdのスコア表を見て、現在のスコアから+1するには何が必要かを確認する
3. 具体的な修正内容を決定する
4. HTMLを修正して保存する
5. → 4a に戻る（再度スクリーンショットから評価）

#### ループ上限に達した場合（3回改善しても不合格）

- その時点のスコアと改善履歴をユーザーに報告する
- 「これ以上の改善には追加情報が必要です」と伝える
- 現時点のHTMLは出力する（破棄しない）

### Step 5: 合格HTMLの出力

1. チャットに以下の形式で埋め込む:

````
```proposal
{ファイル名}.html
```
````

2. 最終スコアを簡潔に報告する（例: Q1:4 Q2:5 Q3:3 Q4:4 Q5:4 = 平均4.0）

### Step 6: 学習パターンの記録

改善ループで修正を行った場合:

1. `learned.md` を読む
2. 改善で効いた修正を**仮説パターン**として追記する:

```markdown
### H{番号}: パターン名
- **問題**: どんな品質問題が起きたか
- **解決策**: 具体的に何をしたら改善したか
- **対象基準**: Q1〜Q5のどれに効いたか
- **日付**: YYYY-MM-DD
```

3. 既存の仮説パターンと同じ内容なら、確認回数を+1する
4. 確認回数が3回以上になった仮説は**確立済みパターン**に昇格させる

### Step 7: 人間フィードバックの記録（出力後にフィードバックがあった場合）

ユーザーが出力後に改善指示・感想を言った場合:

1. `learned.md` の「人間フィードバック履歴」に記録する:

```markdown
- **F{番号}**: {日付} 「{ユーザーの発言要約}」 → {対応: 仮説パターン化 or criteria.md更新提案}
```

2. フィードバック内容が繰り返し発生するパターンなら**仮説パターン**に昇格する
3. フィードバックが criteria.md に含まれていない新しい基準を示唆している場合:
   - 「criteria.md に以下の基準を追加することを提案します: ...」とユーザーに伝える
   - ユーザーが同意したら criteria.md を更新する

## フロー図

```
learned.md 読む → 要件整理 → HTML初版生成
                                  ↓
                          ┌─ 視覚確認(screenshot)
                          │   ↓
                 ループ    │  M1-M5 チェック → Fail → 修正 → ↑
                (最大3回)  │   ↓ Pass
                          │  Q1-Q5 採点 + メタ認知チェック
                          │   ↓
                          │  合格? ─ No → 最低項目を改善 → ↑
                          └── Yes
                                  ↓
                          HTML出力 + スコア報告
                                  ↓
                          learned.md に改善パターン記録
                                  ↓
                          (人間のフィードバックがあれば記録)
```
