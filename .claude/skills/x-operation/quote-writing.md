# 引用を書く・直す

引用（他の人の記事・ポストへの引用と、本人が自分の記事を後から引用するセルフ引用）を書く時に読む。

## 前提

引用ポストで受け手が触れる物は、添付があるかどうかで変わるので、目的も2つに分かれる。

- **テキストのみ**: 受け手が触れる物は、本文と下の引用元の札だけ。本文で「自分向けの話だ」と思わせ、答えは伏せて、札をタップさせる。
- **画像・動画付き**: 受け手はまず添付をタップ・再生する。添付そのものに、その場で使える要点を入れて言い切り、保存させる。引用元の札は、要点の先を知りたい人の行き先として添える。答えを伏せることにこだわらない。

伸びやすさは「通常ポスト < 引用 < 記事への引用 < 記事への動画付き引用」（X顧問 Notion 第6章、メモ `D:\dan-workspace\x_komon_videos\notes_roadmap_ch6_quote.md`）。合格ラインは記事と同じ（表示3万以上・保存4/1000）。実例は [examples/quotes/index.md](examples/quotes/index.md)（テキストのみ合格7本・画像動画付き合格3本、2026-10-16）。

書く前に、どちらで出すかを決める。記事の中に見せられる画面・動き・図があるなら、画像・動画付きを先に考える。

## テキストのみの技

### T1. 読む人の困りごとと、読んだ後に変わる大きさを言い切る
- 何を：読む人の今の困りごとを一言と、記事を読むとそれがどれだけ変わるか（期間・金額・回数・不安が消える）。
- どこに：本文の全部（1〜3行）。
- どういう形で：「〇〇な人、これ読めば〜」「この記事が分かったら〜」の形で大きさを言い切る。記事の手順・結論・答えの数字は書かない。
- なぜ効くか：自分の困りごとが大きく変わると言われると、どう変わるのかを確かめたくなって札をタップするか、後で読むために保存する。
- 良い例：「引っ越しで初期費用に震えてる人、これ読んでから不動産屋行くだけで数十万変わる」（初期費用を下げる交渉の記事に）
- 悪い例：「仲介手数料は半額にできるし、鍵交換は断れる」（交渉の答えを書いている）
- 出どころ：examples/quotes/index.md T1（116万・6.50）、T2（74万・4.38）、T5（10.7万・10.58）

### T2. 書き手が驚いた理由を、本物・量・珍しさで言う
- 何を：書き手が記事を見て驚いた理由。本物であること（誰の実例か）、量（何が何個入っているか）、珍しさのどれか。
- どこに：本文の全部（1〜3行）。驚きの一言から始めてよい。
- どういう形で：量を言う時は、入っている物の名前を並べるだけにし、その中身は書かない（例「指示書・フォルダ・作業手順・確認役・検査が全部入ってる」）。
- なぜ効くか：書き手が驚くほどの物があると分かると、何に驚いたのかを自分の目で確かめたくなる。
- 良い例：「見積書の項目ごとに断り方が全部書いてあって、ここまで具体的なの初めて見た」
- 悪い例：「見積書は仲介手数料と鍵交換の2か所を見るのがコツ」（驚いた理由でなく答えを書いている）
- 出どころ：examples/quotes/index.md T3（22万・7.07）、T4（13万・11.01）、T6（4.3万・5.41）、T7（3.3万・4.20）

### T3. 引用元の答えと、引用元の中だけの言葉を消す
- 何を：書いた本文から、引用元の結論・手順・答えの数字に当たる語と、引用元の中で作られた言葉（造語・章の名前）。
- どこに：書き終えた本文。
- どういう形で：該当する語に線を引いて消し、造語は引用元を読んでいない人にも通じる言い方に置き換える。他人の記事なら、引用するアカウント自身の立場からの一言を残す。
- なぜ効くか：答えが本文で分かると札をタップする理由がなくなり、引用元の中だけの言葉は自分に関係ある話かを判断できずに流される。
- 良い例：「毎月なぜか3万円消えてる人、どこから削ればいいかこの記事で分かります。僕は2つ目で月1.2万浮きました」
- 悪い例：「固定費は通信費と保険から削れ」
- 出どころ：本人の指摘 2026-10-15（sources/generalization-log.md）

## 画像・動画付きの技

### M1. 添付は、記事の要点を場面ごとに言い切る30〜60秒の動画にする
- 何を：記事の要点を4〜7場面に分けた動画。
- どこに：引用ポストの添付に1本。
- どういう形で：各場面は実際の画面（道具の画面・表・資料・作業の様子）を大きく映し、下に要点を1行で言い切る字幕を置く（「〜すると〜が分かる」「最初に〜を外す」）。最後の1場面に記事の題名と「続きは記事で」を置く。素材は記事で使った画面・動画、記事が扱った元動画の切り出し（`scripts/clip_scene.py`）、道具を動かした画面の録画から選ぶ。
- なぜ効くか：見た人がその場で使える要点を持ち帰れるので保存し、要点の先（使い分け・細部）を知りたい人は最後の場面から札をタップする。
- 良い例：「賃貸の初期費用を下げる交渉」の記事に、「仲介手数料の欄を見る」「鍵交換は断れる」など5場面を実際の見積書の画面と1行の字幕で見せ、最後に「交渉の言い方は記事で」と置いた45秒の動画。
- 悪い例：同じ記事に、不動産屋の店先を映しただけの動画や、記事の表紙の画像を1枚付ける（見ても持ち帰る物が無い）。
- 出どころ：examples/quotes/index.md M1（9.7万・9.32）、M2（9.6万・8.73）、惜しいの 2106284486581465498（2.7万・9.83）

### M2. 本文は、添付を見ると何が分かるかか、保存した後の使い道を書く
- 何を：添付を見ると何が分かるか、または保存した後に何に使えるか（「〜に渡すと再現できる」「〜の時に見返す」）。
- どこに：本文（1〜3行）。添付への驚きの一言を前に付けてよい。
- どういう形で：添付の中身を本文で繰り返さない。使い道は、読む人が実際にする行動の形で書く。
- なぜ効くか：添付を後でもう一度使う場面が分かると、その場で見るだけでなく保存する。
- 良い例：「引っ越し前の人、見積書もらったらこの動画と見比べて」
- 悪い例：「仲介手数料・鍵交換・保証会社の3つで20万円下がりました」（動画の中身を文字で繰り返している）
- 出どころ：examples/quotes/index.md M3（3.3万・8.28）、惜しいの 2108377888080937221（1.6万・14.23）、2110636326970331407（7,617・10.24）

### M3. 届く数だけを狙う時は、人物が動く生の場面を使い、保存は狙わない
- 何を：記事で扱った人物が作業している・話している生の場面。
- どこに：添付に1本（2〜3分でもよい）。本文はその場面への反応1〜2行。
- どういう形で：M1 の要点の字幕は入れない。記事の章番号や章題を画面の端に入れると、記事のどこの場面かが伝わる。
- なぜ効くか：人が動いている場面はタイムラインで止まって再生されるので遠くまで届くが、持ち帰る要点が無いので保存はされにくい。合格ライン（保存）を狙う時は M1 を選ぶ。
- 良い例：記事の主人公が複数のPCで作業している場面に「いや、これエグい」と反応を付ける（表示を広げたい2本目以降に）。
- 悪い例：保存を狙う1本目に、この型を使う。
- 出どころ：examples/quotes/index.md 惜しいの 2109813061460910173（147万・2.99）、2097691834386718767（111万・0.51）、2094376893084766405（8.6万・1.79）

## 試してよいこと（実例2本ずつ・保留）

- セルフ引用の1本目は、記事の当日か翌日に出す。
- 1本目が伸びたら、同じ記事の別の場面で2本目を出す。同じ添付・同じ文は繰り返さない。

（同じ記事に当日と翌日に別の場面で出した例：@ai_ai_ailover 2109606194142912689（M3）と 2109813061460910173、@MakeAI_CEO 2109263809638789213 と 2109113243751092385。結果が分かったら技に上げるか消す）

## 確認表（書き終えた引用で目で確かめる）

テキストのみ
- [ ] 本文が1〜3行で、困りごとと変わる大きさ（T1）か、驚いた理由（T2）になっている
- [ ] 引用元の結論・手順・答えの数字と、引用元の中だけの言葉が残っていない

画像・動画付き
- [ ] 添付を再生すると、記事の要点が場面ごとに1行で言い切られている（M3 を選んだ時を除く）
- [ ] 添付の最後に記事の題名と「続きは記事で」がある
- [ ] 本文が、添付を見ると何が分かるかか使い道で、添付の中身を繰り返していない

共通
- [ ] 主張や数字を書いたなら、添付か引用元でそれが確かめられる（SKILL.md の共通の設定）
- [ ] 一人称は「僕」

## 運用室での形

- 引用の原稿は運用室の「引用候補を追加」で作る。添付の動画・画像は attach_image で保存し、本文の最後に `![説明](/api/v1/files/〜.mp4)` の1行で置く（運用室はその行を動画・画像として表示する）。Xに出す時はその行を添付にして、文からは外す。
- 引用はAPIで送れない（Enterprise 契約が要る）。ダンは引用を投稿しない（ブラウザで x.com を自動操作して投稿すると、シャドウバンや凍結のおそれがある）。本人が運用室の「投稿する」から、添付を端末に保存し、「Xの投稿画面を開く」で開いたXの画面で添付を付けて「ポストする」を押す。戻ると運用室がXの投稿を探して原稿に結びつける（見つからない時は「投稿したので記録する」）。添付が投稿画面に入らないなどの不便は、自動投稿に切り替えて解かずに本人に選択肢として出す。
- Xへの送信は本人の承認の後だけ（SKILL.md の送信の項）。
