# やったことは4つだけだった
【画像2: 縦長の図解「Claude Code セットアップ 4ステップ」。①フォルダ構造をつくる ②CLAUDE.mdを書く（最重要）③MCPで外部ツールと接続 ④Skillsで繰り返し業務をコマンド化 → 自律的に動くAIスタッフの完成。濃紺背景・色分けした枠】 https://pbs.twimg.com/media/HDb9DXDaMAAA45M?format=jpg&name=large
振り返ってみると、やったことは驚くほどシンプルでした。
1. **フォルダ構造を作る**
2. **CLAUDE.mdを書く**
3. **MCPで外部ツールと接続する**
4. **Skillsで繰り返し業務をコマンド化する**
順番に書きます。
## １．フォルダ構造を作る
最初にやったのは「AIの作業場所」を決めることでした。
**ai-management/ **というフォルダを1つ作って、その中にこういうフォルダを用意しました。
**・output/（AIが作ったファイルの置き場）
・reference/（AIに読ませたい参照資料）
・clients/（顧問先ごとのフォルダ）
・tools/（自動化スクリプト）
・work-log/（業務ログ）**
なぜこれが大事かというと、AIは「ファイルをどこに保存すればいいか」が分からないと、デスクトップやダウンロードフォルダにファイルを散らかすんです。
人間のスタッフに「この書類はここに入れて」と伝えるのと同じ。
作業場所を決めるだけで、AIの出力が一気に整理されます。
## ２．CLAUDE.mdを書く
これが最も重要なステップです。
CLAUDE.mdというファイルを1つ作る。これだけです。
これは何かというと、AIへの「業務マニュアル」です。
新しいスタッフが入社した時に「うちの事務所ではこうやって仕事してね」と伝えるマニュアル。それをテキストファイルとして書くだけ。
僕のCLAUDE.mdの最初の3行は、これだけでした。
**「あなたはAI税理士事務所のアシスタントです。 ファイルはai-management/配下に保存してください。 判断に迷ったら必ず確認してください。」**
これだけで動き始めました。
「え、これだけ？」と思うかもしれません。でも本当にこれだけです。
そこから実務をやりながら、1つずつルールを足していきました。
「飲食代で1万円以下は会議費にして」
「海外SaaSの支払いは通信費で処理して」 
「源泉徴収の計算は必ず確認してから処理して」
つまり、最初から完璧なマニュアルを作る必要はない。3行から始めて、実務をやりながら育てていく。人間のスタッフを教育するのと全く同じです。
ここで大事なのは「何を書くか」は4つだけ、ということ。
**・あなた（AI）の役割は何か
・やっていいこと、ダメなこと
・迷ったら誰に聞くか（＝人間に確認する基準）
・出力はどこに保存するか**
この4つを書いておけば、AIは驚くほど的確に動いてくれます。
公式ドキュメントはここにあります。日本語もあるので読みやすいです。 
[Anthropic公式ドキュメント](https://docs.anthropic.com/ja/docs/claude-code)
## ３．MCPで外部ツールと接続する
Claude Codeは単体でも優秀です。でも、外部ツールと繋いだ瞬間に「次元が変わる」という表現が一番近い。
僕が繋いだのはこのあたりです。
**・freee（会計ソフト。仕訳登録の自動化） 
・Googleカレンダー（スケジュール管理）
・Notion（議事録、タスク管理）
・Slack（チーム連絡）
・Gmail（メール処理）**
1つのツールにつき、接続にかかった時間は15分くらいでした。
ここで正直に書くと、昨日の記事の引用RTに「弥生会計でも同じことをやりたい」「せめて弥生がAPI周りを解放してくれたら」という声がありました。
これは本当にそうで、僕がここまでの自動化を実現できているのは、freeeがAPIを公開しているからです。
freeeのAPIがあるからこそ、Claude Codeから直接、取引明細の取得も、仕訳の登録も、勘定科目の判定もできる。
会計ソフトのAPI対応状況は、今後この分野の自動化を考える上で、かなり重要な選定基準になると思っています。
## ４．Skillsで繰り返し業務をコマンド化する
最後のステップが「スキル」です。
スキルというのは、よく使う業務を短いコマンドで呼び出せるようにする仕組みです。
僕の事務所では、例えばこんなスキルが動いています。
**・「おはよう」と打つ → 今日の予定と工程表が自動生成される
・「覚えておいて」と打つ → 会話の内容がメモリに保存される
・「経理」と打つ → 60社の仕訳が自動処理される**
朝パソコンを開いて「おはよう」と打つだけで、今日やるべきことが一覧で出てくる。
これは人間のスタッフに「おはよう、今日の予定教えて」と言うのと全く同じ感覚です。
ここまでやって、かかった時間
正直に書きます。
フォルダ構造を作るのに30分。CLAUDE.mdの最初の3行を書くのに10分。MCPの接続に1日。Skillsの設定に半日。
合計で2日くらいです。
ただし「2日で昨日の記事のレベルになれるか」と言うと、それは違います。
2日で「動く状態」にはなります。でも「60社の仕訳を自動で処理できるレベル」にするには、そこから2ヶ月かかりました。
その2ヶ月で何をしたかというと、CLAUDE.mdを育てたんです。
実務で出てくるケースを1つずつ教えていった。
「この取引先は交際費じゃなくて広告費」
「前受金が入った時はこう処理して」
「インボイス番号がない取引は確認して」
これは、新人スタッフを2ヶ月かけて育てたのと全く同じことです。
昨日の反応を見て思ったこと
昨日の記事には「すごい」「真似したい」という反応をたくさんいただきました。
同時に、同業の公認会計士の方から「結構慎重に人間チェックを入れてるんだな」というコメントもいただきました。
その通りです。
AIに任せる部分と、人間が判断する部分の線引き。これが一番難しくて、一番価値がある部分だと思っています。
CLAUDE.mdに「こういう時は必ず確認して」と書くことは簡単です。でも「何を確認させるか」を決めるには、実務の判断力が必要です。
フォルダ構造もスキルも、僕の実務を棚卸しした結果として出来上がったものです。
同じCLAUDE.mdを渡しても、60社の実務経験がなければ、同じ結果にはならない。
仕組みを全部公開しても、同じ結果が出ないのはそういうことです。
AIは手段。差がつくのは、実務の解像度です。

# これから始める人へ
最後に、これから始める人に1つだけ伝えたいことがあります。
完璧を目指さないでください。
CLAUDE.mdは3行でいい。フォルダは3つでいい。MCPは1つだけ繋げばいい。
「おはよう」って打ったらAIが返事してくれる。それだけで、仕事の風景が変わります。
僕も最初はそこからでした。
Claude Codeに「セットアップを手伝って」と言えば、一緒にやってくれます。非エンジニアの僕が出来たんだから、あなたにも出来ます。
**もし分からないことがあれば、気軽にリプ・DMで聞いてください。**📮📧
