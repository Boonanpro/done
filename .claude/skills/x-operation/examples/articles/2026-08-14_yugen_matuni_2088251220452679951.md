私は業務ドキュメントの多くをClaude CodeやCodexといったAIエージェントに書かせています。内容はおおむね正確です。それでも、日本語がどこか変なのです。
たとえばこんな表現が出てきます。
- 効果の中身を書かずに「効く」の一語で済ませる
- 頼んでいない対比で「AではなくB」と否定から入る
- 主語や助詞が抜けていて、誰が何をするのか読めない
- 「〜ます。〜ます。〜ます。」と同じ文末が続いて単調になる

# システムプロンプトに書いても直らない
最初は、見つけるたびに手で直していました。次に、システムプロンプトやCLAUDE.mdのような規約ファイルへ「この表現は使わない」と書き並べました。それでも同じ表現が頻発します。
会話が長くなると指示は薄まる一方です。しかも、モデルが変われば癖の出方も変わります。そのうえ、注意書きを増やすほど、今度は別の場所で別の癖が出てきます。人間の目視だけでは、もう追いつきませんでした。

# 書いた直後に検査して、書き直させる
そこで、書かせる前の注意と併せて、書いた後の機械検査を入れました。使うのは、Claude CodeなどのAIコーディングツールが備えるHooks（フック）という機能です。エージェントの動作の節目に自作のスクリプトを差し込める仕組みで、ファイル編集の直後に発火するものはPostToolUseと呼ばれます。
流れは次のとおりです。
1. エージェントがファイルを書き込むと、直後にHookが動き、そのファイルをNGワードのルール（正規表現による文字列照合）と突き合わせます。
2. 該当があれば「該当文を丸ごと書き直すこと」という警告が、エージェント自身へ返ります。処理を止めずに直させる点が特徴です。
3. 警告を受けたエージェントが文を書き直すと、その書き込みへもう一度検査がかかります。
4. セッション終了時にも全体を再検査します。重大な違反が残っている場合、エージェントはそのまま作業を終えられず、該当文を書き直すまで完了報告できません。
こだわった点ですが、語のみ置き換えは禁止しています。NGワードだけを別の語へ差し替えると、同じ問題が別の語形で残り、文章が破綻するからです。だから警告文は「検出箇所を含む文を丸ごと書き直す」ことを求める文面にしました。

# ルールは指摘のたびに増やす
ルールは、この記事を書いている時点で500本を超えました。一度にまとめて作ったものではありません。
私がエージェントの日本語へ指摘を入れるたび、その場で少しづつ増えていきました。指摘をルールへ登録するSkill（エージェントへ手順を教える仕組み）を作ってあるので、私が指摘すると半ば勝手に登録されていきます。加えて、週に1回ほど、会話履歴をエージェント自身に分析させて、繰り返し直している表現をまとめて登録しています。
【画像2: 図3「私の指摘がルールへ変わり、次からは機械が指摘する」。私が指摘する→ルールへ登録→機械が指摘する、の3つの箱と、週1回会話履歴からまとめて追加する戻り矢印】 https://pbs.twimg.com/media/HPrlDxra0AAkP2K?format=jpg&name=medium
(キャプション: 私の指摘がルールへ変わり、次からは機械が指摘する)
検出カウントを集計すると、上位に来るのは「効く」と、「AではなくB」のような対比構文でした。モデルや会話が違っても、LLMの日本語には共通の癖があります。

# グッドパターンもセットで読ませる
もう1つこだわった点は、エラー検出だけで終わらせない設計です。
NGワードのルールには、1つずつ「こう書き直す」というグッドパターンを持たせました。500個すべてが対になるグッドパターンを持っていて、検出時の警告には、引っかかった語と一緒にそのグッドパターンが返ります。たとえば「効く」を検出したら「真価は〜にある」「本領を発揮するのは〜」が返ります。「AではなくB」の対比なら「不要なら肯定形で直接書く」が返ってくるように設計しています。
禁止だけを並べると、エージェントは避け方が分からず、不自然な回避文を書きがちです。グッドパターンを添えるようにしてから、書き直しの精度が上がっています。

(キャプション: 書く前の文体契約と、書いた後のNGワード検査)
シーンごとにルールのオンオフも変えています。たとえば造語（「◯◯メソッド」のような自分で作った言葉）の検査は、ビジネス文書ではオン、小説ではオフです。なぜなら造語は創作では技法だからです。

# 文書全体の集計で見つかる癖もある
単語の照合だけでは拾えない癖は、文書全体の集計で検出します。
- 同じ文末（ます・です・ましたなど）が3文以上続いたら検出する
- です・ます調と常体の混在を、文末の分布を集計して検出する
- 比喩表現が同じ行や同じ文書内に重なったら、重ね使いとして警告する
「ますが連続する」ような単調さは、1文ずつ見ても違反とは言えません。文書全体で文末の種類を数えて、はじめて指摘できます。ここは正規表現の照合とは別に、スクリプトで文末を数えて判定しています。

# 同じ指摘を二度しないために
この検査の仕組みを入れてから、私が日本語を直す回数は目に見えて減りました。とはいえ、ゼロにはなっていません。
それでも、同じ指摘をくり返す場面は減ってきました。指摘した瞬間にルール化すれば、次からは機械が代わりに指摘してくれるからです。
LLMの日本語の癖は、モデルの進化を待たずに、検査と書き直しのループでかなり抑えられます。エージェントに文書を書かせていて同じ悩みがある方は、自分がよく直している表現を書き出すところから始めてみてください。その表現をファイル書き込み直後のHookで照合するだけでも、手直しの回数は変わるはずです。
