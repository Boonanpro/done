# 本人が話す動画の台本

本人（みきさん）がカメラの前で話す動画の台本を書く時と、書いた台本の直しを受ける時に使う。映像の構成や素材の作り方は `video-direction`、文字で読ませる文章は `build/references/copywriting.md`。

状態（2026-10-12）: LINE特典動画の第3稿に本人が85点を付けた段階。細かい直しを受けたら、この手順と型に足す。

## 1. 書く前に「前提と狙い」を決める

台本の先頭の「◎前提と狙い」には、次の3行だけを1行ずつ書く。商品設計シート・その部屋の会話から埋め、それでも決まらない時だけ本人に聞く。

- 見る人：誰が、どこから来て、何を済ませた状態で見るか（例：LINE特典を見て、ローンチのLINEに移った人）
- 売り方とこの動画の場所：[売り方のパターン](sales-patterns.md) の名前と何本目か（例：審査制ローンチの1本目）
- 見た後にしてもらうこと：1つだけ

この動画で何を話し、何を言わないか（金額、次の動画に残す悩み、済んでいる行動の呼びかけなど）は、売り方のパターンのその段階の欄で決め、作業メモに写して守る。台本には書かない。売り方が決まっていない時は、パターンから一番近い物を選び、本人に1文で確かめてから書く。

書き終えたら、冒頭・締め・各段の最後の文を、3行とその段階の欄に照らして読み直す。

### 前提に同じ主張が何度も書かれていたら、主張ごとにまとめて本編では1回ずつ言う
- 何を：本人が書いた前提（「壊す常識」「伝えたいこと」など、本人の思いを書いた欄）
- どこに：本編を書き始める前
- どういう形で：①前提の文を1文ずつ「何を主張しているか」で仕分け、言い方が違っても同じ主張の文は同じ組にする ②組ごとに、主張を1文で言い切った見出しを付け、その下に本人の文を理由・例・言い方の候補として並べる。本人にしか言えない場面と振り切った言い方は、組の下に一字も変えずに残す（3の「本人の言葉を残し、平均的な言い方に寄せない」）③組ごとに、本編のどの段でその主張を言うかを1つ決め、組の見出しの横に書く（「→ ▼常識を壊す で言う」）④本編を書き終えたら、組ごとに本編を探し、2つ以上の段で同じ主張を言っていないかを確かめる。型が決めている結論の言い直しだけは2回目を残す
- なぜ効くか：見る人は同じ主張を言い方を変えて何度も聞かされると「さっき聞いた」と感じて離れる。主張の数が数えられる形になると、それぞれを一番効く段で1回だけ言える
- 良い例：筋トレの前提に「サプリより食事が大事」「プロテインに頼るな」「体は食べた物で9割決まる」「粉に金を使うなら肉を買え」と4回あった → 1つの組「サプリより、毎日の食事で体は変わる」にまとめ、「粉に金を使うなら肉を買え」を言い方の候補に残し、本編の「▼よくある間違い」でだけ言う
- 悪い例：4つの文をそれぞれ冒頭・本編・締めに1つずつ散らして、全部言う
- 出どころ：2026-10-29 本人の指摘（スヤさんの台本の「壊す常識」）

実例（2026-10-12 に本人が指摘）：LINE特典動画の締めに「LINEでお待ちしてます」（見る人は登録済み）、「今日をポルノを見た最後の日にしましょう」（後で案内するサービスが要らなくなる）と書いた。締めは、次の案内を楽しみにしてもらう所。

## 2. 型を選ぶ

型は動画の役目ごとに分かれている。役目は「見る人がすでに知っていること」と「見た後にしてほしい行動」で決まり、型のファイルの冒頭に1行ずつ書いてある。

- YouTube動画（検索やおすすめから来た、まだ話し手を知らない人）：[youtube-video.md](references/youtube-video.md)
- LINE特典動画（登録済みで、話し手を知っている人）：[line-gift-video.md](references/line-gift-video.md)
- ローンチ動画（「興味がある」を押して案内専用の LINE に来た人・審査に通った人・前回の応募者）：[launch-video.md](references/launch-video.md)。えるさんの型をそのまま使う。男性向けか女性向けかで替えてよいのは言葉と例えだけで、段の順番・話す中身・喋り方は替えない。届け方と各段階で言わないことは [売り方のパターン](sales-patterns.md) の審査制ローンチ⑤⑦と再募集。エバーグリーンローンチでも同じ型で、期限を一人ずつ付けるだけが違う。えるさんの実際の台本の全文は [launch-scripts/](references/launch-scripts/README.md)（書く前に同じ役目の1本を通して読む）。
- それ以外で型がまだ無い種類：売れている同じ種類の動画を2本以上、字幕（`video` の captions）か台本の文書で読み、共通する話の順番を抜き出す。冒頭に「すでに知っていること」と「見た後の行動」を書いて、本人に見せてから使う。合格したら references に足す。

選んだ型の段だけを使う。書く前に、段ごとに「その段で見る人が何を信じ、何を期待するようになるか」を作業メモで確かめ、それが型の「すでに知っていること」に入っている段は省く。別の型の段を持ってきたくなった時も、同じように照らして、入っていれば入れない（例：LINE特典にYouTubeの「冒頭で昔の失敗と実績」を入れると、見る人がもう信じていることをもう一度言うことになり、④の体験と重なる）。この確かめは台本には書かない（3の「台本に載る言葉は、読む人が普段使う言葉で書く」）。

YouTube動画は、台本の前にサムネとタイトルを決める：[thumbnail.md](thumbnail.md)。

## 3. 言い方

- 本人が実際に話した文に寄せる。「見れる」「〜てました」「ぶっちゃけ」「要は」「なので」。元は固定ポスト動画の字幕 `C:\dan-work\pornblock_retake_20261006\edit_rows.json`。
- 有益さと面白さを優先する。保険をかける言い方をしない（冒頭で「全部は防げません」と言わない）。限界の話は、次の案内につなぐ材料として終盤で使う。
- 誰が何をするかを省かない。「これ」「そこ」は、指している物の名前で書く。ダンのチャット用の決まり（`SOUL.md` の「日本語の書き方」の、たとえを使わない・短い句をぶつ切りにしない）は台本には当てない。
- 期待を上げる所、問いかけ、「今回は話さない」、締めは型なので削らない。
- 経歴や体験は、話を分かりやすくするために足してよい（2026-10-12 本人）。ただし同じ体験は台本の中で1か所だけで話す（どこで話すかは型が決めている）。
- ［ ］で始まる行は撮影・編集の指示で、読まない。
- 書き終えた後と直しを受けた時は、私が書いた文を [rewriting.md](rewriting.md) の技で1文ずつ見直す（弱気な言葉・何も言っていない文・型どおりの共感を消す、など）。

### 本人の言葉を残し、平均的な言い方に寄せない
- 何を：本人が書いた・話した文の中の「本人にしか言えない場面」（時刻・場所・その時の気持ち・具体的な行動）と「振り切った言い方」（誇張、口ぐせ、俗な言葉、自分を落とす言い方）
- どこに：本人の文が入った台本を書く・まとめる・直す時、手を入れる前
- どういう形で：先に印を付け、印の付いた言葉は、まとめても並べ替えても、段をまたいで移しても、一字も変えずに残す。削ってよいのは、同じ内容の2回目と、意味が通らない所だけ。印の付いた文を消す・言い換える時は、変更の理由にその文を「」で引用し、どの文と重なっていたか（または何が通らなかったか）を書く。印の付いた文が、売り方のパターンでその段階が言わないことに触れる、言い切りが強すぎる、と思った時も、消したり自分の言葉に差し替えたりせず、残したまま返事で本人に聞く。本人の体験の言い切りに「〜と感じる」「〜ことがある」を足さない。医療や法律など、全員に当てはまるかが心配な一般論だけは、書き換えずに返事で本人に聞く。本人の文が無い段を新しく書く時は、型の「振り切った言い方」の4つの形（誇張した程度・俗な言葉の慣用句・見る人の心の声の芝居・自分を落とす一言）のどれかで、その段の主張を1文書く
- なぜ効くか：どの発信者でも言える平らな文は聞き流される。本人にしか言えない場面と強い言い方が残っていると、見る人は「この人の話だ」と思い、最後まで見て、信じる
- 良い例：本人の「この負のループを作り出していたのが日々のポルノ視聴習慣でした」「中学生の頃はAVとかに死ぬほど興奮していたのに」をそのまま残し、2回出てくる「勃たなかった」の場面だけを1つにする
- 悪い例：同じ所を「その不安に大きく関わっていたと感じるのが、日々のポルノ視聴習慣です」に変え、「死ぬほど興奮していた」を消す
- 出どころ：2026-10-20 本人の指摘（台本室で②をまとめさせたら平均的な言葉になった）、える・イツキのLINE特典動画2本の言い方

### 台本に載る言葉は、読む人が普段使う言葉で書く
- 何を：台本の見出し・注釈・［ ］の行・前提と狙いの欄の言葉
- どこに：台本を書く時と、書き終えた後の読み直し
- どういう形で：①段の役目の確かめ（その段で見る人が何を信じ、何を期待するようになるか）は作業メモか頭の中でだけ行い、台本には書かない ②見出しは、その段で話す中身か役目を、本人や見本の台本（えるさんの台本の「悩みの言語化」「体験談」など）で実際に使われている言葉で書く ③書き終えたら見出し・注釈・［ ］の行だけを読み直し、英語の直訳に聞こえる言い方（「〜を渡す」「〜を提示する」「提供価値」「解像度」「インサイト」）と私が作った言葉に印を付け、「何を話す」「誰が何をする」の言い方に置き換える。本人が自分で使っている言葉（「常識の破壊」「ベネフィット」など）はそのまま使う
- なぜ効くか：台本を読むのは本人と演者と編集する人。知らない言葉が1つあると、そこで読む手が止まり、台本全体が「AIが書いた物」に見えて信用されなくなる
- 良い例：見出し「▼この動画で作れる物：10分でできる夕飯」「▼よくある失敗：火を強くしすぎる」（演者がそのまま「次は、よくある失敗の話です」と読める）
- 悪い例：段の横に「冒頭　提供価値：時短の期待」「本編　渡す物：やり方」
- 出どころ：2026-10-29 本人の指摘（スヤさんの台本の「渡す物」）

### 台本は話の区切りごとに太字の見出しを置き、大事な文だけを太字にする
- 何を：台本の見た目の区切り
- どこに：台本の文書全体（Googleドキュメント・台本室）
- どういう形で：①大見出しを3つ置く：「◎前提と狙い」「◎タイトルとサムネ」「◎台本」 ②台本の中は、話題か段の役目が変わるごとに（目安4〜15行に1つ）「▼」で始まる見出しを置き、その段の中身を短く言う（「▼悩みの言い当て」「▼昔の失敗：質問を何十個も準備していた」）③見出しの行は太字で本文より大きくする（Googleドキュメントなら大見出しを見出し2、▼を見出し3の書式にする）。章の行や撮影・編集の指示の行（［章：…］［テロップ：…］）も太字にして、本文の中に埋もれさせない ④本文では、言い切りの結論・見た後に起きること・見る人に覚えてほしい1文だけを太字にし、1段に1〜2文までにする ⑤書き終えたら、見出しだけを上から読み、それだけで話の流れが追えるかを確かめる
- なぜ効くか：本人は台本を直す時、どこが何の話かを探しながら読む。見出しが本文と見た目で分かれていると、目的の段に直接飛べ、コメントを付ける場所もすぐ見つかる。撮影中の演者も今どこを話しているかを見失わない
- 良い例：「◎台本」の下に「▼1行目：節約してるのにお金が残らない」「▼この動画を見た後に起きること」「▼昔の失敗：コンビニを我慢していた」「▼家計は3つしかない」と見出しを並べ、本文では「**固定費を1つ見直すだけで、年に8万円残ります。**」の1文だけを太字にする
- 悪い例：数十行を見出しなしで続け、［章：入り口1］も本文と同じ細さの文字で書く
- 出どころ：2026-10-29 本人の指摘（スヤさんの台本）、えるさんの台本3本（`marketing-reference/youtube-producer-l/docs/` の 超添削_ビフォーアフター.docx・第2期_メンタリストえる_1本目の動画・0期_ローンチ1本目に流す動画）

## 4. 置き場所と確かめ方

- 台本は台本室（成果物 `script-room`、https://dan.paina.info/preview/script-room ）に置く。チャットに全文を貼らない。台本室の編集アシスタントはこのスキルと `references` の型を毎回読むので、ここを直すと台本室にも効く。保存の形と取り込み方は `frontend/src/app/artifacts/script-room/WORKFLOW.md`。
- 直しの依頼（台本室で一部を選んだコメント、Googleドキュメントのコメント、会話での指示）を受けたら、直す前に [revision.md](revision.md) を読む。選んだ所だけを直さず、つながる所もそろえる。本人が採るか捨てるかを選ぶ修正案で出す時は、1か所ずつ理由を付ける。
- 台本を直接書き換えた時の返事は、1文目で何を直したかをまとめ、その後は本人が決めることと、頼まれた範囲を超えて変えた所（戻したいかもしれない所）だけを1件1文で書く。段ごとの「〜で変えたところ」は返事にも台本にも書かない（2026-10-29 本人「どうせ読まないのでいらない」）。
- 本人の細かい直しは、台本室の台本ごとの会話で受ける。そこで出た「今後も使う決まり」は台本室の「足したルール」に貯まる。何度も使われる決まりは、頼まれた時にこのスキルへ移す。
- チャットから台本を足す・直す時は、保存の直前に最新の行を読み直す（本人の編集を消さない）。直す前の本文は「前の版」（`script_snapshot`）に残す。
- 画面を見せる手順がある台本は、書いた手順を実機やブラウザで確かめ、項目名を実際の表示に合わせる。画面の画像を該当する行の近くに入れる。確かめられない端末（iPhone はダンから操作できない）は、台本の末尾に「未確認」と書く。
