# modify-and-test: コード変更→テスト手順

## 概要

コード変更からテスト完了までの一気通貫ワークフロー。
変更種類を特定し、適切なテスト方法で動作確認してから報告する。

## 手順

### Step 1: 変更対象の特定

変更がどのカテゴリに該当するか判定する:

- **バックエンドのみ**: APIエンドポイント、サービス層、モデル等
- **フロントエンドのみ**: React コンポーネント、CSS、ページ等
- **スキル定義のみ**: SKILL.md、actions/*.md
- **複合**: 上記の組み合わせ

### Step 2: コードを修正

- 既存のコーディング規約に従う
- 変更は最小限に抑える
- セキュリティ脆弱性を作らない

### Step 3: 変更種類に応じたテスト

#### バックエンドの変更がある場合

1. テスト用バックエンドを起動:
   ```bash
   python scripts/start_test_backend.py
   ```

2. curlで動作確認（例）:
   ```bash
   curl http://127.0.0.1:8001/health
   curl -X GET http://127.0.0.1:8001/api/v1/chat/dan/sessions/active-list \
     -H "Authorization: Bearer <token>"
   ```

3. レスポンスを証拠として提示

4. 作業完了後、テスト用バックエンドを停止:
   ```bash
   # port 8001のプロセスを見つけて停止
   netstat -ano | findstr :8001 | findstr LISTENING
   taskkill //F //PID <PID>
   ```

#### フロントエンドの変更がある場合

1. Next.js の HMR が自動反映するので待機
2. ブラウザで該当ページを開く（browserツール使用）
3. スクリーンショットを撮って証拠を提示

#### スキル定義の変更がある場合

1. SKILL.md の内容を確認（read_file）
2. スキル一覧に表示されることを確認

#### 複合変更の場合

- バックエンド変更 → port 8001で確認
- フロントエンド変更 → ブラウザで確認
- 両方の証拠を提示

### Step 4: 結果報告

テスト結果を証拠付きで報告する:

- curlのレスポンス（ステータスコード + ボディ）
- スクリーンショット
- エラーがあれば詳細と修正内容

**「できました」だけの報告は禁止。必ず証拠を添える。**
