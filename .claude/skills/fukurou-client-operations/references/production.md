# 制作・納品

目標は、顧客の売りたい商品から発信を設計し、本人のチェックを挟んで企画、タイトル・サムネ・台本、撮影、編集、投稿までつなげること。構想と今実行できる機能を区別し、全部自動化済みとは言わない。

既にある商品設計シート、面談記録、サイト、LP、動画、LINEの流れを先に確認する。新たなヒアリングを毎回必須にしない。公開情報や既存素材で埋められる所は埋め、制作上の仮説は本人がチェックできる形にする。金額・契約・実績の事実を仮説で確定しない。

商品設計シートは承認された原本をコピーして記入し、原本を壊さない。企画資料は必要な項目に絞る。動画案は型とタイトルが分かる形にし、面談で見せる必要があるなら参考動画を各案に添える。調査済みのことを質問一覧として相手にやり直させない。

基本のYouTube運用と、追加のLINE構築・ローンチ支援を分けて契約範囲を見る。特定案件の「LINE特典→ローンチ1本目→審査→合格者向け動画」や制作順序を全案件へ強制しない。各案件の目的と承認済みの売り方を守る。

- 台本・タイトル・サムネ：talk-scriptと該当する型を使う。
- 台本修正と納品文書：fukurou-script-handoffを使う。ダンの修正は提案、納品時は内部コメントを残さず、相手が編集できる文書と復元用の控えを用意する。
- 撮影・編集：素材と動画の種類に合う既存スキルを使う。本人が仮動画不要とした案件で勝手に生成しない。
- 投稿・納品：承認された版、相手、媒体、公開範囲を確認する。制作を任されたことだけで投稿・外部送信まで許可されたと解釈しない。

工程が終わるたびに、次に必要な制作・資料・確認を判断して進める。送信案も実際の進み具合に合わせる。「資料ができた」のに「できたら送ります」のままにしない。相手へ必要な作業を依頼する文は結論から書き、共有だけなら余計な依頼を足さない。
