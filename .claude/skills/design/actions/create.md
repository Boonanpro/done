# デザイン成果物の作成（自己評価ループ内蔵）

このアクションは「生成→評価→改善」のループをスキル内で閉じる。
人間は「作って」と言うだけ。品質が基準を満たすまでダンが自律的に改善する。

---

## 手順

### Step 0: 用途の特定

成果物の種類を判定する:
- **A. ダッシュボード/管理画面** → Next.js + shadcn/ui
- **B. クライアントHP/ツール** → Next.js + shadcn/ui + Tailwind
- **C. 提案書HTML** → 自己完結HTML

用途によって適用するcriteria.mdのセクション（A/B/C）が変わる。

### Step 1: 学習パターンの読み込み

1. `learned.md` を読む
2. **用途共通 + 該当用途セクション**の確立済みパターンを全てリストアップする
3. 仮説パターンも参照し、該当しそうなものは適用を試みる

### Step 2: 要件の整理

1. ユーザーの要件を整理する:
   - **何を作るか**（ダッシュボード/HP/提案書/ツール）
   - **誰が使うか**（自分用/クライアント向け/見込客向け）
   - **必要な機能**（KPI表示/フォーム/決済/CTA等）
2. 不明点があればユーザーに確認する
3. **確認は最小限にする**。初回の指示で判断できる範囲は自分で決定し、完成後にフィードバックを受ける。途中で「AとBどちらがいいですか？」のような選択確認は原則しない

### Step 3: クリエイティブディレクション定義（用途Bのみ）

HP制作の場合、コードを書く前に**ビジネスゴールからデザイン方針を逆算**する。SKILL.md Bの「ビジネスゴールからデザインへの因果連鎖」に従い:

1. **ビジネスゴール**: このHPで何を達成したいか
2. **訪問者の行動**: 訪問者に具体的に何をさせたいか（問い合わせ、予約、購入、資料請求…）
3. **訪問者の確信**: その行動をとるために訪問者が確信すべきことは何か（実績がある、美味しそう、価格が妥当…）
4. **必要なコンテンツ**: その確信を生むために見せるべき具体物（写真、数字、事例、地図…）
5. **デザイン方針**: そのコンテンツを最も効果的に見せるデザイン
   - 何が主役か（写真？テキスト？数字？）→ 主役を最も大きく目立たせるレイアウト
   - 配色: SKILL.md Bの4層モデル（Neutral/Primary/Secondary/Accent）に従い仮決定
   - フォント: SKILL.md Bの選定基準テーブルに従い Headline/Body/Label を仮決定
6. 上記をプロジェクトフォルダに **`DESIGN.md`** として保存する

### Step 4: リファレンス収集（用途Bのみ）

Step 3で定義したクリエイティブディレクションに基づいてリファレンスを収集する。SKILL.md B「リファレンス駆動デザインプロセス」Phase 1に従い:

1. ブラウザでDribbble / Pinterest / 実在サイトを検索（**DESIGN.mdの方向性に合うもの**を探す）
2. ヒーロー・タイポグラフィ・配色・インタラクションを別々の参照元から収集
3. 最低3つのスクリーンショットをプロジェクトフォルダに保存
4. SKILL.md Bの方法1/2/3から最適な方法を選択

### Step 5: 初版生成

1. SKILL.md の用途別ルールに従う
2. Step 1 の確立済みパターンを全て反映する
3. **用途BではStep 3のDESIGN.md + Step 4のリファレンスをインプットとして使う**。ゼロからデザインを想像しない
4. criteria.md の該当用途の品質基準を意識して、初版から高スコアを狙う
5. **A/Bの場合はバックエンドファーストで実装する**: DB設計 → API実装 → UI実装の順。UIを先に作らない
6. 用途に応じた場所に保存する:
   - ダッシュボード → `frontend/src/app/dashboard/` 配下
   - クライアントHP → `D:/dan-workspace/hp-projects/` 配下
   - 提案書 → `D:/dan-workspace/proposals/` 配下

### Step 6: 自己評価ループ（最大3回）

以下を最大3回繰り返す。1回目は必ず実行する。

#### 6a. 視覚確認

- browser ツールで成果物を開く（ダッシュボード→localhost:3000、HP→dev server、提案書→HTMLファイル）
- スクリーンショットを取得する

#### 6b. 必須基準チェック（criteria.md の M系基準）

- 該当用途のM系基準を1つずつ確認する
- **1つでもFailなら即修正**して4aに戻る

#### 6c. 機能確認（A/Bのみ。提案書HTMLはスキップ）

1. 作成したAPIエンドポイントにcurlして正常レスポンスを確認する
2. ブラウザで一連の操作（作成→表示→編集→削除等）を実行する
3. ローディング中・エラー時・データ空の3状態が実装されているか確認する
4. サイドバー等の既存UIから辿れるか確認する
5. **動かない機能があれば即修正**して4aに戻る

#### 6d. 品質スコアリング（criteria.md の Q系 + F系基準）

1. **根拠→スコアの順**で書く。先にスコアを決めない
2. スクリーンショットを見ながら具体的に述べる
3. A/Bの場合はF系（機能基準）も採点する
4. 迷ったら低い方のスコアをつける
5. 「この評価で見落としている点はないか？」を最後に自問する

#### 6e. 合否判定

- **合格条件**: M系全Pass + Q系・F系合算で平均3.5以上 + スコア2以下が0個
- **合格** → Step 7 へ
- **不合格** → 6f へ

#### 6f. 改善

1. 最もスコアが低い項目を特定する
2. criteria.md のスコア表で +1 に必要なことを確認する
3. 修正してファイル保存
4. → 6a に戻る

#### ループ上限に達した場合

- その時点のスコアと改善履歴をユーザーに報告する
- 現時点の成果物は出力する（破棄しない）

### Step 7: 出力

用途に応じた方法で出力する:
- ダッシュボード → 「ダッシュボードを更新しました」+ スクリーンショット添付
- クライアントHP → デプロイURL or ローカルプレビューのスクリーンショット
- 提案書 → ```proposal``` ブロックで埋め込み + 最終スコア報告

### Step 8: 学習パターンの記録

改善ループで修正を行った場合:

1. `learned.md` を読む
2. 改善で効いた修正を**該当用途セクション**の仮説パターンとして追記:

```markdown
### H{番号}: パターン名
- **問題**: どんな品質問題が起きたか
- **解決策**: 具体的に何をしたら改善したか
- **対象基準**: 評価基準IDのどれに効いたか
- **確認回数**: 1/3
- **日付**: YYYY-MM-DD
```

3. 既存パターンと同じ内容なら確認回数を+1
4. 3回以上 → 確立済みに昇格
5. 用途をまたいで有効なパターンは「用途共通」セクションにも追記

### Step 9: 人間フィードバックの記録

ユーザーが改善指示・感想を言った場合:

1. `learned.md` の「人間フィードバック履歴」に記録
2. 繰り返し発生するパターンなら仮説パターンに昇格
3. criteria.md に含まれていない新基準を示唆している場合は更新提案

## フロー図

```
用途特定 → learned.md 読む → 要件整理
                                  ↓
                        [用途B] クリエイティブディレクション定義
                                  (感情→メタファー→配色/フォント階層→DESIGN.md)
                                  ↓
                        [用途B] リファレンス収集(DESIGN.mdに基づきDribbble等)
                                  ↓
                              初版生成
                                  ↓
                          ┌─ 視覚確認(screenshot)
                          │   ↓
                 ループ   │  M系チェック(AI感脱却含む) → Fail → 修正 → ↑
                (最大3回) │   ↓ Pass
                          │  Q系採点 + メタ認知チェック
                          │   ↓
                          │  合格? ─ No → 最低項目を改善 → ↑
                          └── Yes
                                  ↓
                          成果物出力 + スコア報告
                                  ↓
                          learned.md に改善パターン記録
                                  ↓
                          (人間FBがあれば記録)
```
