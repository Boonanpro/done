# Instagram DM 送受信

## ⚠️ 手順0: 文面は compose_message で送信案カードにする

DM の文面は `compose_message(action="propose", channel="instagram_dm", to="<相手ユーザーネーム>", body=..., intent=...)` で出す。
チャット本文に文面を書いて「これで良ければ送ります」と聞かない。ユーザーはカード上で本文を直せる。

`from_account="<送信元アカウント>"` を必ず渡す。受信DMへの返信なら受信通知の `thread_id` を `reply_to_thread_id` に渡す。

送信はカードの送信ボタン、またはユーザーが「送って」と言ったら `compose_message(action="send", proposal_id=...)`。
サーバーが巡回用プロファイル（ログイン済み）から内部APIで送り、台帳記録（返信照合）も自動で行う。
**サーバー送信がログイン失敗等でエラーになった時だけ**、下記の手順で `browser` から送り、
`compose_message(action="mark_sent", proposal_id=...)` で記録する（本文は `list` で取り直した DB の現在版）。

## 重要: 送ったら必ず記録する

DMを送った**直後に必ず**これを実行する:

```bash
python scripts/dan_record_ig_dm.py --account <アカウント> --to <相手のユーザーネーム> --note "<何の用件か>"
```

`--room` は環境変数 `DAN_ROOM_ID` から自動で入る（今のチャットルーム）。

**記録しないと何が起きるか**: 相手から返信が来ても検知されない。
巡回ポーラーは「送信実績のあるアカウント」しか見に行かないし、返信が来ても
どのルームの用件か分からないので通知タブ止まりになる。記録して初めて
「返信 → このルームでダンが起動して報告・返信案」が成立する。

## 送信のやり方

`browser` ツールで通常どおり操作する。セレクタは焼き込まず、`get_interactive_elements()`
でライブDOMを読んで進める（その場限りの操作なので事前調査は不要）。

1. `https://www.instagram.com/direct/inbox/` を開く
2. 既存スレッドがあればそれを開く / 無ければ新規作成で相手を検索
3. 本文を入力して送信
4. **上記の記録コマンドを実行する**

## 送信後その2: 返信期限の見張りを登録する（必須手順）

台帳記録に続けて、**必ず** watch で「返信が来ない場合」の見張りを登録する:

```
watch(action="create", at="<返信を待つ期限。DMの目安は2〜3日後>",
      note="<相手ユーザーネーム> へのDM（<用件>）に返信が来たか台帳を確認。来ていなければ追いDM文案を作ってユーザーに提案する。返信済みならこの確認は不要と一言で終える。")
```

- ユーザーが「催促不要」と言った場合は登録しない
- ⚠️ 返信が来たことの検知は下記ポーラーが自動で行う。watchの役割は「来ない場合」の催促だけ（二重検知にしない）。

## 受信（自動・ダンは何もしなくてよい）

`app/services/instagram_poller.py` が既定60分間隔（ゆらぎ付き）で巡回する。

- 台帳に相手の記録がある → **その案件ルームでダンが自動起動**し、進展の報告と
  次アクションを提案する（メール着信と同じ扱い）
- 記録が無い相手からの新規DM → 通知タブに出る

案件が特定できた相手のスレッドは開いて会話の流れごと読む（ダンが文脈込みで報告できる）。
知らない相手は受信箱一覧のプレビューのみ。

## ログイン（自動・人手不要）

`ensure_logged_in()` が自力でログインする。認証情報DB + 2captcha + メールOTP。
Instagram はログイン時に reCAPTCHA（enterprise）を挟むが、`solve_page_captchas`
で自動突破できることを実測済み（2026-08-07）。

ログイン結果はプロファイルに永続するので、毎回ログインするわけではない。
自力で駄目だった時だけ通知タブで助けを求める。手動フォールバック:

```bash
python scripts/ig_login_once.py <アカウント>
```

## 環境変数

- `DAN_IG_POLL_INTERVAL`（既定 3600 秒＝60分）— 短くすると凍結リスクが上がる
- `DAN_IG_POLLER_ENABLED`（既定 true）
