以下は、優れたSaaS/プロダクト動画の共通パターンを抽出した、動画制作のためのガイドラインです。
参考動画: Base44 Superagents, Slack, Grammarly, Airtable, Canva, Claude for Word

---

## 1. 物語構造のパターン

良い提案動画は機能の羅列ではなく、1つのタスクを最初から完了まで追う物語になっている。

**構造:**

1. **フック (5秒以内)** — 最初の数秒で「この動画は何について？」を伝える
   - 例(Claude for Word): Wordのトグルスイッチがオンになる→「Claude now works alongside you in Word」。3秒で製品の位置づけが分かる
   - 例(Slack): 創業者が「Slackのビデオ作ってよ」→Adamが「メールで十分だろ」。1往復で文脈が分かる
   - 例(Grammarly): いきなりテキスト入力が始まり赤い下線が出る

2. **アクセス手順（そのツールにどうやって辿り着くかを見せる）** — ツールの「居場所」を明確にする
   - 例(Claude for Word): macのデスクトップにWordファイルがある→ダブルクリックで開く→右側にClaudeサイドバーが出る
   - HPなら: ブラウザで検索→サイトがヒット→クリックして開く
   - アプリなら: ホーム画面のアイコンをタップ→起動画面
   - ツールがどのデバイスのどこにあり、どういう手順でアクセスするかを省略しない

3. **課題（視聴者が「あるある」と感じる状況を見せる）** — 見せるだけ。説明しない
   - 例(Slack): メール、Dropbox、テキスト、電話が同時に通知→情報に埋もれる映像
   - 対象ユーザーの「困っている場面」を再現する

4. **解決の瞬間（「おっ」と思わせるターニングポイント）** — 課題→解決の切り替わりを明確に
   - 例(Slack): 「So yeah, we tried Slack...」の一言でUIが切り替わる
   - 例(Grammarly): 赤い下線の上にカーソル→修正候補ポップアップ→クリック→直る

5. **具体的な操作（1つのタスクを最初から完了まで追う）** — ここがデモの本体
   - 例(Claude for Word): NDA文書のレビューという1つのタスクを、指示→分析→修正→QA→共有まで完遂する。機能を並べるのではなく、1つの仕事が終わるまでを見せる
   - 例(Grammarly): 文章を書く→エラー検出→修正→次のエラー→修正、を連続で見せる

6. **将来の姿（これによってどうなるか）** — 操作デモでは見せられない価値を伝える
   - まだ実装していない将来機能をモックやアニメーションで見せ、導入後の世界を想像させる

7. **締め (3-5秒)** — ロゴ、プロダクト名、行動喚起

## 2. 感情設計パターン

各シーンは「視聴者にこう感じてもらうために」存在する。「何の機能を見せるか」ではなく「何を感じさせるか」で設計する。

| シーンの種類 | 感じさせたいこと | 具体的にどうやって |
|---|---|---|
| フック | 「何だろう？」という好奇心 | 完成形のチラ見せ、意外な質問、印象的なビジュアル |
| アクセス手順 | 「ここにあるのか」という安心感 | 見慣れたデバイス・画面からツールに辿り着く様子 |
| 課題提示 | 「あるある」という共感 | 視聴者自身が経験する状況を再現 |
| 解決の瞬間 | 「おっ」という驚き | Before→Afterの劇的な切り替え |
| 機能デモ | 「なるほど、こう使うのか」という理解 | 1つのタスクを最初から完了まで見せる |
| 将来の姿 | 「いいな、使いたい」という期待 | 将来機能のモック、自動で動いている様子 |
| 締め | 記憶に残る印象 | ロゴ、プロダクト名、短いメッセージ |

## 3. 編集演出パターン

### ズームイン/アウト

ズームは「今ここを見て」という視線誘導。以下の場面で使う：
- **ユーザーが入力する時** → 入力欄にズーム（何を指示しているか読ませる）
- **AIや処理が結果を出した時** → 結果にズーム（何が分かったか読ませる）
- **ボタンをクリックする時** → ボタンにズーム（操作の因果関係を明確にする）
- **重要なテキストが表示された時** → テキストにズーム（読ませる）

パターン: 全体表示→ズームイン→全体表示の繰り返し。常に文脈（全体のどこにいるか）と詳細（今何をしているか）を行き来する。

### テンポ設計

- AI思考中・処理中 → テンポを落とす（期待感を持たせる）
- 結果表示・操作完了 → テンポを上げる（効率感を出す）
- 課題提示 → 高速カットで混乱を強調
- 機能デモ → 落ち着いたテンポでじっくり見せる

### テキスト挿入

操作デモの間に、無地の背景にテキストだけのシーンを挟む。余白のある画面で重要なメッセージを伝える。
- 例(Claude for Word): 「Claude takes on your edits, you sign off on them.」— AIと人間の役割分担を一文で伝える
- 例(Claude for Word): 「2 dealbreakers, 1 negotiable, 3 cosmetic」— 結果の要約をテキストで視覚化

### 効果音

操作に合わせた効果音で「今何をしているか」を聴覚からも伝える：
- クリック時 → クリック音
- テキスト入力時 → タイピング音
- 処理完了時 → 成功音
- エラー検出時 → 通知音

### その他

- **スムーズなトランジション**: シーン間の切り替えを流れるようなアニメーションで繋ぐ
- **情報フローの視覚化**: メッセージバブル、通知、サービスロゴをフローティング表示
- **スプリットスクリーン**: 関連する異なる情報を同時表示し、連携を強調

## 4. カーソルの使い方

- **意味のある操作の時だけカーソルを表示する**。ファイルを開く、入力欄を選択する、ボタンを押す等
- 無操作時や画面遷移時はカーソルを非表示にする。常に表示していると「今の動きは何？」と無駄な動きに勘繰らせてしまう
- カーソルは通常より大きく見やすいサイズにする（視認性重視）
- カーソルは録画時の実物ではなく、編集時に後付けで合成する方が自由度が高い

## 5. 制作技術

単なる画面録画ではなく、複数の技術を組み合わせて高品質を実現する：
- **操作録画**: Playwrightで実物のプロトタイプを操作する映像を撮る（素材）
- **カーソル合成**: 録画にはカーソルを含めず、編集時に大きく見やすいカーソルを必要な箇所にだけ合成する
- **ズーム**: 編集時にRemotionのinterpolateで特定箇所にズームイン/アウト。録画は常に全体表示で撮り、編集で切り出す
- **テキスト・ラベル**: Remotionで直接描画（ベクター品質、劣化なし）
- **効果音・BGM**: Remotionの`<Audio>`で配置

## 6. 非言語伝達のパターン

ナレーションや字幕がなくても、視聴者にメッセージを伝えるテクニック。

- **色彩**: 問題を示す赤色、解決や成功を示す緑色。UI状態の変化で改善を伝える
- **操作の視覚化**: カーソルの動きとクリックで「何を」「どこで」操作しているか直感的に理解させる
- **環境の変化**: 現状→改善後の対比で、変化を暗示する
- **効果音**: クリック音、タイピング音、成功音で操作の種類と結果を聴覚で伝える
- **テキスト挿入**: 操作デモの間に、重要なメッセージをテキストだけのシーンで伝える

## 7. 動きの参考パターン

再利用可能で効果的なアニメーション・トランジション。

*   **テキスト・データ操作**:
    *   リアルタイムタイピングと同時に、誤り検出や修正提案ポップアップが滑らかに出現するアニメーション
    *   データ入力後、即座にテーブルやグラフに反映される同期アニメーション
    *   メッセージや通知がポップアップ表示される動き
*   **UI・オブジェクト操作**:
    *   ドラッグ＆ドロップのアニメーション
    *   サービスロゴやアイコンが連続的に出現するアニメーション
    *   チェックボックス、ドロップダウン等のUI要素が直感的に動くアニメーション
*   **画面・ビュー遷移**:
    *   テーブル→カレンダー→ギャラリー等のビュー切り替えアニメーション
    *   デスクトップ→スマートフォンのクロスデバイス連携アニメーション

## シーン設計書のフォーマット

シーン設計書を作成する際は、各シーンに以下を必ず記述する。
「title.html 3s Dan×Notion」のような羅列は禁止。

```
### シーン N: [短いタイトル]

**秒数**: ○-○秒（○秒間）
**物語上の役割**: フック / アクセス手順 / 課題提示 / 解決の瞬間 / 機能デモ / 将来の姿 / 締め
**視聴者に感じさせたいこと**: （例: 「あるある」という共感、「おっ」という驚き）
**そのために何を映すか**: （上記の感情を引き出すために、画面に何を見せるか）
**操作の流れ**: （カーソルがどこに移動し、何をクリックし、画面がどう変化するか。カーソル非表示のタイミングも）
**前のシーンからの繋がり**: （なぜこの順番なのか、前のシーンの何を受けているか）
**編集演出**: （ズーム対象と目的、トランジション、テンポ、効果音、テキスト挿入の有無）
```
