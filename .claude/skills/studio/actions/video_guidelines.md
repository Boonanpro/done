以下は、優れたSaaS/プロダクト動画の共通パターンを抽出した、動画制作のためのガイドラインです。
参考動画: Base44 Superagents, Slack, Grammarly, Airtable, Canva

---

## 1. 物語構造のパターン

良い提案動画は機能の羅列ではなく、課題→解決の物語になっている。

**構造:**

1. **フック (5秒以内)** — 最初の数秒で「この動画は何について？」を伝える
   - 例(Slack): 創業者が「Slackのビデオ作ってよ」と言う→Adamが「メールで十分だろ」と返す。この1往復で「コミュニケーションツールの話」と分かる
   - 例(Base44): ロゴ→「Create your Superagent」→クリック。3秒で「AIエージェントの製品」と分かる
   - 例(Grammarly): いきなりテキスト入力が始まり赤い下線が出る。「文章チェックツール」と分かる

2. **課題（視聴者が「あるある」と感じる状況を見せる）** — 見せるだけ。説明しない
   - 例(Slack): メール、Dropbox、テキスト、電話が同時に通知→Adamが情報に埋もれる映像
   - 例(Base44): ← この動画は課題提示を省略し、いきなり解決を見せるパターン
   - 視聴者自身が経験する状況を再現する。特定の製品に限らず、対象ユーザーの「困っている場面」を見せる

3. **解決の瞬間（「おっ」と思わせるターニングポイント）** — 課題→解決の切り替わりを明確に
   - 例(Slack): 「So yeah, we tried Slack...」の一言でUIが切り替わる
   - 例(Grammarly): 赤い下線の上にカーソル→修正候補ポップアップ→クリック→直る
   - Before→Afterの劇的な切り替えで「解決された」ことを一瞬で伝える

4. **具体的な操作（実際にこう使う）** — ここがデモの本体。実物の操作を見せる
   - 例(Airtable): テーブルビュー→カレンダービューにタブ切り替え→ドラッグ&ドロップ
   - 例(Grammarly): 文章を書く→エラー検出→修正→次のエラー→修正、を連続で見せる
   - 1機能あたり10-20秒。操作→結果が見える、の繰り返し

5. **将来の姿（これによってどうなるか）** — 操作デモでは見せられない価値を伝える
   - 例(Slack): チームメンバーが楽しそうに働いている映像
   - 例(Base44): 夜間にAIが自動で分析→翌朝ブリーフィングが届く映像
   - まだ実装していない将来機能をモックやアニメーションで見せ、導入後の世界を想像させる

6. **締め (3-5秒)** — ロゴ、プロダクト名、行動喚起
   - 例(全動画共通): ロゴ + プロダクト名 + 短いメッセージ

## 2. 感情設計パターン

各シーンは「視聴者にこう感じてもらうために」存在する。「何の機能を見せるか」ではなく「何を感じさせるか」で設計する。

| シーンの種類 | 感じさせたいこと | 具体的にどうやって |
|---|---|---|
| フック | 「何だろう？」という好奇心 | 完成形のチラ見せ、意外な質問、印象的なビジュアル |
| 課題提示 | 「あるある」という共感 | 視聴者自身が経験する状況を再現。散らかったフォルダ、通知の嵐、手作業の面倒さ |
| 解決の瞬間 | 「おっ」という驚き | Before→Afterの劇的な切り替え。散乱→整理、エラー→修正、手動→自動 |
| 機能デモ | 「なるほど、こう使うのか」という理解 | 実際の操作を見せる。カーソルが動き、クリックし、結果が出る |
| 将来の姿 | 「いいな、使いたい」という期待 | まだ実装していない機能のモック、自動で動いている様子、時間の節約を示唆 |
| 締め | 記憶に残る印象 | ロゴ、プロダクト名、短いメッセージ |

## 3. 編集演出パターン

特定の場面で効果的な編集テクニック。

*   **テンポ変化**: 課題提示や混乱時は高速カットや情報のオーバーレイで混乱を強調。解決策提示後は落ち着いたテンポで機能や効果をじっくり見せる。
*   **スムーズなトランジション**: 異なるビュー、デバイス間、シーン間の切り替えを流れるようなアニメーションで繋ぎ、シームレスな体験や連携を強調する。
*   **UI要素の視覚的強調**: クリックする場所、選択するメニュー、重要なテキストなどを、枠線、ハイライト、ズーム、色の変化などで目立たせ、視線の誘導と理解を助ける。
*   **情報フローの視覚化**: メッセージバブル、通知、サービスロゴなどを画面上にフローティング表示させ、デジタル情報の流れや連携を視覚的に表現する。
*   **サウンドデザイン**: 状況や感情の変化に合わせてBGMや効果音を使い分け、動画のメッセージを聴覚からも強化する（例: 混乱時の雑音、解決後のクリアな音、感動的なBGM）。
*   **リアルタイム操作の描写**: タイピングアニメーション、マウスカーソル操作、プログレスバーなどで、実際の使用感や操作の容易さを臨場感をもって伝える。
*   **スプリットスクリーン**: 関連する異なる情報やデバイスの画面を同時に表示し、連携やリアルタイム同期を強調する。

## 4. 動きの参考パターン

再利用可能で効果的なアニメーション・トランジション。

*   **テキスト・データ操作**:
    *   リアルタイムタイピングと同時に、誤り検出や修正提案ポップアップが滑らかに出現・置換されるアニメーション。
    *   データ入力後、即座にテーブルやグラフに反映される同期アニメーション。
    *   メッセージや通知が画面上にフローティングまたはポップアップ表示される動き。
*   **UI・オブジェクト操作**:
    *   ファイルや要素をドラッグ＆ドロップするアニメーション。
    *   サービスロゴやアイコンが連携時に連続的に出現するアニメーション。
    *   チェックボックスのオン/オフ、ドロップダウンメニューの選択など、UI要素が直感的に動くアニメーション。
*   **画面・ビュー遷移**:
    *   テーブル→カレンダー→ギャラリーなど、データ表示形式が切り替わるアニメーション。
    *   デスクトップ→スマートフォンへのクロスデバイス連携アニメーション。
    *   写真や背景動画にズーム、フェード、スライドなどを適用し、視覚的な奥行きや動きを与える。

## 5. 非言語伝達のパターン

ナレーションや字幕がなくても、視聴者にメッセージを伝えるテクニック。

*   **色彩**: 問題を示す赤色、解決や成功を示す緑色。混乱→整然のUI変化。
*   **操作の視覚化**: マウスカーソルや指の動きを明確に示し、「何を」「どこで」操作しているか直感的に理解させる。
*   **環境の変化**: 現状→改善後の対比で、変化を暗示する。
*   **サウンドデザイン**: 通知音、成功音、環境音で感情の変化やツールの利便性を伝える。

## シーン設計書のフォーマット

シーン設計書を作成する際は、各シーンに以下を必ず記述する。
「title.html 3s Dan×Notion」のような羅列は禁止。

```
### シーン N: [短いタイトル]

**秒数**: ○-○秒（○秒間）
**物語上の役割**: フック / 課題提示 / 解決の瞬間 / 機能デモ / 将来の姿 / 締め
**視聴者に感じさせたいこと**: （例: 「あるある」という共感、「おっ」という驚き）
**そのために何を映すか**: （上記の感情を引き出すために、画面に何を見せるか）
**操作の流れ**: （カーソルがどこに移動し、何をクリックし、画面がどう変化するか）
**前のシーンからの繋がり**: （なぜこの順番なのか、前のシーンの何を受けているか）
**編集演出**: （ズーム、トランジション、テンポ等。本ガイドラインの3,4を参照）
```
