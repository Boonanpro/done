動画制作のためのガイドライン。
主な参考動画: Claude for Word (https://www.youtube.com/watch?v=CnAPjeQt5Jg)

---

## 1. 物語構造

良い動画は機能の羅列ではなく、1つのタスクを最初から完了まで追う物語。

1. **フック (5秒以内)** — 「この動画は何について？」を伝える
   - 例: Wordのトグルスイッチがオンになる→「Claude now works alongside you in Word」

2. **アクセス手順** — そのツールがどこにあり、どうやって辿り着くかを見せる
   - 例: macのデスクトップにWordファイル→ダブルクリック→Claudeサイドバーが出る
   - HPなら: 検索→ヒット→クリック→開く。アプリなら: ホーム画面→タップ→起動
   - 省略しない。視聴者は「で、これどこから使えるの？」と必ず思う

3. **1つのタスクを最初から完了まで** — デモの本体。機能を並べるのではなく、1つの仕事が終わるまでを見せる
   - 例: NDA文書のレビューを、指示→AI分析→修正指示→修正適用→QA→共有まで完遂
   - 機能紹介ではなく「この仕事がこう片付く」を見せる

4. **テキスト挿入** — 操作デモの間に、無地の背景にテキストだけのシーンを挟む
   - 例: 「Claude takes on your edits, you sign off on them.」— 役割分担を一文で伝える
   - 例: 「2 dealbreakers, 1 negotiable, 3 cosmetic」— 結果の要約を視覚化
   - 余白のある画面で重要なメッセージを届ける

5. **締め (3-5秒)** — ロゴ、プロダクト名、行動喚起

## 2. カーソル

- **意味のある操作の時だけ表示する**（ファイルを開く、入力欄を選択する、ボタンを押す）
- 無操作時や画面遷移時は非表示。常に表示していると無駄な動きに勘繰らせる
- 通常より大きく見やすいサイズ
- 録画時の実物カーソルではなく、編集時に後付けで合成する

## 3. ズーム

「今ここを見て」という視線誘導。以下の場面で使う：
- **ユーザーが入力する時** → 入力欄にズーム（何を指示しているか読ませる）
- **結果が出た時** → 結果にズーム（何が分かったか読ませる）
- **ボタンをクリックする時** → ボタンにズーム（操作の因果関係を明確にする）

パターン: **全体表示→ズームイン→全体表示の繰り返し**。文脈（全体のどこにいるか）と詳細（今何をしているか）を常に行き来する。ズームしても文字が崩れない品質を確保する。

## 4. テンポ

- AI思考中・処理中 → テンポを落とす（期待感）
- 結果表示・操作完了 → テンポを上げる（効率感）
- 課題提示 → 高速カットで混乱を強調
- 機能デモ → 落ち着いたテンポでじっくり見せる

## 5. 効果音

操作に合わせた効果音で「今何をしているか」を聴覚からも伝える：
- クリック → クリック音
- テキスト入力 → タイピング音
- 処理完了 → 成功音
- エラー/問題検出 → 通知音

## 6. 制作技術

単なる画面録画ではなく、複数の技術を組み合わせて高品質を実現する：
- **操作録画**: Playwrightで実物のプロトタイプを全体表示で撮る（素材）
- **カーソル合成**: 録画にはカーソルを含めず、編集時に必要な箇所にだけ大きく見やすいカーソルを合成
- **ズーム**: 編集時にinterpolateで特定箇所にズームイン/アウト。録画は常に全体表示
- **テキスト・ラベル**: Remotionで直接描画（ベクター品質、劣化なし）
- **効果音・BGM**: Remotionの`<Audio>`で配置

## 設計書のフォーマット

2階層で書く。上位の「動画全体設計」→下位の「シーン別設計」。

### 動画全体設計（冒頭に1ブロック）

```markdown
# 動画設計書: [案件名]

## 全体設計
- **視聴者**: 誰に見せる動画か
- **核心メッセージ**: 伝えたい1行
- **尺**: N秒（目安）
- **ゴール**: 視聴後に取ってほしい行動
- **トーン**: 丁寧／煽る／軽快 等
- **BGM/ナレーション方針**: 有無とスタイル
```

### シーン別設計（各シーンに1ブロック）

```markdown
### シーン N: [短いタイトル]

**秒数**: N-N秒（N秒間）
**物語上の役割**: フック|アクセス手順|タスク遂行|テキスト挿入|締め
**視聴者に感じさせたいこと**: 一言

**そのために映すもの**（曖昧さを排除するため具体化）:
- 画面: URL or 前シーン継続
- スクロール位置: 「〇〇」要素が中央 / 絶対Y座標
- 中心の要素: [要素A, 要素B]

**操作の流れ**（recorder が読み取れる疑似コードで書く）:
\`\`\`
scroll_to(text="対応車種")
wait(2s)
click(selector='a[href="/contact"]')
type(selector='input[name="company"]', value="〇〇株式会社")
\`\`\`

**前シーンからの繋がり**: 一言

**編集演出**（項目別、機械で検証できる形）:
- ズーム: 対象 / 倍率 / 尺
- テロップ: 文言 / 位置 / 出現タイミング
- 効果音: 種類 / タイミング
- トランジション（シーン末尾）: 種類

**検証チェック**（生成物と照合するための数値）:
- ズーム回数: N
- テロップ数: N
- クリック: N
- タイピング: N
```

### 書くときの原則

1. **操作の流れは recorder の擬似コードで書く**（自然文は不可）。そうすれば recorder に機械変換できる
2. **「そのために映すもの」は必ずセレクタ名・要素名まで具体化する**。「画面の上部」のような抽象表現は不可
3. **編集演出は項目別に書く**。1行に混ぜて書かない。A ロボットが項目ごとに判定する
4. **検証チェックを書く**。これで生成物が設計通りかを機械照合できる
