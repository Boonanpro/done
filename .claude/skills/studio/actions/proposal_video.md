# 提案動画制作手順

> ⚠️ **このアクションは「提案動画作って」とユーザーが明示的に依頼した時だけ参照する。**
> 通常の機能制作・成果物提示には使わない。新アーキテクチャでは
> チャット右ペインのライブプレビューで実物を見せて会話で詰めるのが基本。
> 提案動画は外部営業など「動画が必要な特定状況」に限定したフローとして残してある。

---

## 提案動画とは

テキストで提案済みの内容を動画化する。動画はあくまで**概要を視覚的に伝える補助資料**。承認はテキストの詳細仕様書ベースで行う。動画だけで承認を取らない。

## フロー

1. **デモシーン抽出** — ユーザーの要望 + リサーチ結果の両方からデモで見せるべき項目を漏れなく抽出する
   - **「機能」**: 基本機能として明記されたもの
   - **「ビジョン」**: 将来構想として語られたもの
   - **「具体例」**: ユーザーが挙げた具体的な利用シーン
   - **「リサーチ発見」**: リサーチで発見した重要機能
   - **全項目に対してデモシーンを 1 つ作る。省略しない。**

2. **`create_feature(demo=True, scenes=[...])` を実行する** — ⚠️ 必須。スキップ不可
   - Step 1 で抽出したシーンリストを `scenes` 引数に渡す
   - シーン設計書テンプレート (`docs/proposals/xxx_scenes.md`) が自動生成される
   - DB migration, schemas, フロントエンドページ (demo/ パス) の雛形が生成される
   - **create_feature を実行せずに demo/ にファイルを作ろうとすると guard hook でブロックされる**

3. **シーン設計書を埋める** — 自動生成されたテンプレートの各シーンの詳細を定義する
   - `actions/video_guidelines.md` を参照
   - 各シーンには「何が映るか」「視聴者に何を感じさせるか」「前のシーンからどう繋がるか」を定義する
   - シーン設計書の全シーンを実装する。省略する場合は事前にユーザーに相談

4. **プロトタイプ作成** — create_feature が生成した雛形を埋めてデモ用 UI を構築
   - 実際にクリック・入力・遷移ができる Web ページとして作る。HTML にシーンを埋め込んで JS で切り替える方式は禁止
   - build スキルに従って作る (承認後にプロトタイプを拡張して本番化するため)
   - create_feature が `frontend/src/app/demo/` 配下に雛形を生成済み。これを拡張する
   - 動画提出時にプロトタイプの場所と主要ファイルを明記する

5. **操作録画** — SKILL.md の「制作技術 → 操作録画のルール」に従う

6. **編集** — Remotion でテキスト挿入・BGM・SE 追加

7. **品質チェック** — SKILL.md の「品質チェック」共通チェックリストに従う

## 提案動画用プロトタイプの品質基準

提案動画で見せる create_feature(demo=True) のプロトタイプは、見た目だけのモックで終わらせず、コア機能が実際に動く状態まで仕上げる。最低ラインは「コア機能が動作しているデモ動画が撮れる」品質。動くプロトタイプそのものが最大の営業要素。

## 承認後の本番移行

ユーザーが承認したら `create_feature(feature_name, demo=False)` を実行する。
成果物は **demo/ のまま**保持され (移動しない)、backend の service/routes 雛形が追加される。
`chat_artifact.kind` が `demo` → `production` に切り替わり、チャット右ペインで引き続きプレビュー/編集できる。プロトタイプのまま本番実装を拡張する。

**重要**: 生成物を `frontend/src/app/dashboard/` に作ろうとしない。dashboard/ 配下は廃止済み。全成果物は `frontend/src/app/demo/{slug}/` に配置する。
