# ダンスタジオ

動画の企画・生成・編集を行う汎用スキル。designスキルがUIを伴う成果物全般を扱うように、このスキルは動画を伴う成果物全般を扱う。

---

## 共通ルール

### ⚠️ 品質チェックは必須

レンダリング後、ユーザーに提出する前に必ずセルフチェックする。

- [ ] 映像にアニメーション（マウス移動、画面遷移）があるか？静止画の連続になっていないか？
- [ ] マウスカーソルが全フレームで視認できるか？（操作録画の場合）
- [ ] テキスト/字幕がUI要素と被っていないか？
- [ ] BGMが映像と同じ長さで終わっているか？（黒画面+音楽だけになっていないか）
- [ ] 動画の目的に対して必要なシーンが全て含まれているか？
- [ ] 全体表示時に映像の端が見切れていないか？（ズーム等の意図的な演出は除く）

**1つでも不合格なら修正してから提出する。**

### BGM

- **著作権フリーの実際の楽曲を使う。Pythonで生成したサイン波は禁止。**
- Mixkit (mixkit.co/free-stock-music) 等からダウンロード
- 映像の長さに合わせてトリムする

### 音声ナレーション（推奨）

- 字幕テキストはUI要素と被りやすいため、音声ナレーションが望ましい
- ElevenLabsまたはGoogle TTSで生成
- Remotionの`<Audio>`コンポーネントでタイムラインに配置

## 制作技術: Playwright操作録画 + Remotion編集

### 概要

実物のプロトタイプやWebページをPlaywrightで操作録画し、Remotionで編集してMP4出力する。
DaVinci Resolveのインストールは不要。コードの差分だけで修正・量産可能。

### フロー

1. **Playwrightで操作録画**（PNG連番 + カーソル合成）
2. **PNG連番を直接Remotionに読み込む**（MP4変換を挟まない。二重圧縮による画質劣化を防ぐ）
3. **Remotionコードでイントロ/アウトロ、テキストラベル、BGM、トランジションを追加**
4. **`npx remotion render` でMP4出力**

### 操作録画

- `scripts/record_notion_demo.py` を参照（パターンとして使える）
- `smooth_move(x1,y1,x2,y2,steps)` — イージング付きマウス移動
- `capture(n)` — nフレーム分スクリーンショット
- `mouse_positions[]` — 座標記録→カーソル合成用

**カーソル合成:**
- Playwrightのscreenshot()はカーソルを含まない
- Pillowで全フレームにカーソル画像を合成する（28px、白地に黒アウトライン、完全不透明）

### Remotion編集

**基本API:**
- `interpolate(frame, inputRange, outputRange)` — 数値アニメーション
- `spring({frame, fps, config})` — 自然なバウンスアニメーション
- `<Sequence from={frame} durationInFrames={n}>` — シーンの時間制御
- `<Audio src={staticFile("bgm.mp3")} volume={...} />` — BGM/効果音
- `@remotion/transitions` — シーン間トランジション（fade, wipe, slide）

**操作映像の表示ルール:**
- 全体表示時に映像の端が見切れていないこと（ズーム等の意図的な演出は除く）
- `objectFit: "contain"` を使うか、マージン分を考慮したサイズで表示する

**テキスト・字幕の品質:**
- Remotionで直接Reactコンポーネントとして描画するため、テキストはベクター品質で劣化しない
- 操作映像部分のみラスタ画像（PNG）

**エフェクト拡張:**
- Remotionは普通のReactコンポーネントなので、カスタムエフェクトを自作可能
- パーティクル（Canvas/WebGL）、3D変換（CSS transform/React Three Fiber）、カラー調整（CSSフィルタ）等
- `@remotion/motion-blur` — モーションブラー（公式パッケージ）
- 必要に応じてnpmパッケージとしてエフェクトを追加・作成していく

参考事例: Hotfix社（Gemini→絵コンテ、Claude Code→Remotionコード、ElevenLabs→音声）

### 汎用ツール（HTML録画方式）

HTMLアニメーションから動画を作る場合の専用ツール。

| ツール | 用途 |
|--------|------|
| `studio_record` | HTMLをPlaywright headlessで録画 → .webm生成 |
| `studio_encode` | FFmpegで変換（WebM→MP4、解像度変更等） |
| `studio_probe` | 動画のメタ情報取得（コーデック、解像度、長さ） |
| `studio_extract_frame` | 指定時刻のフレームをPNG抽出（内容検証用） |
| `send_file` | 完成動画をチャットUIに送信 |

**⚠️ Bash で Playwright/FFmpeg を直接実行しない。** 出力データがCLIメモリに蓄積してクラッシュする。必ず上記ツールを使う。

## パターン別ガイド

### パターン1: 提案動画

テキストで提案済みの内容を動画化する。

**前提:** リサーチ・要件策定・提案内容のテキスト化は完了済み。ユーザーから「動画にして」と指示されて起動。

**⚠️ 提案動画と承認の関係:** 動画はあくまで概要を視覚的に伝える補助資料。承認はテキストの詳細仕様書ベースで行う。動画だけで承認を取らない。

**フロー:**

1. **デモ設計** — 提案内容からシーン構成を決定
   - 要件の核心機能は必ずデモに含める
   - ユーザーが将来ビジョンとして語った内容もシーンに含める（モックやチャットUIで表現可能）
   - Before/After構成を基本とする
   - Gemini APIに参考動画を見せて絵コンテを生成できる
   - **絵コンテの全シーンを実装する。省略する場合は事前にユーザーに相談**

2. **プロトタイプ作成** — デモ用UIを構築
   - 全機能は不要。デモで見せるシーンの画面だけ（全体の20%程度）
   - モックデータでOK。ただし実ファイルを数点含めると説得力が上がる
   - `frontend/src/app/demo/` 配下に作成

3. **操作録画** — Playwrightで録画+カーソル合成

4. **編集** — Remotionでタイトル・BGM・音声追加

5. **品質チェック** — 共通チェックリスト + 以下を追加確認
   - [ ] 要件の核心機能が全てデモに含まれているか？
   - [ ] 将来ビジョンのシーンが含まれているか？
   - [ ] 動画の長さは30-45秒以内か？

**参考動画ライブラリ:**

| 用途 | URL |
|------|-----|
| SaaS紹介 | https://www.youtube.com/watch?v=mHUVjd8-BF8 |

### パターン2: 紹介動画（追加予定）

完成した成果物（HP、アプリ等）の紹介動画。実物をPlaywrightで操作録画する。

### パターン3: チュートリアル（追加予定）

操作手順を説明する動画。ステップごとの操作録画+音声ナレーション。

### パターン4: SNSショート（追加予定）

SNS投稿用の短尺動画。縦型対応、テンポ重視。
