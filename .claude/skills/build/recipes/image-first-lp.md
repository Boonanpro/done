# T0 画像ファーストLP（LP・広告LPの既定方式）

GPT Image 2 でLPデザインを**画像として生成**し、操作が必要な箇所（入力欄・ボタン）だけを
実HTMLで重ねる方式。コードでデザインを組み立てない。

2026-08-03 に置く床暖房LPで通し検証済み。従来のコード方式より速く、デザイン品質も高い
（AIの平均的なHTML出力ではなく、画像モデルのデザイン能力をそのまま使えるため）。

## いつ使う / 使わない

| 使う（既定） | 使わない（従来のコード方式 T1〜T4） |
|---|---|
| 広告LP・ドライテストLP・キャンペーンページ | 多ページ企業HP（kittoku型） |
| 縦スクロール1枚もの | SEO・検索流入が主目的のサイト |
| スマホユーザーが主対象 | 頻繁な文言更新を客が自分で行うサイト |
| | ダッシュボード・管理画面・機能ページ |

**この方式ではリファレンス収集(HM5)・自己採点ループ(criteria.md)は不要**。
デザイン品質は画像モデル側が担保する。代わりに後述の「文字QA」を必ず行う。

## 制約（先に知っておく）

- Higgsfield経由の GPT Image 2 は**縦長が 9:16 まで**。LP全体はタイル分割で作る
- 9:16タイル1枚（1520×2688, 2k）＝スマホ約1画面ぶん。解像度はスマホ幅の約3.9倍で拡大にも耐える
- Inspector編集は使えない。文言修正は「タイル再生成→領域合成」で行う（後述）
- テキスト選択・コピー不可。SEOはalt属性のみ（広告LPでは実害なし）

## 手順

### 1. タイル設計 — 密度は役割で決める（疎密のリズム）

タイル（9:16＝スマホ約1画面）の情報密度は一律にせず、**役割で強弱をつける**:

- **疎（1メッセージ・余白で魅せる）**: ヒーロー / ブランドメッセージ / 登録フォーム / 締めCTA
- **密（2メッセージ・部品で説得する）**: 中盤の説得パート（悩み共感・根拠・比較・
  仕様・FAQ）。カード群 / 比較表 / 仕様表 / 間取り図・断面図 / アイコン列 などの
  「LPの部品」を積極的に使う
- **疎→密→疎のリズム**を作る。同じ密度の画面を3枚以上連続させない

（経緯 2026-08-03: 全タイル1メッセージは「おさまりは良いがLPらしい分かりやすさが
消える」、1タイル2〜3メッセージ詰めは「デザイン性が高い」評価。良さの正体は
密度そのものではなくリズムと部品の多彩さ、という結論からこの規則になった）

典型構成（6〜7タイル、[疎]/[密]を明記）:
ヒーロー[疎] → 悩み共感＋解決の核心[密] → 根拠・数字＋比較[密] →
ブランドメッセージ[疎] → 仕様＋FAQ[密] → 登録フォーム[疎]

### 2. プロンプト型

各タイルのプロンプトに必ず含める:

```
【全体スタイル（厳守）】
- 背景は全面 <背景色>。画像の最上端と最下端は約60pxぶん背景色のみとし、
  要素を端に接触させない   ← タイルの繋ぎ目を消すため必須
- 見出しは<見出しフォント指定>、本文はゴシック体
- アクセント色は<色>（CTAボタンと強調のみ）
- スマホで読む前提。文字は画面幅に対して大きく、余白はたっぷり
【最重要ルール】この画面が伝えるメッセージは1つだけ:「<メッセージ>」
【内容】（上から順に、文言を一言一句指定する）
...
日本語の文字はすべて正確に、誤字なく描くこと。
```

- 文言はプロンプトで**一言一句指定**する（モデルに作文させると誤字・改変が出る）
- 入力欄・ボタンは「白い角丸の入力欄（内側にグレー文字で◯◯）」
  「<色>の大きな角丸ボタン:「◯◯」」のように描き込ませる（後で実HTML化する）
- LINEボタンは緑 #06C755 指定（後段の色検出が green→line と分類する）

### 3. 生成 — 1枚目をスタイル参照に連鎖

```bash
# 1枚目（スタイルの基準になる。出来が悪ければ作り直してから先へ）
cat tile1_prompt.txt | higgsfield generate create gpt_image_2 \
  --aspect_ratio 9:16 --resolution 2k --wait --json > r1.json

# 2枚目以降は1枚目を --image で渡す（配色・書体・トーンが揃う）
cat tile2_prompt.txt | higgsfield generate create gpt_image_2 \
  --image ./tile1.png --aspect_ratio 9:16 --resolution 2k --wait --json > r2.json
```

- 2枚目以降は並列実行してよい（全部 tile1 参照でOK。実測で一貫性に問題なし）
- 1タイル2〜3分。認証切れは `higgsfield auth login`（ユーザーに承認してもらう）

**⚠️ 生成完了までターンを終えないこと。**「生成中です、あと数分」と報告して
ターンを終えると、バックグラウンドの生成プロセスはターン終了と同時に死に、
完了通知も次ターンに届かない（2026-08-03 実測: 並列7ジョブが全滅）。
並列化はシェルの `( ... --wait ... ) & ... wait` で**同一コマンド内で完了まで待つ**。
完了→文字QA→具現化→検証→URL報告までを1ターンで完走する。

### 4. 文字QA（必須）

各タイルを Read で表示し、**プロンプトの指定文言と1文字ずつ照合**する。
誤字・脱字・勝手な改変があればそのタイルだけ再生成。
（実測: 9タイル生成して誤字ゼロだったが、保証はないので必ず見る）

### 5. 具現化 — 座標検出とページ生成

```bash
python scripts/lp_image_materialize.py \
  --images t1.png t2.png t3.png --slug <slug> \
  --out-json coords.json --out-page page.tsx
```

- ボタン（ベタ塗り横長・彩度高）と入力欄（白い横長・文字なし・ボタンの直上）を
  色検出して座標JSON + page.tsx 雛形を出力する
- 検出結果は**必ず目視確認**（雛形ページの「操作領域を表示」トグルで赤枠表示）
- 雛形の TODO（送信先scope・LINE URL・ボタンの遷移先）を案件に合わせて埋める
- 画像は `frontend/public/scratch/<slug>/`（試作）または
  `frontend/public/artifacts/<slug>/`（納品）に置く

ページ側の必須事項:
- `/scratch` 配下は専用 layout.tsx で html/body のスクロール解放
  （globals.css の overflow:hidden 対策。`/artifacts` 配下は既存 layout が解決済み）
- ルート layout が `maximumScale: 1` なので、viewport export で
  `maximumScale: 5, userScalable: true` を上書き（ピンチ拡大できないと画質確認不能）
- エラーメッセージ等の後付けUIは**不透明背景の帯**にする（背後の描き込み文字と被るため）

### 6. 修正 — タイル再生成 → 領域合成

Higgsfield の参照編集は**全体を微妙に描き直す**（写真の細部が変わる）。
そのまま差し替えず、**変更したい領域だけを元画像に合成**して領域外の完全不変を保証する:

```bash
# 1. 該当タイルを参照にして修正版を生成
echo "添付画像の◯◯を「◯◯」に変更。それ以外は一切変更しない" | \
  higgsfield generate create gpt_image_2 --image ./t1.png \
  --aspect_ratio 9:16 --resolution 2k --wait --json > edit.json

# 2. 変更領域だけ合成（--region 推奨。場所が不明なら --auto + 目視確認）
python scripts/lp_image_patch.py --original t1.png --edited t1_edit.png \
  --region <x0,y0,x1,y1> --out t1_v2.png
```

- `--region` の座標は coords.json（materialize出力）か画像目視から取る
- 出力の `changed OUTSIDE region: 0.0000%` を必ず確認
- レイアウト自体を変える修正（要素の追加・移動）は合成不可。タイルごと作り直し、
  文字QAをやり直す

### 7. 検証

Playwright で: 表示200・操作領域の位置ズレ（赤枠トグル）・入力→送信→API 200・
CTAスクロール・モバイルviewportスクショ。実機URL（LAN IP）をユーザーに渡す。

## 公式API（任意の強化）

OpenAI 公式 `gpt-image-2` はマスク編集（inpainting）と自由サイズに対応しており、
手順6の代替になる（マスク外は構造的に不変）。ただし従量課金で、課金上限に注意。
Higgsfieldだけで全工程が成立することは実証済みなので、無くてよい。
