## 2026-10-25 並びで分かる説明を重ねない
- 種類: 指摘
- 変更するファイル: SKILL.md、criteria.md
- 具体の指摘: 開発室の付箋に状態の札を増やした際、本人は「分かりづらい。もっと直感的に分からなきゃいけない」と指摘した。今回、画面の並びで分かる札や説明を減らす規則と、表示文字の点検を求めた。
- 受け手に起きていなかったこと: 利用者が項目の位置や操作の形から判断できず、内容に進む前に補助の文章を読まされていた。
- 一般則: 状態・種類・操作は、関連する対象の近くで並び・色・形・動きにより区別する。同じ情報を説明文で繰り返さなければ、内容と操作を探しやすい。ただし、色や動きだけに意味を依存させず、意味が曖昧になる文字は残す。
- 技: 作成・修正する画面で、同種の項目を揃えて並べ、操作を対象の近くに置き、選択や進行を形・色・動きで区別する。表示文字を抽出し、本文・データ以外の札・説明・凡例を1つずつ仮に隠し、操作・状態・種類が分かるものだけ消す。分からなければ並びを直すか短い文字を残す。操作名、入力欄の名前、エラーの理由や復旧方法、重要な判断情報、読み上げ名を一律に消さない。
- 別テーマでの例: 家計の入出金画面。良い例は「支出」「収入」の列に金額を揃え、各支出の横にある反復した「支出の金額です」を消す。悪い例は同じ列配置に、その説明を毎行足す。列見出し、円の単位、赤字の理由を示すエラーは残す。列の並びを見て入出金を区別できるか、説明を消しても金額の意味が失われないかを確認できる。
- 出どころ: 本人の2026-10-23の指摘と2026-10-25のGO済み計画 ui-layout-explains。開発室の既存実装では札を視覚表示から外し、読み上げ用の状態名を残している（page-body.tsx sticky）。今回の画面見本は承認済み成功例として扱わず、採用判断用とする。

## 2026-10-18 確かめる範囲を裏側と公開版まで広げ、確かめずに終われないことを書く
- 種類: 操作
- 変更するファイル: SKILL.md
- 何を直したか: 確認の段の artifact_seen.py の説明を、今の仕様に合わせた。(1) 出力に、本番の裏側（_server を動かす 8000）が今のファイルで動いているかと、公開版（スマホのアプリが開く Vercel の写し）が今のファイルから作られたかも出る。どれかが古ければ result=NG。(2) _server は本体の再起動なしに数秒で読み直される。裏で thread を回す routes.py には止め方 `dan_unload()` が要り、無ければ「本体の再起動が要る」と出る。(3) 成果物を書き換えたのに artifact_seen.py を走らせずにターンを終えようとすると、Stop の関所（scripts/hook_artifact_verify_gate.py）が止める。(4) 「直した」の根拠にしてよいのは本人と同じ経路（3000 の /preview/<slug>、裏側は本番 8000）の確認と artifact_seen.py の出力だけ。8001 などの確認用サーバーや worktree での確認は途中の試験で、完了の根拠にしない。背景: 10/18 本人「あなたが直して確認した画面と私が見る画面が一致し、直したと言われたものはちゃんと直っている状態に」。画面だけ新しく裏側が再起動待ちのまま、の食い違いが面談受付で長く続いた。
- 確かめたこと: 実際の uvicorn（本体と同じ event loop）で _server を2回書き換え、3,036回の連続アクセス中に失敗0件で新しい版に替わり、見回りの thread が1本のままだったこと。構文エラーの版は古い版のまま動き続け state=failed、dan_unload の無い thread 付きの版は state=needs-restart になること。artifact_seen.py が裏側の記録が無い時（再起動前）に NG と理由を出すこと。Claude CLI と Codex CLI の両方で、成果物を書き換えて終えようとすると関所が止め、artifact_seen.py を走らせて結果どおりに書くと通ること。
