# Tool Reference

Toolは、ユーザーが画面上で作業する成果物。見た目よりも、操作完了までの分かりやすさ、状態管理、エラー回復を優先する。

## 必須フロー

1. 主要ジョブを1つ決める: 予約する、生成する、診断する、投稿する、検索する、管理する。
2. 入力、処理、出力、保存、共有の有無を整理する。
3. API/DBが必要ならバックエンドから作る。
4. UIは既存のshadcn/uiとローカルhooksを優先する。
5. 3状態を必ず作る: loading / error / empty or initial。
6. ブラウザで主要操作を実行して確認する。

## UI

- ボタン、入力、タブ、ダイアログ、メニュー、トーストは既存UIコンポーネントを使う。
- 画面説明の長文を置かず、操作面そのものが分かるようにする。
- 主要操作はファーストビューで開始できるようにする。
- 結果はコピー、保存、再実行、戻るの導線を用意する。

## Integration

- 既存APIクライアントやhooksがある場合は再利用する。
- ログイン/初期設定が必要なページは `useSetupGate` を使う。
- 予約が必要な場合は `<BookingCalendar>` + `useBooking` を優先する。
- 問い合わせ送信は `<InquiryForm>` または `/api/v1/inquiries` を使う。

## 完了条件

- 主要操作が最後まで通る。
- 入力バリデーションがある。
- loading/error/empty/success状態がある。
- mobileで操作ボタンが潰れない。
- APIがある場合はcurlまたは統合テストで確認済み。
