# LP Reference

LPは、1つの行動に向けて訪問者を迷わせず進めるページ。
HPのように全体理解や回遊を主目的にしない。

## 必須フロー

1. 目的を1つに絞る: 申込 / 問い合わせ / 購入 / 予約 / 待機リスト / モニター募集。
2. 流入元を仮定する: 広告 / SNS / DM / 既存顧客 / 検索。
3. オファーを明確にする: 誰に、何を、なぜ今、どの条件で。
4. CTAとフォームの設計を先に決める。
5. 必要ならGPT Image 2でハイファイmockまたは画像スライスを作る。
6. active要素はDOMで実装し、送信後の状態まで作る。

## 推奨構成

1. First view: 対象者、痛み/欲求、具体的約束、主CTA。
2. Product visual: 実物、画面、スマホmock、生成ビジュアル。
3. Why now: 放置コスト、機会、期間/人数制限。
4. How it works: 3ステップ。
5. Proof: 実績、レビュー、デモ、比較。
6. Offer detail: 価格、条件、対象/非対象。
7. FAQ: 申込前の不安。
8. Final CTA/Form: 完了後の次アクションを含む。

## Rendering Modes

- `dom-first`: SEO/編集性重視。B2Bや長文説明に向く。
- `comp-guided-dom`: 画像mockを見本にHTML化。バランス型。
- `image-slice-hybrid`: 生成画像セクションを大きく使い、CTA/フォーム/入力/送信結果だけDOMで重ねる。ビジュアル再現度が最優先の短いLPに向く。

`ImageSlicePage` を使う場合:

- desktop/mobile画像を分ける。
- overlayは%矩形で指定する。
- H1、主要説明、CTA、フォームラベル、完了メッセージはDOMまたはsr-onlyで持つ。
- 画像内に焼き込まれたボタンをそのままにせず、可能なら空の枠で生成し直す。

## CTA

LPではCTAは強めでよいが、数を増やすこと自体を目的にしない。
同じ行動に統一し、途中CTAはフォームや最終CTAへ自然につなぐ。

## Motion

LPの動きはCVを邪魔しない範囲に限定する。

- 入力欄、ボタン、送信状態は明確に反応させる。
- スクロール演出は、理解促進や視線誘導に効く場合のみ使う。
- 重い動画やスクロールジャックでフォーム到達を遅らせない。

## 完了条件

- ファーストビューで「誰向け・何の得・何を押す」が分かる。
- CTAとフォームがPC/mobileで操作できる。
- 送信成功/失敗/ロード状態がある。
- 画像mock方式の場合、overlay位置がPC/mobileでズレていない。
