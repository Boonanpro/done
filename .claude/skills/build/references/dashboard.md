# Dashboard Reference

Dashboardは、データを見て判断・管理する画面。装飾よりも情報階層、スキャン性、操作効率を優先する。

## 必須フロー

1. 誰が何を判断する画面かを決める。
2. KPI、チャート、一覧、詳細、フィルタ、アクションを分類する。
3. DB/APIが必要ならバックエンドから作る。
4. shadcn/uiのCard、Table、Tabs、Badge、Button、Skeleton等を使う。
5. loading / error / emptyを作る。
6. データ型と表示型が一致しているか確認する。

## Layout

- 上から、概要KPI → 傾向/チャート → 詳細一覧 → 操作ログ/補足。
- 同じ優先度のカードを並べすぎない。
- フィルタや検索は一覧の近くに置く。
- 重要な異常値や期限は色だけでなくラベルやアイコンでも示す。

## Interaction

- フィルタ、ソート、ページング、詳細表示など、業務上自然な操作を入れる。
- destructive操作は確認ダイアログを挟む。
- 更新/保存/削除は成功・失敗のフィードバックを出す。

## 完了条件

- 主要データが実APIまたは明確なmockから表示される。
- loading/error/emptyがある。
- PC/mobileで表やカードが崩れない。
- 数値、単位、日付、状態ラベルが一貫している。
- APIがある場合はcurlまたは統合テストで確認済み。
