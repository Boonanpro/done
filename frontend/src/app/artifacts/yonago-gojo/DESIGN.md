# DESIGN.md — OBANZAI bar 五条 (米子) 公式サイト【第2案・リニューアル】

> 第1案はテンプレ寄りで「普通」だった（横ナビ + 動画ヒーロー + 均等カード）。
> 第2案は **アートディレクションを根本から強化** する。技法ではなく見せ方を変える。

## ビジネスゴールからの逆算
- **① ゴール**: 集客と認知の拡大。新規来店とInstagramフォロー/DM予約増。
- **② 訪問者の行動**: 地図で場所を確認して来店 / Instagramをフォロー・DMで予約。
- **③ 確信させたいこと**: 「料理が旨そう」「夜に行きたい隠れ家」「店主の人柄」「場所がわかる」「ちゃんとした店」。
- **④ 必要コンテンツ**: 実写の板場・調理動画（カラグレ済）、おばんざい＋価格、店名の由来、アクセス、Instagram連携、常時見える予約導線。
- **⑤ デザイン方針**: 夜の隠れ家。映像が主役。たっぷりの余白と大きな縦書き明朝で「普通」を脱する。常時表示の予約タブ。

### 実装へ反映する具体デザイン判断（最低2つ→5つ採用）
1. **左固定の縦ナビ（日本語＋英語小ラベル）** をPCで採用（hōsa）。横並びテンプレナビをやめる。
2. **右端に縦書きの「ご予約 / Instagram」常時タブ** を採用（hōsa）。集客の主導線を常時露出。
3. **大きな縦書き明朝のヒーローコピー**（暗色映像の上に白＋琥珀）。テンプレ感のある中央横組みをやめる。
4. **生成り（和紙）×墨黒の明暗コントラスト**で単調な暗色一辺倒を回避（hōsa の生成り＋アワード集の暗色を両取り）。お品書きは明るい和紙セクションに置く。
5. **スクロール連動のフェード/パララックスと「scroll」誘導**（framer-motion `whileInView`）。

### 採用案: **B. 灯下の隠れ家 / Premium Night Bar**
- 理由: 五条は**カウンター6席の夜の隠れ家**。最大の資産は店主が撮った**実写カラグレ映像**と稼働中のInstagram。映像を主役に据える夜のシネマティック表現が、業態・資産・集客目的のすべてに最も合う。第1案が「普通」だったのは技法ではなく**アートディレクションが弱かった**ためなので、B案で縦書き・側面ナビ・灯り色・スクロール演出を入れて作り直す。

## 3つの作り方（技法）の比較と選定
ユーザー指定の3案を比較した。

| 技法 | 内容 | 長所 | この店での短所 | 判定 |
|---|---|---|---|---|
| ① GPT Image 2 画像コンプ / image-slice | 料理・店内をAI生成して画像スライスで貼る | 視覚再現度は最高・プロっぽい | **生成した料理/店内は“偽物”**。実在の6席の店・実際の品と食い違い、来店客の期待を裏切る＝集客に逆効果。実写映像という本物の資産を捨てることになる | ✕ 主軸にしない |
| ② DOM中心 (dom-first) | すべてHTML/CSS・実写のみ | SEO・速度・編集性・正直 | アートディレクションが弱いと第1案同様「普通」に戻る | △ 情報部分で採用 |
| **③ 動画/画像hybrid (media-rich-hybrid)（採用）** | **実写カラグレ映像を主役**＋DOMの編集的レイアウト＋GPT Image 2は**質感/雰囲気の抽象素材のみ**（和紙テクスチャ・琥珀の灯りボケ・墨の筆ストローク。料理や店内の偽造はしない）＋スクロール演出 | シネマティックで“プロっぽい”／実写で**正直**（料理・店は本物のまま）／ユーザー撮影の映像が主役／GPT Imageは非欺瞞の質感だけ | 重め（性能予算とフォールバックを用意） | ◎ 採用 |

- **レンダリング方針 = `media-rich-hybrid`**。
- GPT Image 2 の使いどころ（正直さを壊さない範囲）:
  - `texture-washi.jpg` … 和紙の質感（明るいお品書きセクション背景）
  - `night-amber.jpg` … 琥珀の灯りボケ（夜の抽象背景・CTA帯の奥行き）

## Interaction Evidence（スクロール体験の設計）

### 参考体験（hōsa）
高級和食店 hōsa（https://www.hosa.nagoya/）の上質さは、要素が**ゆっくり段階的に立ち上がる**ことと、背景メディアに**わずかな奥行き（視差）**があることから来ていた。これを「重くしすぎず・少しだけ」取り入れる。`motion_intensity = expressive`（控えめではないが過剰でもない）。

### 採用した motion primitives（`@/components/motion`）と目的
FadeIn だけに頼らず、追加 primitive を **2種（StickyStory / ParallaxMedia）** 使う。

| primitive | 使用箇所 | 目的（なぜ入れたか） | 強さ / 設定 |
|---|---|---|---|
| **StickyStory** | こだわり（craft）セクション | 調理映像を画面に固定したまま、壱・弐・参の章を横でスクロールさせる。hōsa で感じた「一つの場面に留まりながら語りが進む」上質な体験を作る。均等カードの羅列より没入感が出る | 章ごと min-h-[45vh]・lg で映像 sticky（top-24・h-70vh） |
| **ParallaxMedia** | 最終CTA帯の背景（night-amber.jpg） | 文字より背景がゆっくり動くことで奥行きを出し、CTAに余韻と高級感を足す | intensity=subtle（±28px・overscan 12%で見切れ防止） |
| FadeIn（既存） | 各見出し・本文・About写真・CTA本文・StickyStory内の章 | セクションの素直な出現。骨格は維持 | y=16〜24 |

### なぜ ImageReveal / TextReveal を採用しなかったか
- 当初 About 写真に `ImageReveal` を使ったが、この成果物プレビュー（dev の React strict mode＋HMR）と headless 検証の両方で、内部の `whileInView`（clipPath 展開）が発火せず**画像が表示されないまま固まる**事象を確認（FadeIn は同条件で発火）。表示が消えるのは集客サイトとして致命的なため**不採用**にし、About は確実に表示される FadeIn＋画像に戻した。
- `TextReveal` は内部で `useReducedMotion()` を見ておらず、reduced-motion 設定を無効化できないため**不採用**（要件「reduced-motion を壊さない」を優先）。

### motion_intensity = expressive の解釈
- スクロール連動の強い演出は「craft の StickyStory」と「CTA の ParallaxMedia」の2箇所に絞り、全要素には付けない（＝重くしない）。
- ParallaxMedia は subtle 1箇所のみ。視差を多用すると体感が重くなるため。

### reduced-motion を壊さない方針
- `ParallaxMedia` は内部で `useReducedMotion()` を見ており、ON のとき視差移動を 0 にする（静止表示）。実装確認済み。
- `StickyStory` の「固定」は CSS の position: sticky（通常スクロールの範囲で、付加的なアニメーションではない）。揺れや視差を伴わないため reduced-motion でも違和感が出にくい。
- 既存 FadeIn は透過＋小移動（〜24px）のみ。OS 設定で動きを抑えたい利用者にも過剰な揺れを与えない。

### 検証
- PC 1440px / mobile 390px、および reduced-motion=reduce で表示確認（CTA の ParallaxMedia 見切れ無し、craft の StickyStory がPCで固定スクロール／モバイルで縦積み、About 写真が確実に表示）。
